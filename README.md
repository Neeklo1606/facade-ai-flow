# neeklo FieldOps, пакет Фасады

Система подрядчика по навесным фасадам. Она ведёт одну цепочку от проектного документа до факта
на площадке и у каждого значения показывает, откуда оно взялось:

**документ → проверенные позиции → запросы поставщикам → решение с причиной → поставка и приёмка →
объём с площадки → история объекта.**

Имя продукта — **neeklo FieldOps**. «Фасады» — отраслевой пакет: справочники материалов, чек-листы
входного контроля и словарь работ. Ядро от пакета не зависит ([ADR-020](docs/adr/ADR-020-name-and-alternatives.md)).

## Два контура

| Контур             | Где данные                                   | Зачем                                                           |
| ------------------ | -------------------------------------------- | --------------------------------------------------------------- |
| **Демонстрация**   | во вкладке браузера зрителя                  | показ на вымышленных данных; письма и распознавание имитируются |
| **Рабочий контур** | PostgreSQL на сервере заказчика или в облаке | настоящая работа; права проверяются на каждом вызове порта      |

Граница между ними — [ADR-004](docs/adr/ADR-004-demo-adapter-in-browser.md) и
[ADR-016](docs/adr/ADR-016-working-contour.md). Всё, что в демонстрации подготовлено заранее,
помечено на самом экране, а не только в документации — это правило продукта, а не пожелание.

## Быстрый старт

```bash
bun install
bun run dev                     # демонстрация: http://localhost:4620
bun run dev --mode server       # рабочий контур, нужна база (см. docs/runbook/database.md)
```

Проверить всё разом — `bun run ci` (около 12 минут, нужна переменная `DATABASE_URL`).
Развернуть, откатить, восстановить — [docs/RUNBOOK.md](docs/RUNBOOK.md).
Перед показом или запуском — [docs/RELEASE.md](docs/RELEASE.md).

## Как устроен код

Слои, и импорт идёт только вниз:

```
contracts  типы и схемы данных, общие для всех
   ↓
ports      интерфейсы хранилищ: что можно спросить и что изменить
   ↓
domain     правила и расчёты, без React и без сети
   ↓
api        слой запросов TanStack Query: хуки для экранов
   ↓
components / routes   экраны
```

Правила, которые держит линтер, а не договорённость:

- компонент не импортирует `@/domain/*` — считает `domain`, показывает `api`;
- фикстуры демонстрации доступны только из `adapters/{fixtures,demo,db}`;
- цвет задаётся токеном, а не `#hex` в разметке: иначе он сломается в светлой теме.

Реализации портов — в `src/adapters`: `demo` (данные во вкладке), `db` (PostgreSQL),
`fixtures` (единственный источник демонстрационных данных для обоих).

## Как проверять

| Команда                      | Что делает                                                                 | Сколько идёт |
| ---------------------------- | -------------------------------------------------------------------------- | ------------ |
| `bun run typecheck`          | типы приложения и тестов                                                   | ~20 с        |
| `bun run lint`               | линтер и форматирование                                                    | ~20 с        |
| `bun test tests`             | домен, согласованность экранов, негативные сценарии, справка, сравнение    | ~1 с         |
| `bun run check:fixtures`     | фикстуры против схемы базы                                                 | ~1 с         |
| `bun run check:db`           | миграции, паритет с демо-адаптером, версия данных, замеры                  | ~30 с        |
| `bun run build`              | сборка                                                                     | ~10 с        |
| `bun run check:bundle`       | размер клиентского бандла против порога                                    | ~1 с         |
| `bun run test:e2e`           | сквозные: роли, честность, связи, справка, окна, EMBER, axe, консоль       | ~5 мин       |
| `bun run lighthouse`         | доступность, практики, производительность                                  | ~40 с        |
| `bun run ci`                 | всё перечисленное по порядку, с итоговой таблицей                          | ~12 мин      |
| `bun run check:links`        | ссылки внутри документов: ни одна не ведёт в никуда                        | ~1 с         |
| `bun run check:sources`      | сравнение с другими системами против их сайтов: скачивает страницы целиком | ~10 с        |
| `bun run walkthrough`        | обход: каждая кнопка каждой роли; `WALK_THEME=light` — светлая тема        | ~1 ч на тему |
| `bun run walkthrough:report` | сводка обхода в `docs/state/walkthrough.md` и контактные листы снимков     | ~10 с        |

Сверка источников и обход в конвейер не входят: первой нужна сеть и чужие сайты, второй идёт часами. Его результаты пишите вне каталога сессии:
`WALK_OUT=<папка проекта>/.verify/walk-json`.

## Правила работы в этом репозитории

1. **Решение — сначала ADR, потом код.** Файл в `docs/adr`, отдельным коммитом, до реализации.
   Задним числом ADR не пишется: в [TASKS.md](TASKS.md) записан случай, когда это нарушили.
2. **Один коммит на задачу**, сообщение объясняет причину, а не перечисляет файлы.
3. **Проверка запускается, а не предполагается.** Нельзя писать «проверено», не запустив команду;
   отчёт обхода сам отмечает коммит, на котором прогнан, — чтобы это нельзя было подделать молча.
4. **Тест проверяется от противного.** Сломайте место, которое он стережёт: не упал — он холостой.
5. **Честность интерфейса.** Всё подготовленное заранее или ещё не работающее помечено на экране.
   Сюда же — сравнение с другими системами: у каждого утверждения о чужой системе либо источник
   с датой, либо пометка «не проверено».
6. **Ключей в репозитории нет.** Только переменные окружения; порядок — в
   [docs/RUNBOOK.md](docs/RUNBOOK.md).
7. **История не переписывается.** Репозиторий связан с Lovable: без force-push, rebase и amend
   уже отправленных коммитов.

## Если что-то не работает

- Экран не загрузился или показывает старое — это почти всегда старая сборка в открытой вкладке:
  перезапустите сервер и откройте новую вкладку. Убивать сервер по порту (`lsof -ti :4620 | xargs kill`),
  а не по `pkill -f "PORT=…"`: `PORT` — переменная окружения, в командной строке её нет.
- «Рабочий режим без базы» — не задан `DATABASE_URL`; порядок в [docs/runbook/database.md](docs/runbook/database.md).
- Остальное — [docs/RUNBOOK.md, §8 «Частые проблемы»](docs/RUNBOOK.md).
