# Глоссарий предметной области

- **Задача:** P1-1 ([TASKS.md](../../TASKS.md)), решение — [ADR-001](../adr/ADR-001-data-layer.md)
- **Дата:** 2026-09-16, состояние кода после фазы 0 (`fe8bbf3`)
- **Дальше:** схемы в `src/contracts/*`, таблицы и индексы в [docs/db/schema.md](../db/schema.md)

Документ отвечает на три вопроса: какие сущности есть в продукте, что значит каждая величина на экране
и из какой таблицы или формулы она берётся. Всё, чего здесь нет, в модель продукта не входит.

## 1. Сущности

Код сущности совпадает с именем схемы в `src/contracts` и таблицы в PostgreSQL.

### Организация

| Сущность | Таблица | Что это | Ключевые поля |
|---|---|---|---|
| Сотрудник | `employees` | Пользователь системы: руководитель проекта, прораб, ПТО, снабжение, финансы, рабочий | роль, телефон, Telegram, статус |
| Участие в объекте | `project_members` | Какие сотрудники работают на объекте | объект, сотрудник |
| Контрагент | `counterparties` | Заказчик, поставщик или субподрядчик | роль, ИНН (уникален), контакт, среднее время ответа |
| Профиль поставщика | `supplier_profiles` | Для подбора в запрос: регион, разделы спецификации, свежесть контакта | поставщик, регион, разделы, дата проверки контакта |
| Бригада | `crews`, `crew_members` | Бригада на объекте и её состав | объект, прораб, численность |

|---|---|---|---|
| Объект | `projects` | Строительный объект, на котором ведётся фасад | код (уникален), заказчик, регион, стадия, статус, руководитель, сроки |
| Договор | `contracts` | Договор с заказчиком по объекту | номер (уникален), сумма и аванс в копейках, сроки, удержание |
| Контрольная точка | `milestones` | Этап договора с требованием и сроком | договор, срок, требование, статус |
| Захватка | `work_zones` | Участок фасада: оси, этажи, плановый и фактический объём | объект, родитель, план, факт |

### Документация и спецификация

| Сущность | Таблица | Что это | Ключевые поля |
|---|---|---|---|
| Документ | `documents` | Документ проекта независимо от ревизии: «Спецификация фасадных материалов» | объект, раздел (НВФ, АР, КМ), название |
| Ревизия документа | `document_revisions` | Загруженный файл конкретной ревизии и его обработка. **На экранах «документ» — это ревизия** | документ, номер ревизии (уникален в документе), файл, статус обработки |
| Лист | `document_sheets` | Лист ревизии в дереве структуры | ревизия, номер (уникален в ревизии), раздел спецификации |
| Позиция спецификации | `positions` | Строка спецификации, извлечённая из листа. **Единственная сущность «что нужно купить»** | лист, номер позиции, проектное наименование, материал, количество, уверенность, решение проверки, передача в закупку, этап закупки |
| Изменение позиции | `position_changes` | Журнал: извлечено, подтверждено, исправлено, объединено. Только добавление | позиция, кто, когда, было, стало |
| Материал | `materials` | Справочник нормализованных наименований: семейство, наименование, единица | семейство, наименование + единица (уникальны) |
| Изменение документации | `revision_changes` | Расхождение между ревизиями, которое нужно разобрать | документ, ревизии «было/стало», описание, статус |
| Предложение замены | `replacement_suggestions` | Аналог материала с причиной и разницей в цене | семейство, статус, кто решил |

## 2. Определения, на которых держатся цифры

| Термин | Определение |
|---|---|
| **Активная позиция** | `review` не `excluded`, не `merged`, не `header`. Только активные позиции считаются в любых итогах |
| **Проверенная позиция** | Активная, `review ∈ {confirmed, corrected}` — человек подтвердил или исправил |
| **Непроверенная позиция** | Активная, `review = pending` |
| **Требует нормализации** | `material_id is null`: для позиции не выбран материал справочника |
| **Уверенность** | `confidence` 0…1. ≥ 0,85 — «Проверено распознаванием», 0,70–0,85 — «Требует внимания», < 0,70 — «Не удалось определить» |
| **Передана в закупку** | `handed_over_at is not null`. Передавать можно только проверенные позиции |
| **Готова к запросу** | Проверена, передана в закупку, `purchase_status = none` |
| **Этап закупки позиции** | `purchase_status`: `none → requested → offers → supplier_selected → ordered → delivered`. Хранится в позиции, меняется событиями: позиция вошла в запрос, пришло первое предложение, зафиксировано решение, оформлен заказ, принята поставка |
| **Потребность в материале** | Сумма `qty` активных позиций объекта с этим `material_id`. Отдельно не хранится |
| **Отправленный запрос** | `sent_at is not null` |
| **Ответивший поставщик** | Есть `supplier_offers` по паре «запрос — поставщик» |
| **Просроченный запрос** | Отправлен, решения нет, ответили не все, `reply_due_at` < текущее время сервера |
| **Активный запрос** | Отправлен, статус не `decided`, не `ordered`, не `cancelled` |
| **Итог предложения** | Σ(цена × количество строки) + доставка, плюс НДС на эту сумму. Копейки, округление до копейки на строке. Хранится только в расчёте, не в таблице |
| **Лучшее предложение** | Наименьший итог среди предложений на все строки запроса; если полных нет — среди всех ответивших |
| **Принятый объём** | `accepted_qty` отчёта со статусом `accepted`. Факт захватки = сумма принятых объёмов по захватке |

## 3. Откуда берётся каждая цифра на экране

Формулы — это представление `project_overview` (view) и расчёты домена. В таблицах эти числа не хранятся.

| Экран | Величина | Формула / источник |
|---|---|---|
| Реестр, карточка | Позиций | Число активных позиций текущих ревизий объекта. Для ревизии, позиции которой ещё не загружены в систему, — `document_revisions.positions_total` |
| Реестр, карточка | Непроверено | Активные позиции с `review = pending`; для ревизии без загруженных позиций — `positions_total − positions_verified` |
| Реестр | Ревизия документации | Номер последней загруженной ревизии документов объекта |
| Реестр | Запросов | Число активных запросов объекта |
| Реестр, карточка | Просрочено | Число просроченных запросов объекта |
| Реестр, карточка | Изменений | `revision_changes` объекта со статусом `open` |
| Карточка | Закуплено | Проверенные позиции с `purchase_status ∈ {ordered, delivered}` |
| Карточка | В пути | Проверенные позиции с `purchase_status = ordered` |
| Карточка, сводка | В запросе / получены предложения / поставлено | Проверенные позиции с `purchase_status` от `requested`, от `offers`, `= delivered` соответственно |
| Карточка, сводка | Отсутствующие отчёты | Бригады объекта, от которых нет отчёта за последние 7 дней от текущего времени |
| Документация | Извлечено / проверено у документа | Активные / проверенные позиции ревизии |
| Проверка позиций | «Проверено N из M» | Проверенные / активные позиции ревизии |
| Материалы | Готовы к запросу | Позиции объекта, готовые к запросу |
| Материалы | Плитки этапов закупки | Проверенные и переданные позиции по `purchase_status` |
| Закупки | Ответили N из M | Ответившие поставщики / получатели запроса |
| Закупки, сравнение | Лучшая цена, итог колонки, НДС, доставка | Расчёт домена `procurement` по строкам предложения и условиям (P3-1) |
| Отчёты с площадки | На проверке / всего | Отчёты объекта со статусом `review` / все |
| История и решения | Лента | `project_events` и `project_decisions` объекта по убыванию времени |
| Ход работ | Объёмы по захваткам | `work_zones.plan_qty`; факт — сумма принятых объёмов отчётов по захватке |

## 4. Статусы

| Сущность | Статусы | Кто меняет |
|---|---|---|
| Объект | `active`, `at_risk`, `paused`, `done` | Руководитель проекта |
| Ревизия документа | `uploaded → recognizing → extracted → review → verified` | Обработка до `review`, человек — `verified`, когда проверены все активные позиции |
| Позиция, проверка | `pending`, `confirmed`, `corrected`, `excluded`, `merged`, `header` | Человек на экране проверки |
| Позиция, закупка | см. «Этап закупки позиции» | События закупки |
| Запрос, хранимый | `draft → sent → decided → ordered`, из любого — `cancelled` | Отправка, решение, заказ |
| Запрос, на экране | `sent`, `collecting`, `ready`, `overdue`, `decided`, `ordered` | Вычисляется из хранимого статуса, ответов и срока |
| Контакт поставщика | `verified`, `needs_check`, `stale` | Снабжение при проверке контакта |
| Отчёт с площадки | `review`, `accepted`, `returned` | Руководитель проекта или ПТО |
| Поставка | `expected`, `in_transit`, `received`, `rejected` | Снабжение, приёмка на площадке |
| Предложение замены | `proposed`, `agreed`, `rejected` | Руководитель проекта |
| Контрольная точка | `planned`, `at_risk`, `done`, `overdue` | Руководитель проекта |
| Изменение документации | `open`, `resolved` | ПТО |

## 5. Расхождения старой и новой модели

Найдены при составлении глоссария на коде после фазы 0. Колонка «Решение» — что меняется в модели.

| № | Расхождение | Решение | Задача |
|---|---|---|---|
| R1 | «Запросов 6» и «Просрочено 2» у «Северной Короны» в реестре — числа в `projectOverviews`, заданные руками. В разделе закупок того же объекта просрочен 1 запрос, а созданный в демо запрос реестр не видит | Счётчики запросов считаются из запросов (§3) | P1-5 |
| R2 | Хранимый `SupplyRequest.status` (`compared`, `collecting`) и вычисляемый на экране `rfqStatus` — два разных статуса одного запроса | Хранимый статус — только жизненный цикл, экранный — вычисляемый (§4) | P1-2, P3-2 |
| R3 | `SupplierOffer.total` хранит сумму без доставки и НДС, а сравнение считает с ними. Карточка материала и превью закупок показывают первое, экран сравнения — второе | Итог не хранится, считается одной функцией | P1-2, P3-1 |
| R4 | `SupplierOffer.prices` дублирует `OfferLine.price`; `OfferTerms` — отдельная таблица 1:1 к предложению | Условия — поля предложения, цены — только строки предложения | P1-2 |
| R5 | Строка запроса ссылается на `materialId` вида `mt-bracket` (старый справочник `materials` с потребностью 12 400 шт), а созданные в демо — на ключ `семейство:наименование:единица` | Справочник `materials` без потребности; строка запроса ссылается на `material_id`, позиции — через `supply_request_positions` | P1-2, P1-5 |
| R6 | Потребность `mt-bracket` 12 400 шт задана руками, сумма позиций спецификации — 13 930 шт | Потребность = сумма позиций (§2) | P1-5 |
| R7 | Нормализованное наименование хранится строкой в позиции (`normalizedName`) | Ссылка на `materials`; «требует нормализации» = нет ссылки | P1-2 |
| R8 | Превью «Материалы» в карточке берёт `specItems` — 9 строк старого набора — для объектов без позиций | Превью читает только позиции | P1-8 |
| R9 | Превью «Документация» в карточке берёт `DocumentRecord` (`doc-10`…), раздел «Документация» — `projectDocuments`. Версии в сводке — третий набор `docVersions` со ссылкой на `doc-10` | Документ + ревизии; версии в сводке — ревизии документа | P1-2, P1-8 |
| R10 | Три журнала одного объекта: лента сводки (`activityItems`), «История» в карточке (`auditLog`), раздел «История и решения» (`timelineSeed`) | Один журнал `project_events` + решения | P1-8 |
| R11 | «Ждут решения» в карточке — это `risks`, которых нет в разделе «История и решения» | Вычисляемый список: запросы, готовые к решению, и предложенные замены | P1-8 |
| R12 | Подтверждения `approvals`, журнал `auditLog`, входящие `incomingEvents` — остатки старой модели «агента»; в продукте их заменили изменения позиций, решения и события | Удаляются; аудит действий пишется в серверных функциях | P1-8, P2-1 |
| R13 | `Project` хранит договор строкой, суммы договора и финансы (`performedAmount`, `closedAmount`, прогресс) из `volumeEntries`; ни один экран их не показывает | Объект — только свои атрибуты; договор — `contracts`; финансы и записи объёмов вне модели до раздела «Ход работ» | P1-2 |
| R14 | Регион и стадия объекта лежат в сводке, а не в объекте | Поля `projects.region`, `projects.stage` | P1-2 |
| R15 | Факт захватки `WorkZone.factQty` задан руками и не связан с принятыми отчётами | Факт = сумма принятых объёмов; до P3 хранится в фикстурах как базовый факт до начала учёта отчётами | P1-2, P3 |
| R16 | Выбор объекта в шапке хранит `s-korona`, репозиторий — `p-korona`; текущий пользователь `u-sokolov` из `mock/users`, сотрудник — `e-sokolov` | Выбор объекта хранит id объекта, пользователь — сотрудник | P1-6 |
| R17 | Деньги в рублях с дробной частью (итог «38 569 381,5 ₽»), НДС — число процентов | Деньги — целые копейки (`bigint`), ставка НДС — целые проценты | P1-2, P1-5 |
| R18 | Даты — строки без часового пояса, «просрочено» считается от зашитого `MOCK_NOW` | В БД `timestamptz`; время — серверное; в демо — часы демо-адаптера | P1-2, P3-2 |
| R19 | Открытые изменения документации и отсутствующие отчёты — числа в сводке без сущности за ними | `revision_changes`; отсутствующие отчёты — формула по бригадам и отчётам | P1-2, P1-5 |
| R20 | Позиции загружены только для спецификации «Северной Короны»; у остальных объектов число позиций есть, самих позиций нет | Счётчики ревизии `positions_total` / `positions_verified` как явный источник до загрузки позиций; разделы материалов этих объектов пусты | P1-5, P2-6 |

## 6. Вне модели продукта

Удаляются вместе со старыми моками (P1-8). Если функциональность понадобится, она возвращается новой
сущностью через этот глоссарий, а не восстановлением старого кода.

- `SpecItem`, старый `Material` с потребностью, заказом и остатком — заменены позициями и справочником материалов.
- `DocumentRecord`, `DocVersionRecord` — заменены документами и ревизиями.
- `ActivityItem`, `AuditLog`, `Approval`, `IncomingEvent` — заменены событиями объекта, изменениями позиций и решениями.
- `Task`, `Risk` — задачи и риски в продукте после ADR-003 не ведутся.
- `WorkType`, `WorkItem`, `VolumeEntry`, `ScheduleItem`, финансовые поля объекта — учёт выполнения и денег по актам не входит в текущий продукт.
- `src/types/index.ts`, `src/mock/sites.ts`, `src/mock/users.ts` — старая модель целиком.
