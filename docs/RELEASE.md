# Перед запуском: финальные проверки

Документ для того, кто выпускает. Здесь только то, что проверяется командой или глазами за один
проход, и то, что уже однажды ломалось. Развёртывание и откат — [RUNBOOK.md](RUNBOOK.md), состояние
продукта — [STATE.md](STATE.md).

Порядок один и тот же для показа покупателю и для запуска у заказчика: разница в том, сколько
пунктов обязательны. Пункты с пометкой **(запуск)** к показу не относятся.

## 1. Код и проверки

- [ ] `bun run ci` пройден целиком на той ветке, которую выпускаете. Не «проходил вчера» — сейчас.
      Вывод сохранён: он понадобится, если после выпуска что-то пойдёт не так.
- [ ] Обход прогнан на **текущем** коммите: `bun run walkthrough` и `WALK_THEME=light bun run walkthrough`,
      затем `bun run walkthrough:report`. Отчёт сам называет коммит прогона — сверьте с `git log -1`.
      Если код менялся после обхода, отчёт скажет об этом прямо.
- [ ] В отчёте обхода: **тупиков нет** и **ошибок в консоли нет**. Тупиком считается и переход
      на «Нет доступа» — ссылка, которая приводит роль в отказ, для человека такой же тупик.
- [ ] Размер бандла в пороге. Порог не поднимается ради выпуска — разбор в
      [state/bundle.md](state/bundle.md).
- [ ] Рабочее дерево чистое, ветка влита через проверку, а не мимо неё.

## 2. Честность экранов

Покупатель прощает «этого пока нет» и не прощает обнаруженного обмана. Проверяется глазами
за пять минут:

- [ ] Метка «Демо» видна в первом экране на любой ширине.
- [ ] Под результатом разбора документа стоит пометка, что содержимое файла не распознаётся.
- [ ] Запрос, ждущий ответов, говорит, что письма не отправляются.
- [ ] Отчёт с площадки говорит, что приём из Telegram — заготовка.
- [ ] Статья справки «Частые вопросы» перечисляет то же самое, что и экраны: расхождение между
      ними хуже, чем отсутствие обоих.
- [ ] `bun run check:sources` — сравнение с другими системами сверено с их сайтами: команда
      скачивает каждую страницу целиком и ищет слова, на которых держится утверждение.
      Она же падает, если сверке больше 90 дней: сайты меняются, и таблицу пора пересмотреть.

## 3. Доступ и данные

- [ ] Ключ демонстрации задан переменной `DEMO_ACCESS_KEY` на хостинге, а не в репозитории.
      Без него шлюз выключен, и адрес открывается всем.
- [ ] Ссылка с ключом проверена в новом окне браузера, где её ещё не открывали.
- [ ] Превью ссылки в мессенджере показывает имя продукта и картинку, а не пустой прямоугольник.
- [ ] `robots` закрывает индексацию: демонстрация не должна находиться поиском.
- [ ] **(запуск)** `DATABASE_URL` и `DATABASE_DRIVER` заданы; миграции применены; начальные
      справочники загружены — [runbook/database.md](runbook/database.md).
- [ ] **(запуск)** `SESSION_SECRET` задан: иначе сессии сотрудников не переживут перезапуск.
- [ ] **(запуск)** Резервная копия базы снята **до** выпуска и проверена восстановлением
      в отдельную базу. Копия, которую не разворачивали, — это не копия.

## 4. Роли

- [ ] Вход за каждую из пяти персон: руководитель проекта, снабжение, ПТО, прораб, директор.
      У каждой открывается её рабочее место, а закрытые разделы не показываются в меню.
- [ ] Прямой переход в закрытый раздел даёт экран «Нет доступа» с объяснением, а не пустоту
      и не чужие данные.
- [ ] **(запуск)** У директора нет кнопок записи: он смотрит, но не правит.

## 5. Обе темы и телефон

- [ ] Переключатель темы работает, выбор переживает перезагрузку, «как в системе» слушает
      настройку системы.
- [ ] Печать реестра идёт светлой из любой темы.
- [ ] На 375 px первый экран без горизонтальной прокрутки, области нажатия не меньше 44 px,
      ничего не появляется только по наведению.

## 6. После выпуска

- [ ] Открыть продукт по публичному адресу в новой вкладке и пройти сценарий показа целиком
      ([SALES_DEMO.md](SALES_DEMO.md)): один раз, полностью, не пропуская шагов.
- [ ] Проверить, что «Сбросить демо-данные» возвращает исходное состояние.
- [ ] Записать в [STATE.md](STATE.md) дату выпуска и то, чем он проверен.
- [ ] Через сутки — посмотреть журнал сервера: отказы прав и ошибки отрисовки
      ([RUNBOOK.md, §7](RUNBOOK.md)).

## Что останавливает выпуск

Три вещи, при которых выпуск переносится, а не «выпустим и починим»:

1. **Тупик или ошибка в консоли в отчёте обхода.** Покупатель находит их быстрее, чем продавец
   успевает объяснить.
2. **Обещание без пометки.** Экран, который выглядит работающим, а на деле подготовлен заранее.
3. **Утверждение о чужой системе без источника.** Одно опровергнутое на встрече утверждение
   стоит дороже всей презентации.
