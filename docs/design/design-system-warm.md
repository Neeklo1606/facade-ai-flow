# Дизайн-система «Тепло»: основа — референс 20.11.2026

Решение владельца: визуальный язык со скриншотов (мобильное приложение финансового агента в тёплой
гамме) берётся за основу всего сервиса ГАЙКА и лендинга. Синяя палитра pto-app.ru из
`2026-11-20-design-changes.md` отменяется. Берём язык, а не бренд: чужие логотип, название и тексты
не копируем.

Совпадает с правилами проекта: один оранжевый акцент, Inter, вес до 600, без капса (EMBER).

## 1. Что видно на референсе

1. **Тёплый фон страницы,** почти белый с серо-бежевым оттенком. Карточки чисто белые, без
   теней или с очень мягкой тенью, радиус 28–32 px.
2. **Крупный заголовок-итог** на две строки: «Ваш агент собрал $12 840 за ночь». Над ним
   приветствие мелким серым.
3. **Главная цифра точечным шрифтом** (как табло из светодиодов) на карточке-фото: размытое
   небо или закат, сверху подпись и период, снизу тонкий прогресс из двух цветов (белый и
   оранжевый) и легенда точками: «23 закрыто · 14 обещано».
4. **Плитки быстрых действий** в ряд: белая карточка, круглая серая кнопка с иконкой, подпись
   снизу. Одна плитка чёрная — главный вход («Агент»).
5. **Список событий в белой карточке:** круглый аватар с инициалами пастельного цвета (персик,
   камень, сирень), название, серая подпись, сумма справа. Положительная сумма — оранжевым.
6. **Шапка:** колокольчик в белом круге с оранжевой точкой, аватар сиреневым кругом.
7. **Нижняя панель:** иконка и подпись; активная чёрная, неактивные серые.
8. **Маркетинг:** градиент персик → оранжевый → ржавый → почти чёрный, поверх сетка из символов
   (цифры, знаки, буквы), которая проявляется к краю. Стеклянная плашка-уведомление с размытием.
   Тёмная стеклянная панель с тонкой рамкой и точечной цифрой.

| Стиль | Размер / межстрочный | Вес | Где |
| --- | --- | --- | --- |

| `title` | 28 / 32, −1 % | 600 | заголовок экрана |

| `body` | 17 / 24 | 400 | строки списка (телефон) |
| `body-strong` | 17 / 24 | 500 | название в строке, сумма |

Шрифт Inter с цифрами одинаковой ширины (`tnum`). Компьютер: шкала та же, `body` 15.

### Форма и отступы

- Радиусы: карточка 28, плитка 24, поле 16, кнопка 999 (капсула), аватар и иконка-кнопка — круг.
- Отступы: 4, 8, 12, 16, 20, 24, 32. Поле экрана 16 на телефоне, 32 на компьютере.
- Размеры нажатия: 44 минимум, 48 для полевых действий бригадира, 56 круглая кнопка голоса.
- Тени: нет. Карточки отделяются от фона цветом, не тенью. Исключение — стекло.

### Движение

- 160 мс на нажатие, 240 мс на появление шторки, кривая `cubic-bezier(.2,.8,.2,1)`.
- Точечная цифра при смене значения «перекатывает» точки за 400 мс; при «уменьшить движение» —
  сразу.

## 4. Как это ложится на экраны

| Экран | Было | Станет |
| --- | --- | --- |
| «Сегодня» бригадира | список и большая кнопка | `ScreenHello` «Сегодня сдано 2 записи», плитки «Добавить время» (чёрная) и «Как вчера», `ListCard` записей с аватаром объекта, вопрос «закончены?» плиткой |
| «Проверка» | карточки с серыми полями | `Segmented` вкладок, `ListCard` очереди, строки с аватаром бригады, сумма справа, `Chip` замечаний; на компьютере `DataTable`; деталь — `SidePanel` |
| «Неделя» | метрики и шкала | `KpiCard` «Начислено» точечной цифрой с `SplitProgress` принято/ждёт, плитки «Закрыть неделю», «Выгрузить» |
| «Сметы» | блок папки и список | `ActionTile` «Загрузить сметы» (чёрная), `ListCard` файлов со статусом, карточка сметы — `Sheet` / `SidePanel` |
| Страница объекта | шторка справочника | `ScreenHello` адресом, `KpiCard` «Остаток по разделам», `ListCard` разделов с бригадами |
| Табель | сетка | `DataTable` в белой карточке, без подсветки столбцов |
| Лендинг | розово-оранжевый градиент | `grad-hero` с `CharField`, телефон с экраном «Неделя», `GlassToast` «Бригада 2 · +19 950 ₽ принято», тёмная панель с точечной цифрой |

## 5. План перехода

**Шаг 0. Макеты на согласование (1 день).** Четыре экрана на 390 и 1440: «Сегодня» бригадира,
«Проверка», «Неделя», первый экран лендинга. HTML-макет на тех же токенах, чтобы потом не
перерисовывать. Остановка: согласование владельцем.

**Шаг 1. Токены (0,5 дня).** Новые значения в `src/styles.css` под теми же именами, что уже
используют экраны. Большая часть сервиса перекрашивается сразу без правки компонентов.
Проверка контраста скриптом `check:contrast`, светлая и тёмная темы.

**Шаг 2. Базовые компоненты (2 дня).** `DotNumber`, `KpiCard`, `SplitProgress`, `ActionTile`,
`ListCard`, `ListRow`, `Avatar`, `IconButton`, `GlassToast` в `src/components/ui/kit`. Страница
`/design-system` с примерами. Тесты: `DotNumber` озвучивает настоящее число; плитки от 44 px.

**Шаг 3. Экраны по одному (4–5 дней).** «Сегодня» бригадира → «Проверка» → «Неделя» → «Сметы» →
страница объекта (этап 1 плана) → табель. Каждый экран: снимки 390 и 1440, axe, консоль чистая,
e2e зелёные.

**Шаг 4. Лендинг (2 дня).** `grad-hero`, `CharField`, телефон с экраном «Неделя», стекло, форма в
первом экране. Lighthouse не ниже порогов: сетка символов — CSS или одна картинка, не JS.

**Шаг 5. Тёмная тема (1 день).** Те же компоненты на тёмных токенах; снимки.

Итого 10–11 рабочих дней. Порядок «токены → компоненты → экраны» даёт видимый результат с
первого дня и не ломает работающее.

## 6. Ограничения

- Точечные цифры только для одной главной цифры экрана. В таблицах и суммах строк — обычные
  цифры `tnum`: их нужно читать, а не любоваться.
- Оранжевый — одна точка внимания на экране. Статусы «ок / ждёт / ошибка» своими цветами.
- Градиент и стекло — только лендинг, вход и карточка главной цифры. Рабочие экраны — плоские
  белые карточки на тёплом фоне.
- Фото на `KpiCard` — размытый градиент, а не настоящее фото: вес страницы и первый экран
  бригадира на 4G (порог 2,5 с).
