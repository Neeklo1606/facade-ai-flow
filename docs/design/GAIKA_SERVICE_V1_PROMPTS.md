## 1. Продуктовые решения (основа для всех промптов)

### 1.1. Что продаём и как называем

ГАЙКА: помощник подрядчика. Данные с объекта превращаются в проверенные записи, отчёты и документы.

Три модуля одной системы:

| Модуль | Пользователи | Результат |
|---|---|---|
| 1. Учёт времени и выработки бригад (главный, газовый заказчик) | бригадир, менеджер, руководитель, администратор | закрытая неделя и Excel в формате заказчика |
| 2. Снабжение | прораб, снабженец, руководитель | заявка → предложения поставщиков → заказ → приёмка на объекте |
| 3. Исполнительная документация (ПТО) | ПТО, прораб, руководитель | комплект черновиков АОСР, реестр ИД и записи журнала из подтверждённых данных объекта |

Связи модулей:
- принятая приёмка материала (модуль 2) с сертификатом попадает в материалы для актов (модуль 3);
- подтверждённые объёмы работ дают основание актов;
- материалы сметы (модуль 1, разбор смет) дают лимит заявок.

### 1.2. Показатели модуля 1: честные определения

Внешний разбор прав: время не равно выработке. Разделяем величины.

| Показатель | Как считается | Где виден |
|---|---|---|
| Часы записи | окончание минус начало минус перерыв, от минут | всем, кроме бригадира в чужих записях |
| Состав | число людей в записи (по умолчанию из состава бригады на дату, можно изменить) | бригадир вводит, менеджер проверяет |
| Человеко-часы | часы каждого человека суммой; при «у сотрудников разное время» по строкам людей | всем ролям |
| Стоимость работ по смете (начислено) | по ADR-053: подтверждённая стоимость объекта, распределение по минутам | менеджер, руководитель, администратор |
| Выработка на час бригады | начислено / часы записи, формула заказчика из его Excel; подсказка с формулой словами | менеджер, руководитель |
| Выработка на человеко-час | начислено / человеко-часы | менеджер, руководитель |
| Стоимость труда | человеко-часы × ставка (ставка с периодом действия); без ставок скрыто | руководитель, администратор |

Правила:
- Слова «маржа», «прибыль», «доходность объекта» не использовать.
- Финансы бригадиру не отдаются ни в интерфейсе, ни из серверной функции (проверка тестом).
- Название модуля в интерфейсе: «Учёт времени бригад». Отчёт заказчика оставляет его название «Выработка».

### 1.3. Роли и стартовые экраны

| Роль | Стартовый экран | Поверхность |
|---|---|---|
| Бригадир | «Сегодня» бригадира (мобильный) | телефон, отдельный интерфейс; бот MAX показан только в деморежиме |
| Менеджер проверки | «Проверка» | компьютер и телефон |
| Руководитель | «Неделя» (закрытие недели) | компьютер и телефон |
| Администратор / сметчик | «Справочники» | компьютер |
| Прораб | «Сегодня» прораба (ввод голосом и текстом, заявки) | телефон |
| Снабженец | «Заявки» | компьютер и телефон |
| ПТО | «Документы» | компьютер |

### 1.4. Инварианты для всех модулей (проверяются тестами)

1. Неподтверждённое не попадает в итог и финальную выгрузку. Черновая выгрузка помечена «Черновик», непроверенные строки выделены.
2. Исправление подтверждённого требует причины и создаёт новую версию. История видна и не редактируется.
3. Закрытый период (неделя, реестр ИД) не меняется: переоткрытие с причиной создаёт версию v2.
4. Повтор отправки с тем же ключом не создаёт дубль (ключ клиента, внешний ID сообщения).
5. Права проверяются в серверных функциях. Финансы и чужие объекты роль не получает из API.
6. AI только предлагает поля черновика. Подтверждает человек, расчёт выполняет код.
7. Офлайн: пользователь видит «Сохранено на телефоне» или «Принято сервером», никогда не путает их.
8. Никаких чисел вне данных. Нет данных: честная метка («План не задан», «Ставки не заданы»).
9. Документы ИД, заказ поставщику и любые подписи не выполняются системой. Только черновики и статусы, которые ставит человек.

## 3. Серия промптов S0-S8

Каждый промпт самодостаточен. Общие правила для всех: CLAUDE.md и MASTER-AGENT-SKILL,
Task Brief, ADR до реализации, проверка запуском команды, отчёт после этапа, простой русский
без эмодзи и длинных тире, «проверено» только после запуска.
