# Аудит перед «Сервисом v1» (S0, п. 3)

Дата: 29.10.2026. Ветка `feature/service-v1` от `origin/feature/graphite` (9fe4a77) с влитым
`origin/main` (1dcd55c). Основание: docs/design/GAIKA_SERVICE_V1_PROMPTS.md, разделы 1, 2, S4-S6.

Метки:
- **есть**: работает на демо-данных, есть домен и экран;
- **частично**: часть есть, чего-то не хватает (написано, чего);
- **заглушка**: экран или текст есть, логики нет, или код лежит за флагом;
- **нет**: ни домена, ни экрана.

## 0. Что уже лежит в коде

| Слой | Модуль 1 (газ) | Модуль 2 (снабжение) | Модуль 3 (документы) |
|---|---|---|---|
| Контракты | `domain/gas-ops/model.ts` (типы без zod) | `contracts/procurement.ts`, `contracts/field.ts` (`material_requests`) | `contracts/documents.ts`: проектная документация и спецификации |
| Домен | `domain/gas-ops/*` (12 файлов: время, флаги, отчёт, сметы, режимы проверки, график) | `domain/procurement.ts`, `deliveries.ts`, `rfq-template.ts` | `domain/extraction.ts`, `positions.ts`; `registry.ts` это реестр объектов, не реестр ИД |
| Порт | `ports/gas-ops.ts` (`GasOpsPort`) | `ports/procurement.ts`, `ports/supply.ts` | `ports/documents.ts` |
| Адаптер | `adapters/gas-ops/demo.ts`: состояние в браузере | fixtures, demo, db (PostgreSQL) | fixtures, demo, db |
| Экраны | `/gas/*` (15 маршрутов), своя оболочка `GasShell` | `/projects/$id/procurement`, `/$rfqId`, `/deliveries`, `/materials`, `/inbox` (заявки) | `/projects/$id/documents`, `/$docId` |
| Флаг | не под флагом | `procurement`, `suppliers`, `deliveries`, `materials` под `VITE_LEGACY_MODULES` | `documents` под `VITE_LEGACY_MODULES` |

Флаг: `src/lib/legacy-modules.ts`. `VITE_LEGACY_MODULES=1` или ключ `neeklo-fieldops-legacy`
в sessionStorage возвращает разделы целиком. Без флага пункты уходят из меню, адреса ведут на
рабочий экран роли (ADR-034, ADR-038).

Важная находка по модулю 3: «Документы» в коде это **проектная** документация (загрузка ревизии,
распознавание, извлечение спецификации, изменения между ревизиями). Исполнительной документации
(АОСР, реестр ИД, журнал работ, участники) в коде нет совсем: поиск по «АОСР», «освидетельств»,
«журнал работ», «НРС», «скрытых работ» даёт ноль файлов.

Роли: в газовом контуре 4 роли (`admin`, `manager`, `foreman`, `director`), в FieldOps
`employeeRole` 7 ролей (`manager`, `foreman`, `pto`, `supply`, `finance`, `worker`, `director`).
Прораб, снабженец и ПТО есть только в FieldOps, бригадир только в газе. Общей модели ролей нет.

## 2. Модуль 2: снабжение (S5)

Есть две разные сущности: **заявка с площадки** (`material_requests`, ADR-037) и **запрос цены
поставщикам** (`supply_requests`, RFQ, ADR-011/014/025). Сценарий S5 связывает их в одну цепочку.

### Данные

|---|---|---|

| Заявка: материал из номенклатуры | нет | наименование словами площадки; номенклатура есть в `ports/catalog.ts` |
| Заявка: приоритет, фото, ключ отправки | нет | |

| Приёмка: факт по строкам, расхождение | есть | `lineDiscrepancies`, замечания снабжению |
