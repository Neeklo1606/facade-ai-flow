## 1. Что работает

### Настоящее

- **Разбор смет в браузере** (`/gas/estimates`): файл не уходит на сервер. Формат определяется
  по содержимому (ГРАНД-Смета 421/пр или ресурсная 14 граф), достаются прямые затраты,
  материалы, ФОТ, накладные, сметная прибыль, без НДС, ставка и сумма НДС, ВСЕГО, разделы
  с суммами и трудозатраты; у каждого числа номер строки файла.
- **Молчаливого числа нет**: нет итога, разделы не сходятся с итогом больше чем на 1 ₽,
  без НДС + НДС ≠ ВСЕГО, строки с суммами ниже «ВСЕГО по смете» — статус «Требует проверки
  сметчиком», замечание с номером строки, подтвердить нельзя, пока сметчик не отметит.
- **Стоимость работ объекта**: правило состава словами («Всего без НДС минус материалы»,
  «Требует согласования»), подтверждение правила на компанию с записью в журнал, переопределение
  для объекта в домене и порте. Версии сметы: файл, дата, кто подтвердил; стоимость из последней
  подтверждённой версии целыми рублями. Подсказка объекта по имени файла, подтверждает человек.
- **Пересчёт**: новая стоимость распределяется по минутам записей объекта (наибольший остаток,
  сумма частей равна стоимости ровно), меняются только неподтверждённые записи с суммой.
  Подтверждённые записи и сданные отчёты не меняются: отчёт помечается «Требует обновления».
- **Норма против факта**: «норма 57,6 чел.-ч, факт 41,5 ч» на карточке объекта и в отчёте.
- **Ручной ввод** для объектов без сметы (котлы): сумма и обязательный комментарий, источник
  «вручную», пересчёт тем же правилом.
- **Режимы проверки** (`/gas/admin`): «Проверять все», «Только с замечаниями», «Без проверки,
  итоговая проверка перед отчётом». Режим меняет маршрут отправленной записи. Режим 3 закрыт,
  пока точность (доля последних решений менеджера без правки, не меньше 20 решений) ниже
  порога 90 / 95 / 98 %; причина и числа видны рядом.
- **Итоговая проверка и сдача отчёта** (`/gas/reports`): список записей без ручного
  подтверждения, подтверждение одним действием с журналом; выгрузка утверждённого отчёта
  и сдача закрыты, пока список не пуст.
- **Недельный график** (`/gas/objects`): импорт Excel, сопоставление колонок с запоминанием
  по подписям колонок, предпросмотр «добавится / изменится / уйдёт», строки с ошибкой
  с номером, применение одной кнопкой с отменой 6 секунд. Бот бригадира берёт объекты
  дня из графика, если он загружен.
- **Бригады на неделю** (`/gas/brigades`, «Состав на неделю»): «работает / в отпуске»
  через порт с журналом; бригада в отпуске не получает объектов в боте.
- **«Графит»**: токены обеих тем, прежние имена псевдонимами, контраст каждой пары проверяется
  скриптом в конвейере; шрифт Golos Text своей копией без Google Fonts; кнопки-таблетки
  одним компонентом; левая панель 240 / 64 с поиском ⌘K, счётчиками разделов; «Обзор»
  `/gas/overview` с полосой показателей, спарклайнами, ColumnChart, ProgressStack, BarList;
  `/gas/summary` перенаправляет на «Обзор»; витрина `/design-system`, раздел «Графит».

### Демо

- Всё состояние `/gas` по-прежнему в `localStorage` вкладки: рабочей базы нет (как и до задачи).
- Пользователи и роли — мок-вход без пароля; «сметчик» как отдельная роль не заведён:
  правило и сметы подтверждают менеджер и администратор.
- Числа в «Обзоре» — из демо-записей; плана недели в данных нет, рядом с суммой «План не задан».

### Чего нет

- Формат недельного графика заказчика не известен (файла нет): сопоставление колонок обобщённое.
- Переопределение правила для отдельного объекта есть в домене и порте, на экране только
  правило компании.
- Глубокая перекраска экранов ГАЙКИ и `/office` по макетам V4 не делалась (макетов нет): они
  получили «Графит» через токены, шрифт и кнопки, без перевёрстки.
- Скорость 2,5 с на 4G не подтверждена (см. раздел 2).

## 6. Решения без владельца и вопросы к заказчику

Решения (откатываемые, записаны в ADR):

1. Golos Text вместо Onest: у строчной l есть хвост, I и l различимы (ADR-052).
2. В браузере SheetJS для обоих форматов вместо exceljs для xlsx: exceljs весит 250 КБ gzip
   и один превысил бы порог самого большого куска; SheetJS всё равно нужна для xls (ADR-053).
3. Куски «по требованию» (SheetJS, разбор сметы, чтение файла, разбор графика) меряются своим
   порогом `onDemand`; общий порог и порог самого большого куска не поднимались.
4. Стоимость объекта делится между записями по минутам; запись без суммы получает долю при
   подтверждении, а не при смене версии.
5. Менеджер остаётся на очереди проверки как на стартовом экране (с неё начинается показ),
   «Обзор» стартовый у руководителя, у менеджера он пункт меню «Работа».
6. Вариант кнопки `accent` остался капсулой цвета текста: иначе на экранах ГАЙКИ два
   оранжевых пятна.

Открытые вопросы к заказчику:

1. **Правило состава стоимости работ**: какие строки итогов входят (сейчас кандидат «без НДС
   минус материалы» с меткой «Требует согласования»).
2. **Формат смет**: какой формат станет единым; что делать со строками ниже «ВСЕГО по смете»
   (технадзор, врезка) — входят ли они в стоимость.
3. **Порог автоподтверждения**: 90, 95 или 98 %, и по скольким последним решениям считать.
4. Пример недельного графика: какие колонки и как пишется бригада.
5. Распределение стоимости объекта, по которому работали несколько дней: сейчас по минутам
   записей (ADR-053), признак «объект на несколько дней» остаётся поводом посмотреть.
