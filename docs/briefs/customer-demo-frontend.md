# ГАЙКА: поэтапная сборка демонстрационного фронтенда

Дата: 17.11.2026. Работа в отдельной ветке, без merge main и production.

## Объём и порядок

1. Аудит существующих экранов и цепочки из пользовательского Excel. Сохранить дизайн,
   маршруты, импорт, проверку, табель, выгрузку и раздельные demo/server контуры.
2. Собрать старт «Сценарий на ваших данных» без сброса. Объект → смета → бригада/график →
   форма времени → проверка → табель. Показать фактическую готовность каждого шага.
3. Устранить разрывы: ручное назначение бригады без обязательного Excel; назначенные объекты
   видны в карточках до первой записи; сметы и разделы доступны из объекта. Редактирование
   объекта и его статуса в demo, с сохранением и журналом, без притворного серверного API.
4. Представить будущие начисления отдельным подписанным проектом на реальных разделах
   загруженной сметы. Сотрудник указывает материалы раздела, бригаду, день и долю выполнения.
   Хранить проект в браузере; показать стоимость, распределение и остаток; экспортировать
   отдельный проект XLSX. Не подмешивать его в утверждённый отчёт и старый расчёт по минутам.
5. Пройти основные экраны и сценарии на 1440/375: импорт, формы, назначение, мобильное время,
   правка/принятие/отмена, табель и скачивание Excel. Проверить ошибки, пустые состояния,
   роли, сохранение и отсутствие горизонтального переполнения.
6. Подготовить инструкцию показа, честную матрицу возможностей и handoff Сергею.

## Механизм дизайна

Для каждого шага: задача роли → реальные входные данные → состояния загрузка/пусто/ошибка/
нет прав → существующие токены и компоненты → один главный переход → телефон → проверка.
У исходных значений сохранять ссылку на смету/версию/строку; неизвестные материалы и объёмы
не угадывать. Не выдавать макет финансового правила за согласованное начисление.

## Граница backend

Не добавлять VPS, внешних ботов, токены, транскрипцию и новую финансовую модель сервера.
Существующие порты продолжат вести время/проверку/отчёт. Проект частичных начислений
отдельный, пока заказчик не утвердит эталон. Источник пользовательских данных — загруженные
через интерфейс файлы; не коммитить сами файлы, адреса и персональные данные клиента.
