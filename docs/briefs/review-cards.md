# Экран проверки карточками · 17.11.2026

## Первый этап: экран

- Один центральный блок карточек. Закрытые карточки одинаковой высоты, выше компактной строки.
- Нажатие раскрывает запись на месте; повторное нажатие закрывает. Справа отдельной панели нет.
- В детали: объект, дата работы, автор, время внесения, сохранённый канал, замечания и решения.
- Чекбокс отдельно от раскрытия; выбор доступных записей по одной и всех видимых, подтверждение
  и отмена через существующий порт. Замечания остаются для индивидуальной проверки.
- Принятая запись участвует в существующем табеле на исходную дату и объект без копирования.
- Проверки клавиатуры, мобильных целей, раскрытия, независимого выбора и прежних действий.

## Следующие этапы: объект → бот → смета → настройки

1. Проверить серверный путь сообщения MAX/Telegram через существующий общий обработчик
   и порт до очереди. Режим автопилота может принимать чистые записи автоматически:
   если требуется ручная проверка всех поступлений, менеджер выбирает существующий режим
   «проверять все». Не менять режим без отдельного решения владельца.
2. Сохранять конкретный мессенджер в записи. Сейчас EntryChannel хранит только общее `bot`;
   историческим записям нельзя приписывать MAX или Telegram без доказательств.
3. В настройках явно связать подключения, доступные сотруднику объекты и подтверждённые
   сметы объектов. Проверить права и серверное хранение; токены не показывать в браузере.
4. Требование владельца: бот привязан к объекту. Следующим этапом спроектировать реестр
   подключений по объектам и серверную проверку маршрутизации. Существующий бот с выбором
   объекта не равнозначен отдельному подключению на объект. Не создавать внешних ботов
   и не менять модель хранения в рамках первого этапа экрана.
5. Пройти реальную доставку из каждого настроенного мессенджера, повторы вебхука, проверку
   менеджером и табель. Без серверных подключений и токенов не объявлять интеграции рабочими.

Публикация в рамках этого изменения не выполняется.
