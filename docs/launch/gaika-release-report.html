Как работает сервис

Подрядчик газовой компании ведёт учёт выработки бригад. Стоимость работ берётся из сметы и делится на время, которое бригада провела на объекте.

  1. Справочники

    Администратор загружает бригады и сотрудников из Excel. Перед применением видно, что добавится, обновится и пропустится, с причиной по строке.

  2. Объекты и график

    Менеджер заводит объекты и загружает график недели: какая бригада на каком объекте в какой день.

  3. Смета и формула

    Смета из Excel разбирается по колонкам, привязывается к объекту и подтверждается. Формула решает, какие строки сметы идут плюсом, какие минусом: например, «всего без НДС плюс технадзор минус материалы».

  4. Время от бригадира

    Бригадир в боте выбирает объект из графика и пишет фразу «с 8 до 17», указывает перерыв. Денег он не видит. Запись уходит на проверку.

  5. Проверка

    Менеджер видит запись с долей сметы, источником суммы и ценой часа. «Принять» или «Исправить» с причиной.

  6. Отчёт

    Руководитель выгружает утверждённый Excel по форме заказчика с контрольной суммой и закрывает неделю. Неделя идёт с понедельника по субботу и сменяется сама.

В демо данные живут во вкладке браузера. В рабочем контуре всё лежит в PostgreSQL, права ролей проверяет сервер, а файл Excel собирается из базы, а не из того, что прислал экран.

Что сделано

Рабочий контур новое

  • db:gas-init: пустая компания без демо-данных и ссылка администратора
  • db:gas-user: менеджер, руководитель, бригадир со своей бригадой, у каждого ссылка входа
  • «Сегодня» и неделя идут по часам сервера, прошлые недели остаются в базе
  • При отказе сервера экран говорит причину и даёт «Войти» и «Повторить», а не подменяет данные демо
  • Excel собирается из базы с проверкой роли: подставить сумму с экрана нельзя

Сайт

  • Градиенты и сияние первого экрана, бегущая строка возможностей
  • Страницы «Для кого», «Как работает», раздел статей и 6 статей
  • 12 новых адресов в меню, подвале, sitemap

Исправления

Инструкция: запуск пилота на сервере

Подробно в docs/runbook/pilot.md. Нужны сервер с Docker, домен, имена и телефоны людей, файлы заказчика: бригады, график, сметы.

cp deploy/.env.example deploy/.env    # DOMAIN, GAIKA_MODE=server, POSTGRES_PASSWORD, SESSION_SECRET, APP_TIME_ZONE
docker compose --env-file deploy/.env up -d db
docker compose --env-file deploy/.env --profile tools run --rm migrate        # только с «да» владельца
docker compose --env-file deploy/.env --profile tools run --rm migrate \
  bun run db:gas-init --name "Имя Фамилия" --phone "+7…" --group "1. Стальные" --url "https://$DOMAIN"
docker compose --env-file deploy/.env up -d --build app caddy

  1. Администратор

    Входит по ссылке из db:gas-init. «Данные»: «Бригады из Excel», «Сотрудники из Excel».

  2. Люди

    db:gas-user --role manager, director, foreman --brigade "Бригада 1". Каждая команда печатает ссылку на 72 часа, одноразовую. Передать лично.

  3. Первая неделя

    Менеджер: объекты, график, смета, формула. Бригадиры вносят время с телефона. Менеджер проверяет. Руководитель выгружает Excel и закрывает неделю.

Инструкция: показ на демо

Перед встречей «Сбросить демо». Один раз скажите: бот MAX не подключён, бот на экране работает так же, как будет в MAX.

  1. Справочники

    /gas/directory: бригады и сотрудники из Excel, «Всё верно, применить».

  2. Объект, график, смета, формула

    /gas/objects, /gas/estimates: «Подтвердить смету», «Настроить», «Сохранить редакцию».

  3. Бот бригадира

    /gas/foreman: «Внести время», «с 8 до 17», перерыв, «Отправить».

  4. Проверка и Excel

    /gas/moderation «Принять», затем /gas/tabel «Выгрузить Excel» и сверка на /gas/week.
