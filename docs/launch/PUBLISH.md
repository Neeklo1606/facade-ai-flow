# Публикация сайта и демо: что сделать владельцу

Шаг L9 (01_SPEC 13 и 14). Слияние в main и Publish делает владелец (ОСТАНОВКА 2 и 3).
Значений здесь нет: ключи и адреса задаются только в окружении хостинга Lovable.

## 1. Переменные окружения

`VITE_*` подставляются при сборке: после изменения нужен повторный Publish. Остальные
читаются сервером при запросе.

### Сайт и тексты (сборка)

| Переменная                            | Нужна                       | Что делает                                                                |
| ------------------------------------- | --------------------------- | ------------------------------------------------------------------------- |
| `VITE_PUBLIC_URL`                     | при своём домене            | canonical, `og:url`, адреса картинок превью и ссылки набора партнёра      |
| `VITE_CONTACT_TG`                     | да                          | Telegram владельца без @: честный переход формы, ссылки «Написать»        |
| `VITE_PRICE_RAZBOR`                   | по желанию                  | Цена экспресс-разбора; пусто: «Стоимость сообщим после заявки»            |
| `VITE_RAZBOR_CREDIT`                  | по желанию                  | `on`: строка «засчитывается в пилот при старте в течение 14 дней»         |
| `VITE_PRICE_PILOT`                    | по желанию                  | Цена пилота в «Как начать»; пусто: строка цены не выводится               |
| `VITE_PRICE_IMPL`                     | по желанию                  | Цена внедрения; пусто: не выводится                                       |
| `VITE_PRICE_SUPPORT`                  | по желанию                  | Цена сопровождения; пусто: не выводится                                   |
| `VITE_CASE_STATUS`                    | по желанию                  | Метка кейса, по умолчанию «Внедрение, октябрь 2026»                       |
| `VITE_CASE_CLIENT_NAME`               | только с согласия заказчика | Название заказчика в кейсе; пусто: без названия                           |
| `VITE_LEGAL_LINE`                     | желательно                  | Реквизиты в подвале и оператор в политике                                 |
| `VITE_PRIVACY_FINAL`                  | после юриста                | `on`: снимает пометку «Черновик, проверяется юристом» с политики          |
| `VITE_METRIKA_ID`                     | по желанию                  | Номер счётчика Метрики; без него строки согласия нет и скрипт не грузится |
| `VITE_VIDEO_URL`, `VITE_VIDEO_POSTER` | по желанию                  | Видео на лендинге, грузится по нажатию                                    |

### Сервер (при запросе)

| Переменная                                           | Нужна         | Что делает                                                                  |
| ---------------------------------------------------- | ------------- | --------------------------------------------------------------------------- |
| `LEADS_TELEGRAM_BOT_TOKEN`, `LEADS_TELEGRAM_CHAT_ID` | одна из двух  | Заявки приходят в Telegram владельца                                        |
| `LEADS_WEBHOOK_URL`                                  | одна из двух  | Заявки уходят POST JSON на вебхук (например, таблица «Лиды»)                |
| (ничего из двух)                                     |               | Форма честно ведёт в Telegram с готовым текстом и не пишет «отправлено»     |
| `CLIENT_LINK_KEY`                                    | для заказчика | Ключ личной ссылки `/gas?c=…`: бренд, вопросы и сверка заказчика            |
| `SEO_INDEX`                                          | по решению    | `on`: страницы сайта открываются поиску; `/kit` и приложение закрыты всегда |
| `SESSION_SECRET`                                     | желательно    | Подпись куки персоны демо                                                   |
| `DEMO_ACCESS_GATE`, `DEMO_ACCESS_KEY`                | не задавать   | Шлюз ключа: по решению 21.10.2026 демо открывается без ключа                |
| `AI_MODE`, ключи моделей и речи                      | не задавать   | Живые модели в этот запуск не входят                                        |

Статус приёма заявок и личного контура виден в кабинете: «Кабинет компании» → «Подключения»
(роль руководителя), без значений ключей.

## 2. Ссылки для рассылки

```
https://<адрес>/                  сайт: что это, за 30 секунд
https://<адрес>/demo              демо с телефона, 3 минуты
https://<адрес>/case/gas          кейс газового подрядчика
https://<адрес>/razbor            экспресс-разбор, заявка
https://<адрес>/kit               набор партнёра (только партнёрам, нигде не выводится)
https://<адрес>/gas?c=<ключ>      личная ссылка заказчика, только ему
```

Партнёр добавляет свой код в `/kit`: ссылки получают `?src=<код>`, код уходит в заявку.

## 3. Проверка с телефона за 2 минуты после Publish

1. `/`: первый экран, «Открыть демо» видна без прокрутки, тема по системе.
2. Пролистать до формы: липкая «Открыть демо» появилась после первого экрана и спряталась у формы.
3. `/demo` → «Начать показ»: открылся бот бригадира, полоса «1/6».
4. Бот: «Внести время» → «Сказать голосом» → «Готово»: фраза разобрана, «Отправить».
5. Полоса показа: «Как менеджер» → «Подтвердить» → «Как руководитель» → строка подсвечена.
6. «Выгрузить Excel»: файл скачался. «Итог показа» → «Разобрать мои данные» → `/razbor`.
7. Отправить заявку с тестовыми данными: при заданном приёме «Заявка отправлена» и сообщение
   пришло; без него честный переход в Telegram.
8. Переслать ссылку `/` себе в Telegram: превью с картинкой и заголовком.
9. «Ещё» → «Сбросить демо-данные».
10. Личная ссылка заказчика: его бренд и «Сверка с вашим файлом»; в другом браузере без
    ссылки бренда нет.
