Основание: 01_SPEC 10 и 11.

```text
Следуй docs/launch/00_SYSTEM.md. Выполни шаг L6.

ADR-051 «Заявки, аналитика и превью ссылок» до кода: порт LeadSink и адаптеры, порт Analytics
и согласие, что пишется в журнал хостинга и что нет, og-картинки.

1. ЗАЯВКИ
   - Порт LeadSink в src/ports, адаптеры telegram, webhook, none в src/adapters/leads,
     выбор по переменным окружения на сервере. Ключи только в окружении.
   - POST /api/leads: zod, ловушка, лимит 5 в час с IP (в памяти воркера достаточно для старта,
     ограничение записать в ADR), 204 или 400. Персональные данные в журнал не пишутся.
   - Форма на /, /razbor, финалах показа: состояния «отправляю», «отправлено», «ошибка, повторить».
     При адаптере none сервер отвечает 501 с признаком, форма показывает честный переход
     в Telegram с готовым текстом заявки (01_SPEC 11.1). Тест: ни при каком ответе сервера
     не показывается «Заявка отправлена», если сервер её не принял.
   - Тесты адаптеров на подменённом fetch: формат сообщения Telegram, тайм-аут, ошибка.

2. СТРАНИЦЫ
   - /case/gas по 01_SPEC 10.1. Название заказчика и цифры эффекта только из config.
   - /razbor по 01_SPEC 10.2. Цена и зачёт в пилот только из config.
   - /kit по 01_SPEC 10.3: копирование, Web Share, QR на клиенте (небольшая библиотека
     или своя реализация, без внешних сервисов), код партнёра в ссылках ?src=, текст первого
     сообщения. noindex, ссылка на /kit нигде не выводится.
   - /privacy по 01_SPEC 10.4 с пометкой «Черновик» до VITE_PRIVACY_FINAL=on.
   - Параметр src из адреса сохраняется на время сессии и уходит в заявку.

3. АНАЛИТИКА
   - Порт Analytics, адаптеры none и metrika. Строка согласия внизу экрана, решение хранится
     в localStorage (try/catch). Без согласия скрипт Метрики не загружается вовсе.
   - События 01_SPEC 11.2 в местах вызова через порт, не через window напрямую.

4. ПРЕВЬЮ ССЫЛОК
   - scripts/og-images.ts: Playwright снимает 1200 x 630 из специальной страницы /og/<имя>
     (только в dev) для /, /demo, /case/gas, /razbor; картинки в public/og/.
   - og и twitter теги на четырёх страницах, og:url от VITE_PUBLIC_URL.
   - Проверка: запросы с user-agent TelegramBot, vkShare, WhatsApp получают 200 и теги.

Проверка: bun run ci; e2e: заявка с лендинга при none (честный переход), при webhook
на тестовом сервере (204 и формат тела), ловушка, лимит; /kit копирует ссылку с ?src=,
QR декодируется обратно в ту же ссылку (тест), share вызывается; снимки всех страниц
на 390 и 1440 в docs/launch/after/site/. Отчёт. Без остановки.
```
