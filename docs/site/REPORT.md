# Сайт v2: отчёт приёмки

Задание `docs/site/GAIKA_SITE_V2.md`, ветка `feature/site-v2` от origin/main 0b30f4c.
Решения: ADR-067. Матрица возможностей: `docs/site/CAPABILITIES.md`. Журнал: `docs/site/LOG.md`.
Референсы: `docs/site/REFERENCES.md`. Снимки: `docs/site/before` и `docs/site/after`
(все страницы на 390 и 1440, пара «было / стало» главной: `home-390.png`, `home-1440.png`).

## Что сделано

- Главная по разделу 5: первый экран с живым фрагментом недели, три задачи со статусами,
  путь из четырёх шагов со снимками, «Меньше переписывания», контроль, кейс, как начать
  с ценой из config, 6 вопросов, заявка с выбором задачи, липкая кнопка телефона.
- Три страницы задач по одному шаблону (раздел 6): крошки, статус, H1, снимок, роли, шаги,
  результат, границы, 4 вопроса, заявка с задачей, ссылки на две другие задачи и кейс.
- `/case/gas`, `/razbor`, `/demo`, `/privacy`, `/kit` в новом виде, страница 404 сайта.
- 12 настоящих снимков экранов демо (`bun run site:shots`), превью ссылок трёх задач.
- SEO одной переменной `SEO_INDEX`: мета, `x-robots-tag`, `robots.txt`, `sitemap.xml`,
  JSON-LD (Organization, SoftwareApplication, FAQPage, BreadcrumbList), коды Вебмастера.
- Анимация раздела 8 на CSS и requestAnimationFrame, без библиотек.
- Заявка: поле «Какая задача», источники страниц задач, события аналитики раздела 11.

## Решения, которые владельцу нужно знать

1. **Статус учёта времени «Пилот у первого заказчика»**, а не «Работает у первого заказчика».
   Рабочей базы нет, заказчик смотрит свой отчёт по личной ссылке (ADR-067, решение 2).
   Когда появится рабочий контур, это одна строка в `src/lib/site/copy.ts`.
2. **H1 главной запасной**: «Табель, снабжение и документы ПТО из данных с объекта».
   Основной вариант на 390 при 32/38 занял 4 строки (раздел 5.2 разрешает замену).
3. **Шесть фраз поправлены по коду** (матрица, ADR-067, решение 3): правка после закрытия
   недели идёт через переоткрытие с причиной; у суммы видны смета, версия и кто подтвердил,
   строки сметы нет; предложения сравниваются карточками, а не таблицей; выработка на
   человеко-час не показывается; Google Таблицы не проверены; своих шаблонов документов нет.
4. **Снабжение и ПТО в демо заморожены флагом ADR-061.** Плитки этих задач на `/demo`
   открывают их на сессию вкладки (ADR-067, решение 11). Сборка, `/gas` по ссылке и личный
   контур заказчика не меняются. Если заморозка должна держаться и на сайте, это одна
   функция `openFrozenModules` в `src/routes/demo.tsx`.
5. **Снимки продукта в теме «Газ v4» с оранжевым.** Это настоящий интерфейс; сам сайт
   остаётся монохромным.

## Что не выполнено

**P1. Lighthouse телефона 76-80 при цели 90.** LCP это H1, он ждёт общий файл стилей
приложения (41 КБ gzip, блокирует отрисовку) и предзагрузку модулей приложения. На origin/main
главная v1 меряется так же (LCP 4,5-6,5 с тем же способом), то есть это не регрессия сайта.
Удаление предзагрузки шрифтов 500 и 600 ничего не дало (проверено, возвращено). Что поможет:
отдельный маленький файл стилей для страниц сайта или встроенный критичный CSS первого экрана.
Это правка общей сборки, а не файлов сайта, поэтому ночью не делалась. Замер локальный
через прокси с gzip; на опубликованном адресе с HTTP/2 и brotli цифра может быть выше,
её нужно снять после Publish.

**Best practices 96 на /snabzhenie (компьютер)**: скрытая на компьютере копия снимка
в мобильном списке шагов попадает в аудит соотношения сторон. Порога в задании нет.

**Lovable Publish, переменные хостинга, Вебмастер и Search Console** делает владелец (раздел 15).
