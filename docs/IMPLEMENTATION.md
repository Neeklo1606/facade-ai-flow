# Внедрение neeklo FieldOps: от решения до первой рабочей недели

Документ для того, кто внедряет neeklo FieldOps, пакет Фасады, в компании. Здесь описано то,
что продукт умеет сегодня, а не то, что задумано: шаги, которые пока не проходятся, названы
прямо, вместе с тем, что делать вместо них.

**Сколько это занимает.** Первые два дня — разворот и справочники; дальше объём работы зависит
от того, что уже подключено. Участие со стороны заказчика — один человек (обычно ПТО или
снабженец) по два часа в день.

> **Что сегодня проходится, а что нет.** Пустая база пока не заводится без разработчика: первого
> сотрудника в ней создать нечем, а без него никто не войдёт. После того как первый руководитель
> появился, справочники, поставщики, сотрудники, приглашения и вход проходятся полностью с
> экрана. Цепочки «документ → позиции → запрос → поставка» и «отчёт с площадки → приёмка объёма
> → ход работ» на новом объекте не проходятся вовсе. Три недостающие вещи и что делать с ними —
> в разделе [«Чего пока нет»](#чего-пока-нет). Пока они не закрыты, внедрение у заказчика
> начинать нельзя.

## Шаг 1. Что подготовить до начала (1 день)

| Что нужно                         | В каком виде                                                       | Кто даёт    |
| --------------------------------- | ------------------------------------------------------------------ | ----------- |
| Список объектов в работе          | название, код, регион, заказчик, договор, сроки, ответственный     | руководство |
| Дерево категорий материалов       | 5–15 категорий верхнего уровня и подкатегории под них              | снабжение   |
| Номенклатура материалов           | Excel: наименование, единица, категория (колонки в любом порядке)  | снабжение   |
| Поставщики                        | название, ИНН, регион поставки, категории, контакт, телефон, почта | снабжение   |
| Сотрудники                        | ФИО, должность, **телефон**, роль в системе, объекты               | руководство |
| Проектная документация по объекту | PDF, DOCX или XLSX — пока только для хранения, см. «Чего пока нет» | ПТО         |

Про номенклатуру: **категория в файле обязательна**, и она должна совпадать с названием
категории в дереве. Строки с незнакомой категорией не загрузятся, и вы увидите их номера —
поэтому дерево заводят раньше номенклатуры, а не наоборот.

Про телефоны: вход в систему — по телефону и коду из SMS, пароля нет (строители их забывают,
а у прорабов нет рабочей почты). Телефон сотрудника — обязателен, почта — нет.

Чего **не** нужно: приводить названия номенклатуры к единому виду — сопоставление проектных
названий со справочником делает система, человек подтверждает.

## Шаг 2. Развернуть систему (полдня)

Порядок в [RUNBOOK.md](RUNBOOK.md) и [runbook/database.md](runbook/database.md). Коротко:

1. База PostgreSQL на вашем сервере или в вашем облаке.
2. Миграции одной командой. Начальных справочников в базе нет — их заводят с экрана на шаге 3.
3. Приложение: адрес, сертификат, переменные окружения. Для входа сотрудников нужны
   `DATABASE_URL` и канал отправки кодов (`AUTH_CHANNEL`).
4. **Первый руководитель.** `bun run db:owner --name "…" --phone "+7…" --url "https://…"` —
   заводит первого сотрудника и печатает одноразовую ссылку для входа на 72 часа. Только в
   пустую базу. Команда и сервер работают с одним `SESSION_SECRET`, иначе ссылка не подойдёт.
   `bun run db:seed` в базу заказчика **не запускают**: он заливает вымышленные объекты и людей.
5. Проверка: открыть реестр объектов, завести тестовый объект, открыть его карточку. Удаления
   объекта в системе нет — тестовый объект остаётся в реестре, дайте ему говорящее название.

**Данные не покидают ваш контур.** Ни документы, ни цены, ни контакты поставщиков наружу
не уходят.

## Шаг 3. Завести объекты и справочники (1 день)

Всё с экрана, доступ к базе не нужен.

1. **Объекты:** реестр объектов → «Создать объект». Название, код, регион, заказчик, договор,
   сроки, ответственный. Заказчик создаётся сам, если такого контрагента ещё нет.
2. **Дерево категорий:** «Справочники» → «Категория верхнего уровня» и «Подкатегория».
   Правила определения по наименованию можно заполнить сразу, можно потом: по ним система
   предлагает категорию новому материалу.
3. **Номенклатура:** «Справочники» → «Загрузить из Excel». Выберите файл, проверьте
   сопоставление колонок (система угадывает по заголовкам), посмотрите предпросмотр и
   загрузите. В отчёте будет видно, сколько добавлено, сколько обновлено и какие строки
   не приняты — с номером строки и причиной. Поправьте их в файле и загрузите его снова:
   уже загруженное обновится, а не задвоится.
4. **Поставщики:** объект → «Поставщики и запросы» → вкладка «Поставщики» → «Завести
   поставщика». Регион и категории обязательны: по ним система подбирает, кому уходит запрос.
5. **Проверка:** откройте любой материал и убедитесь, что по его категории есть поставщики.
   Пустой список здесь означает, что подбор на шаге закупки тоже будет пустым.

Все изменения справочников видны в журнале: «Справочники» → «Журнал» — кто, когда, что было
и что стало.

## Шаг 4. Пригласить сотрудников (полдня)

Роли — по работе, а не по должности:

| Роль                 | Кому                   | Что открыто                              |
| -------------------- | ---------------------- | ---------------------------------------- |
| Руководитель проекта | ведёт объект целиком   | всё по своим объектам                    |
| Снабжение            | закупки и поставщики   | материалы, запросы, поставки, поставщики |
| ПТО                  | проверяет документацию | документация, материалы, отчёты          |
| Прораб               | площадка               | отчёты, приёмка на своих объектах        |
| Директор             | смотрит, но не правит  | чтение всего                             |

Порядок: «Сотрудники» → «Добавить сотрудника» (ФИО, телефон, роль, объекты) → «Пригласить».
Ссылка приглашения живёт 72 часа и срабатывает один раз; после неё сотрудник входит по
телефону и коду. Доступ выключается кнопкой «Выключить» — она же закрывает все его сессии.

Матрицу прав видно в разделе «Права доступа» — покажите её сотрудникам сразу: половина вопросов
о том, «почему я не вижу раздел», снимается этой таблицей.

## Шаг 5. Telegram-бот (пока не подключается)

Бот задуман для прорабов: отчёт голосом и приёмка с телефона. **Сейчас его нет:** приём
сообщений из Telegram и распознавание речи — работа очереди R3–R4, ключ бота прописывать некуда.

Что вместо него: отчёт с площадки заводит руководитель, ПТО или прораб вручную — кнопкой
«Завести отчёт» на экране отчётов. Источник записывается честно: «заведён вручную», кем и когда.
Оговорка про отсутствие бота стоит первым абзацем в статье справки о Telegram.

Ограничение сегодняшнего дня: отчёт требует зоны работ, а зоны на новом объекте создать нечем —
см. [«Чего пока нет»](#чего-пока-нет).

## Шаг 6. Обучение (2 часа)

Не лекция, а работа на своём объекте. По ролям — то, что сегодня действительно проходится:

- **Снабжение** — завести категории, загрузить номенклатуру из своей выгрузки, разобрать
  непринятые строки, завести пять поставщиков (60 минут).
- **Руководитель** — завести объект, пригласить сотрудников, раздать роли и объекты (30 минут).
- **Все** — войти по телефону и коду, найти свой рабочий экран, посмотреть матрицу прав
  (20 минут).
- **ПТО и прораб** — обучение работе с позициями и отчётами откладывается до подключения
  ввода позиций и зон: сейчас показывать на своём объекте нечего.

Материал для обучения — [USER_GUIDE.md](USER_GUIDE.md) и раздел «Справка» внутри системы.

## Первая неделя

То, что проходится на новом объекте сегодня:

| День | Что делают                                                            | Кто                  |
| ---- | --------------------------------------------------------------------- | -------------------- |
| 1    | Разворот, проверка адреса и входа, тестовый объект                    | внедренец            |
| 2    | Объекты, дерево категорий, номенклатура из Excel, поставщики          | снабжение            |
| 3    | Сотрудники, приглашения, вход каждого, разбор матрицы прав            | руководство          |
| 4    | Загрузка документации в реестр: хранение и ревизии без разбора файла  | ПТО                  |
| 5    | Итог: что готово, что ждёт ввода позиций и зон, план следующей недели | внедренец и заказчик |

Каждый день — 15 минут с внедренцем: что мешает, что непонятно, что править в справочниках.

## Чего пока нет

Две недостающие вещи, каждая из которых обрывает свою цепочку. Это не оговорки на будущее:
на новом объекте эти шаги сегодня физически не проходятся.

| Чего нет                  | Что из-за этого не работает                                                      | Что делать сейчас                                                  |
| ------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Ввод позиций спецификации | документ → позиции → проверка → передача в закупку → запрос → поставка → приёмка | документы хранить в реестре; закупку вести как раньше, вне системы |
| Зоны работ на объекте     | отчёт с площадки → приёмка объёма → ход работ → «Требует решения» по отставанию  | отчёты собирать как раньше; в системе их пока не завести           |

Подробно:

1. **Позиции.** Разбор загруженного файла не подключён, и завести позицию руками тоже нельзя:
   экран проверки умеет подтверждать, исправлять, делить и объединять позиции, но не создавать.
   Поэтому после загрузки документа список позиций пуст, и экран говорит об этом прямо —
   ожидания «обрабатывается» там больше нет.
2. **Зоны.** Отчёт с площадки привязывается к зоне работ (ось, этаж, фасад). На объектах
   демонстрационного набора зоны есть, у нового объекта их нет, а создать зону с экрана нечем.
   Значит, форма «Завести отчёт» на новом объекте не заполнится.

Пока эти два шага не закрыты, внедрение честно выглядит так: система принимает справочники,
поставщиков, сотрудников и документы, а работа с позициями и площадкой остаётся снаружи.
Обещать заказчику полный контур на этой версии нельзя.

## Критерии успешного запуска

Что проверяемо сегодня:

1. Первый руководитель вошёл в систему по своему телефону.
2. Справочники заведены с экрана: дерево категорий, номенклатура из выгрузки заказчика,
   поставщики с регионом и категориями. Непринятые строки разобраны, а не оставлены «как-то так».
3. По любому материалу из справочника подбор поставщиков не пуст.
4. Сотрудники заходят сами: по телефону и коду, без внедренца и без пароля.
5. Каждый видит свой рабочий экран с корня адреса, и ни у кого нет «Нет доступа» вместо работы.
6. Документация объекта загружена в реестр, ревизии видны, файл открывается.
7. Ни одна цифра на дашборде не вызывает вопроса «откуда она»: на каждую есть источник.

Что проверить нельзя до закрытия пунктов из «Чего пока нет»:

- проверка позиций и передача в закупку;
- запрос поставщикам, сравнение предложений, решение с причиной;
- приёмка поставки и закрытие расхождения;
- отчёт с площадки и принятый объём в «Ходе работ».

Если сотрудники не заходят сами — дело не в обучении, а в том, что работа в системе пока дороже
работы в Excel. Разберите с людьми, где именно.

## Частые трудности

| Трудность                                      | Что делать                                                                            |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| Номенклатура в Excel «как попало»              | загружайте как есть: колонки сопоставите в мастере, непринятые строки видны списком   |
| В файле нет колонки «категория»                | добавьте её в файл: без категории материал не попадёт ни в один подбор поставщиков    |
| Загрузка приняла не все строки                 | поправьте названные строки в файле и загрузите его снова — задвоения не будет         |
| У прораба нет рабочей почты                    | и не нужна: вход по телефону и коду, приглашение можно отправить ссылкой в мессенджер |
| Спросили про распознавание документов и отчёты | скажите как есть: этого пока нет, план — в разделе «Чего пока нет»                    |
