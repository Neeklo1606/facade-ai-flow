# Внедрение: от решения до первой рабочей недели

Документ для того, кто внедряет систему в компании. Порядок проверен на демонстрационном
наборе данных; в реальной компании сроки зависят от того, в каком виде лежит номенклатура
и сколько объектов берут в работу сразу.

**Сколько это занимает.** Первый объект — рабочая неделя при участии одного человека со стороны
заказчика (обычно ПТО или снабженец) по два часа в день. Второй и последующие объекты — день,
потому что справочники уже заполнены.

## Шаг 1. Что подготовить до начала (1 день)

| Что нужно                         | В каком виде                                | Кто даёт    |
| --------------------------------- | ------------------------------------------- | ----------- |
| Список объектов в работе          | название, адрес, заказчик, договор, сроки   | руководство |
| Проектная документация по объекту | PDF, DOCX или XLSX: спецификации, ведомости | ПТО         |
| Номенклатура материалов           | выгрузка из 1С или Excel: название, единица | снабжение   |
| Поставщики                        | название, ИНН, контакты, что возят, регион  | снабжение   |
| Сотрудники                        | ФИО, должность, телефон, роль в системе     | руководство |

Чего **не** нужно: приводить номенклатуру к единому виду — система сама сопоставляет проектные
названия со справочником и показывает, где не уверена.

## Шаг 2. Развернуть систему (полдня)

Порядок в [RUNBOOK.md](RUNBOOK.md) и [runbook/database.md](runbook/database.md). Коротко:

1. База PostgreSQL на вашем сервере или в вашем облаке.
2. Миграции одной командой, начальные справочники — из подготовленных файлов.
3. Приложение: адрес, сертификат, переменные окружения.
4. Проверка: открыть реестр объектов, завести тестовый объект, удалить его.

**Данные не покидают ваш контур.** Ни документы, ни цены, ни контакты поставщиков наружу
не уходят.

## Шаг 3. Завести объекты и справочники (1 день)

1. Заведите объекты: название, заказчик, договор, сроки, ответственный.
2. Загрузите номенклатуру и дерево категорий: от него зависит подбор поставщиков.
3. Заведите поставщиков и отметьте, какие категории они возят и в каких регионах.
4. Проверьте на одном материале: система должна предложить поставщиков, а не пустой список.

## Шаг 4. Пригласить сотрудников (полдня)

Роли — по работе, а не по должности:

| Роль                 | Кому                   | Что открыто                              |
| -------------------- | ---------------------- | ---------------------------------------- |
| Руководитель проекта | ведёт объект целиком   | всё по своим объектам                    |
| Снабжение            | закупки и поставщики   | материалы, запросы, поставки, поставщики |
| ПТО                  | проверяет документацию | документация, материалы                  |
| Прораб               | площадка               | отчёты, приёмка на своих объектах        |
| Директор             | смотрит, но не правит  | чтение всего                             |

Матрицу прав видно в разделе «Права доступа» — покажите её сотрудникам сразу: половина вопросов
о том, «почему я не вижу раздел», снимается этой таблицей.

## Шаг 5. Подключить Telegram-бота (полдня)

Бот нужен прорабам: отчёт голосом и приёмка с телефона.

1. Создайте бота и получите ключ.
2. Пропишите ключ в переменных окружения системы.
3. Каждый прораб получает одноразовую ссылку и отправляет её боту — чат связывается с учётной
   записью.
4. Проверьте на одном прорабе: голосовое → расшифровка → подтверждение → отчёт в системе.

**Сейчас этого нет:** приём из Telegram и распознавание речи — работа очереди R3–R4. До их
появления отчёт заводит руководитель или ПТО вручную, всё остальное работает.

## Шаг 6. Обучение (2 часа)

Не лекция, а работа на своём объекте. По ролям:

- **ПТО** — загрузить свою спецификацию и проверить первые 50 позиций (40 минут).
- **Снабжение** — собрать из проверенных позиций запрос и отправить (30 минут).
- **Прораб** — принять поставку по чек-листу и сдать отчёт (30 минут).
- **Руководитель** — разобрать очередь «Требует решения» (20 минут).

Материал для обучения — [USER_GUIDE.md](USER_GUIDE.md) и раздел «Справка» внутри системы.

## Первая неделя

| День | Что делают                                                       | Кто       |
| ---- | ---------------------------------------------------------------- | --------- |
| 1    | Загружают документацию первого объекта, проверяют первые позиции | ПТО       |
| 2    | Заканчивают проверку, передают в закупку                         | ПТО       |
| 3    | Собирают и отправляют первые запросы поставщикам                 | Снабжение |
| 4    | Разбирают ответы, фиксируют первое решение                       | Снабжение |
| 5    | Принимают первую поставку, сдают первый отчёт с площадки         | Прораб    |

Каждый день — 15 минут с внедренцем: что мешает, что непонятно, что править в справочниках.

## Критерии успешного запуска

Запуск состоялся, если через неделю:

1. Вся документация первого объекта загружена, а позиции проверены не менее чем на 90 %.
2. Отправлен хотя бы один запрос поставщикам и зафиксировано хотя бы одно решение с причиной.
3. Принята хотя бы одна поставка с актом; расхождение, если было, закрыто.
4. Сдан хотя бы один отчёт с площадки, и принятый объём виден в «Ходе работ».
5. Сотрудники заходят сами, без напоминаний внедренца.
6. Ни одна цифра на дашборде не вызывает вопроса «откуда она»: на каждую есть источник.

Если пункт 5 не выполняется — дело не в обучении, а в том, что работа в системе пока дороже
работы в Excel. Разберите с людьми, где именно.

## Частые трудности

| Трудность                                  | Что делать                                                                    |
| ------------------------------------------ | ----------------------------------------------------------------------------- |
| Номенклатура в Excel «как попало»          | загружайте как есть: сопоставление предложит система, человек подтвердит      |
| Прорабы не пользуются ботом                | начните с приёмки: она даёт им защиту в споре, а не лишнюю работу             |
| Снабжение продолжает писать письма вручную | покажите сравнение предложений: ручной сбор цен в Excel занимает втрое дольше |
| Позиции распознались неточно               | это нормально: у каждой видно источник и уверенность, исправление — два клика |
