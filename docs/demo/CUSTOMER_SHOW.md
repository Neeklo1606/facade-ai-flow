# Показ ГАЙКИ на данных заказчика

## Подготовка

В этой облачной среде активируйте Bun: `export PATH="/workspace/.tools/node_modules/.bin:$PATH"`.

Запуск из репозитория: `bun install --frozen-lockfile`, затем `bun run dev --host 0.0.0.0 --port 4620`.
Для проверки сборки: `NITRO_PRESET=node-server bun run build`, `PORT=4631 node .output/server/index.mjs`.
Демонстрационная версия живёт в браузере; изменения переживают перезагрузку. Это не серверная база.
Не очищайте данные сайта и не нажимайте «Показать за 3 минуты»: старый тур сбрасывает демо.
Для своих файлов используйте новый вход «Сценарий на ваших данных» на `/gas` → `/gas/demo`.

## Основной показ (10–15 минут)

1. Войдите как менеджер. В сценарии проверьте режим «Все новые записи направляются менеджеру».
   Если автоприём включён, нажмите «Направлять все записи на проверку» до ввода новой записи.
2. «1. Смета»: загрузите XLS/XLSX известного формата (ГРАНД-Смета или ресурсная 14 граф).
   Проверьте лист, колонку сумм, строки и замечания. Сопоставление колонок можно исправить.
   Неизвестный формат не считается распознанным; используйте проверку/ручной ввод существующего экрана.
3. Если объекта ещё нет, закройте карточку разбора: загруженная версия остаётся в списке
   «Ждут подтверждения». Создайте объект в «Объектах» или на `/gas/demo`: адрес, свой номер,
   вид работ. Номер уникален. Вернитесь к сохранённой версии в разделе смет.
4. В смете выберите этот объект. Проверьте замечания и нажмите «Подтвердить смету».
   Стоимость объекта считается действующим правилом «без НДС минус материалы» либо согласованным
   правилом компании. Не путайте весь бюджет сметы со стоимостью работ.
5. «3. Бригада»: создайте бригаду, заполните состав. «Назначить бригаду»: объект, бригада, день.
   Существующий график сохранится; новый объект сразу виден у бригады, бригада — у объекта.
   В отпуске бригада не назначается; доступность меняется на экране бригад.
6. «4. Время»: менеджер выбирает «Ввод за бригаду», затем «Добавить время». Выберите объект,
   день, начало/окончание/перерыв, состав. «Проверить» показывает рассчитанные минуты до отправки.
7. «5. Проверка»: найдите запись по объекту/дате. Раскройте карточку, проверьте автора, канал,
   время и замечания. Примите индивидуально либо выберите допустимые строки для пакета.
   Записи с замечаниями проверяются отдельно. Исправление/отклонение требуют причины.
8. «6. Табель и Excel»: выберите период и вид, откройте таблицу во весь экран, покажите источник
   ячейки и выгрузите утверждённый Excel. Непринятые записи не добавляют утверждённых начислений.
9. «Неделя»/«Обзор»: показатели отражают тот же набор. «Журнал» показывает решения и изменения.

## Отдельный показ будущего расчёта по разделам (не утверждённый отчёт)

На `/gas/demo` выберите объект и нажмите «Открыть проект начислений». Дополнительный экран
загружается по требованию. Из последней привязанной версии загруженного файла берутся
реальные названия и итоги разделов, номер строки и версия. Если разделы не распознаны,
система говорит об этом, не создаёт вымышленных СМР и опрессовку.

Выберите раздел, подтвердите вид «СМР»/«Опрессовка»/«Другие работы». Укажите материалы именно
этого раздела по исходной смете; если их нет — 0. Материалы всей сметы не вычитаются из каждого
раздела. Выберите бригаду, день и долю общего объёма (например 40 %, затем 35 %).

После добавления видны проект начисления и остаток 25 %. Доли больше 100 % запрещены.
Проект сохраняется по объекту, версии и контуру. Новая версия не получает автоматически
доли старой. Ошибка сохранения в браузере показывается явно.

«Скачать проект начислений XLSX» выгружает два листа: доли по дням/бригадам и разделы с остатками.
Этот файл подписан как проект. Он НЕ меняет действующие суммы табеля, закрытые недели и
утверждённую выгрузку: правило объёмного начисления ещё нужно согласовать с заказчиком.

## Что говорить о подключениях

Симулятор бота создаёт записи в этом же demo, но не отправляет сообщения в настоящий MAX/Telegram.
Наличие настроек на сервере не доказывает доставку: статусы теперь говорят «настроен».
Реальная доставка, VPS, токены и транскрипция в рамках этой фронтенд-задачи не подключались.
Не обещайте распознавание голоса без провайдера и не утверждайте суммы голосом/AI.

## Работа с файлами клиента

Файлы импортируются через браузер. Оригинал сметы не становится серверным архивом документов;
сохраняются распознанные значения. Не добавляйте реальные исходники в Git. Для нового клиента
используйте отдельный профиль браузера, чтобы не смешивать локальные данные разных показов.

## Обновлённые рабочие экраны (ADR-076)

- «Проверка»: пустой период подписан «Все даты». «Неделя отчёта» выставляет даты из данных,
  а не сегодняшний день компьютера. Для своего периода заполните «Дата с/по»; при пустом
  результате сбросьте фильтры. Дата, время, часы и сумма показаны отдельными полями карточки.
- «Неделя»: четыре компактных показателя и шесть дневных сумм. Нажатие дня выделяет его и
  показывает точную сумму; рядом переходы к проверке и табелю. Закрывает неделю руководитель.
- «Табель»: выделите ячейку/диапазон, под сеткой нажмите жёлтую, зелёную или сиреневую пометку.
  «Очистить пометку» действует на выделение. Пометки личные для этого браузера, не изменяют
  числа, статусы и утверждённую выгрузку. На телефоне сначала «Открыть как таблицу».
- «Бригады»: откройте строку бригады. В компактной панели менеджера доступны назначение на
  объект и «Изменить состав». Последний переход открывает справочник уже с этой бригадой.
  «Добавить в состав» открывает отдельную форму имени и даты, сохранение обновляет общий список.
  Руководитель видит показатели и сметы, а управление составом остаётся менеджеру/администратору.
