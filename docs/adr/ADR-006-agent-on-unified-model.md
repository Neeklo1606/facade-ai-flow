# ADR-006. Ассистент возвращается на единой модели: ответ из портов и всегда с источником

- **Статус:** принято
- **Дата:** 2026-09-18
- **Уточняет:** [ADR-003](ADR-003-remove-legacy-screens.md) (п. 5 — агент возвращается отдельным решением),
  [ADR-001](ADR-001-data-layer.md) (порты), [ADR-004](ADR-004-demo-adapter-in-browser.md) (два транспорта)

## Контекст

ADR-003 удалил старого AI-агента: он отвечал по отдельной модели данных и называл цифры, которых не было
на экранах объекта. Пункт 5 разрешил вернуть агента только на единой модели и отдельным решением.

Нужен экран `/agent`: пользователь спрашивает об объекте, документах и поставках и получает ответ со ссылкой
на первоисточник. Языковой модели в продукте пока нет, для показа достаточно четырёх сценариев быстрых действий.

## Решение

1. **Порт `agent.ask`** (`src/ports/agent.ts`) в наборе `Repositories`. На вход — вопрос, объект из селектора
   и, для быстрого действия, сценарий. На выход — ответ или `null`.
2. **Ответ собирается из других портов, а не из состояния адаптера** (`src/adapters/agent`). Сводка берёт
   `projects.card`, поставки — `procurement.deliveries` и `requests`, поиск — `positions.list` постранично,
   решения — `timeline.pending` и `reports.list`. Поэтому числа в ответе совпадают с карточкой объекта
   при любом адаптере, и ассистент заработает на PostgreSQL без переписывания.
3. **Без первоисточника ответа нет.** Схема `agentReply` требует `sources.min(1)`: сервер не отдаст ответ без
   источника, экран его не покажет. Источники — записи `sources`: письма поставщиков, сообщения прорабов,
   листы спецификации. Клик по источнику открывает оригинал в панели деталей.
4. **Вопрос вне сценариев — это не ответ.** Порт возвращает `null`, экран показывает подсказку, на что
   ассистент отвечает сейчас. Выдуманного ответа и ответа без источника не бывает.
5. **Сценарий определяется по словам вопроса** (`classifyIntent`), объект — из селектора, по названию
   в вопросе или первым в реестре, где сначала объекты, требующие внимания.
6. **Транспорт как у остальных портов** (ADR-004): в демо — адаптер во вкладке, в рабочем режиме —
   серверная функция `askAgentFn` с проверкой входа и выхода схемами.

## Последствия

**Плюсы**

- Ассистент не может противоречить экранам: у него нет своих данных.
- Каждое утверждение проверяется по оригиналу в один клик.
- Замена сопоставления по словам на языковую модель меняет только выбор сценария и текст, а не контракт
  ответа: источники остаются обязательными.

**Минусы и ограничения**

- Отвечает только на четыре сценария; остальные вопросы получают подсказку.
- Поиск по документам ищет по наименованиям уже разобранных позиций; ревизии без построчного разбора
  не участвуют, и ассистент говорит об этом прямо.
- История диалога и оценки «Полезно / Неточно» не сохраняются.
- Поиск загружает все действующие позиции объекта страницами по 200 — для объектов с десятками тысяч
  строк нужен поиск в SQL.

## Условия приёмки

- Экран и компоненты получают ответ через `src/api` (правило линтера из P1-7).
- Ответ каждого сценария содержит хотя бы один источник; числа сводки совпадают с `projects.card`.
- Вопрос вне сценариев не создаёт ответа системы.
