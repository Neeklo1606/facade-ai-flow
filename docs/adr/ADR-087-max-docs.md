# ADR-087. MAX: адрес API по документации, проверка канала из «Подключений»

Дата: 23.11.2026. Направление: night/docs (промпт C, пункты 3 и 5).

## Контекст

Канал MAX (ADR-061, 14) был каркасом: адрес `platform-api.max.ru`, поля событий и заголовок
секрета взяты из описаний клиентских библиотек и помечены «сверить». В «Подключениях» был
только признак «настроен / не подключён», проверить вебхук и доставку было нечем. Заказчику
нужна инструкция, как завести организацию и бота.

## Сверка с dev.max.ru (23.11.2026)

- Страницы методов `GET /me`, `POST /messages`, `PUT /messages`, `POST /subscriptions`,
  `GET /subscriptions` просят слать запросы на `platform-api2.max.ru`, а не на
  `platform-api.max.ru`. Токен только в заголовке `Authorization: <token>`, в строке запроса
  больше не принимается.
- Секрет подписки приходит в заголовке `X-Max-Bot-Api-Secret`; 5-256 символов, латиница,
  цифры и дефис. Вебхук только HTTPS на порту 443, сертификат доверенного центра или
  Минцифры, самоподписанный не подходит.
- Поля `bot_started` (`user`, `chat_id`, `payload`), `message_callback`
  (`callback.callback_id`, `callback.user.user_id`, `callback.payload`), `message_created`
  (`message.sender.user_id`, `message.body.mid`, `message.body.text`,
  `message.recipient.chat_id`), параметры `user_id` и `message_id`, клавиатура
  `inline_keyboard` с кнопками `callback` и `link` совпали с кодом.

## Решение

1. `MAX_API` = `https://platform-api2.max.ru`. Ожидание теста отправки меняется вместе
   с требованием: тест сверяет новый адрес (`tests/domain/gas-ops-max.test.ts`).
2. `POST /api/gas/max-check`, только администратор (сервер проверяет роль):
   - без `MAX_BOT_TOKEN` в MAX не ходит ничего, ответ: канал не подключён, бригадир
     работает в мобильной веб-форме по ссылке входа;
   - `check`: `GET /me` и `GET /subscriptions`, сверка подписки с адресом
     `https://<домен>/api/max/webhook`, вид секрета. В MAX ничего не меняется;
   - `test`: короткое сообщение только самому администратору в его привязанный аккаунт
     через порт отправки (`createMaxMessenger`).
3. В «Подключениях» строка MAX без токена говорит, как работает бригадир без бота; с токеном
   и базой под строкой две кнопки и результат строками.
4. Подписку вебхука делает администратор сервера командой из `docs/customer/max-setup.md`:
   кнопка «подписать» не добавлена, чтобы экран не менял внешний сервис без нужды.

## Не проверено

Живым ботом: токена нет. Ответ на нажатие кнопки (`POST /answers`) не реализован, как и
раньше: страница метода не прочитана, параметр не подтверждён.
