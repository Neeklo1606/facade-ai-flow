# ADR-040. Голос: машина состояний, порт речи, отмена созданного

Дата: 18.10.2026. Статус: принято. Шаг D1 этапа D (ADR-038).

## Контекст

После G4 запись шла, но расшифровка из интерфейса не вызывалась, а экран писал «речь
не распознаётся» длинным абзацем. Голос ощущался формой, а не продуктом. Состояния экрана
жили в нескольких `useState` и флагах мутаций: повтор «Готово», отказ микрофона и отмена
созданного не были описаны нигде целиком и не проверялись тестами.

## Решения

### 1. Одна линия состояний

Экран `/capture` ведёт чистая машина состояний `src/domain/capture-flow.ts`:

```
idle → recording ⇄ paused → uploading → transcribing → extracting → review → done
                 ↘ no-mic (нет доступа, нет MediaRecorder) → «Показать без микрофона» → uploading
любое рабочее состояние → error (с повтором)
```

- Текст минует запись: набранный текст идёт в `uploading` и дальше без `transcribing`.
- Повтор «Готово» вне записи ничего не делает: второй отправки нет.
- «Уточнить голосом» из `review` возвращает в `recording` с тем же сценарием.
- Из `done` можно отменить созданное в течение 6 секунд; позже отмена не принимается машиной.
- Машина не знает о браузере и сети: события ей приносит экран, а переходы проверяются
  unit-тестами.

### 2. Порт речи отдельно от шлюза разбора

`SpeechPort` (`src/ports/speech.ts`) с тремя реализациями:

| Реализация           | Когда                                                   | Что делает                                              |
| -------------------- | ------------------------------------------------------- | ------------------------------------------------------- |
| `demo`               | `AI_MODE` не `live`, либо нет `STT_API_KEY`/`STT_MODEL` | Подготовленная расшифровка сценария с таймингами слов   |
| `openai`-совместимая | `AI_MODE=live`, `STT_PROVIDER=openai` и ключ            | Запрос к `/audio/transcriptions`, интервалы слов        |
| `yandex`             | `STT_PROVIDER=yandex`                                   | Заготовка: бросает «Распознавание Yandex не подключено» |

Выбор делает чистая функция `pickSpeech(env)`; без ключа в демо-контуре выбирается `demo`,
и это закреплено тестом. Раньше выбор по умолчанию называл `openai` даже без ключа.

Демо-распознаватель живёт только во вкладке демо-контура. Серверная функция рабочего контура
без ключа его не берёт: подготовленная расшифровка на настоящую запись была бы враньём, поэтому
сервер отвечает «Распознавание речи не подключено», и экран предлагает текст.

Демо-реализация честна: в описании порта `demo: true`, и экран ставит одну строку «Демо:
расшифровка подготовлена заранее». Если сценарий не выбран, берётся «Смена». С ключом живой
адаптер подставляется без правки экрана.

Аудио в демо никуда не уходит и не хранится. В рабочем контуре путь хранения идёт через порт
файлов, который пока заглушка (ADR-036, п. 1).

### 3. Отчёт ссылается на запись, из которой он сделан

`createReportInput` получает необязательный `sourceId`. Отчёт из разбора ссылается на источник
записи, а не на новый ручной источник: ПТО в «Проверке» видит фразу прораба (правило 2).
Повтор «Верно» с тем же источником, захваткой, видом работ и объёмом возвращает уже созданный
отчёт: дубля нет (инвариант 2).

### 4. Отмена вместо подтверждения

«Верно» создаёт отчёт и заявку сразу, без диалога. 6 секунд экран «Готово» держит «Отменить»:

- `reports.retract` снимает отчёт, если его автор тот же человек и отчёт ещё на проверке;
  источник записи остаётся (факт не теряется).
- `supply.retractRequest` снимает заявку автора в статусе «Новая».

Права проверяются на сервере: обёртка портов пускает тех, кто пишет отчёты, а действие
сверяет автора. Чужое и уже решённое отменить нельзя.

## Последствия

- Пример «Замечание» уходит из «Примеров показа» (ADR-038); код и разбор остаются.
- В конфиге Playwright появляется проект `mic` с флагами фальшивого микрофона Chromium.
- В журнал обработок пишется и расшифровка: задача `transcribe` уже есть в перечне.
