# ADR-053. Сметы и стоимость работ

Дата: 25.10.2026. Статус: принято, правило состава и формат смет ждут заказчика.
Основание: задача владельца от 25.10.2026, раздел 4; встреча с заказчиком 21.10.2026;
ADR-043 (расчёт от минут), ADR-045 (вид), открытый вопрос 3 ADR-043.

## Task Brief

Цель: разбор сметы перестаёт быть заготовкой (`estimate-samples.ts`). Файл заказчика
читается в браузере, итоги достаются по строкам с номерами, стоимость работ объекта
считается по подтверждённому правилу из подтверждённой версии сметы, а расхождения
показываются, а не прячутся. Плюс недельный график объектов, доступность бригад и режимы
проверки, о которых заказчик говорил 21.10.

Меняются: `src/domain/gas-ops` (новые модули с тестами), порт и демо-адаптер `/gas`,
экраны «Стоимость работ», «Объекты», «Бригады», «Проверка», «Отчёт», «Настройки».
Не меняются: правила расчёта доходности ADR-043, фикстуры «Северной Короны», выгрузка
XLSX отчёта. Класс T2: всё обратимо, рабочей базы нет.

## Решение

### 1. Разбор файла

- Чтение только в браузере, файл не уходит на сервер. Адаптер `src/adapters/gas-ops/estimate-file.ts`
  превращает файл в сетку строк (`(string | number | null)[][]`), формат файла узнаётся по
  сигнатуре (zip или OLE), а не по расширению. Оба формата читает SheetJS CE 0.20.3
  с официального `cdn.sheetjs.com`, версия закреплена в `package.json` адресом архива.
- **Отступление от задачи:** задача предлагала читать xlsx библиотекой exceljs. В браузере
  она весит 250 КБ gzip и одна превышала бы порог самого большого куска (110 КБ), а SheetJS
  всё равно нужна для xls. Поэтому в браузере одна библиотека на оба формата. exceljs остаётся
  на сервере (выгрузка отчёта) и в тестах: тест собирает xlsx exceljs, а читает SheetJS,
  так проверяется путь между двумя независимыми реализациями.
- SheetJS грузится отдельным куском только в момент выбора файла и меряется своим порогом
  `onDemand.xlsx` в `scripts/bundle-budget.json` (165 КБ при замере 156,9). Общий порог
  и порог самого большого куска не менялись. Если модуль не загрузился, экран честно пишет,
  что делать (для xls: «Сохраните как .xlsx»).
- Строки считаются от A1, а не от первой заполненной ячейки: иначе номера строк в замечаниях
  разошлись бы с файлом. Этот дефект поймал тест на синтетическом файле.
- Разбор сетки — чистая функция `parseEstimateGrid` в `src/domain/gas-ops/estimate-parse.ts`.
  Формат определяется по содержимому, а не по расширению:
  - **А, ГРАНД-Смета** (приказ 421/пр): есть «ГРАНД-Смета» или «Итоги по смете» вместе
    с «Всего по разделу». Колонка сумм — «всего в текущем уровне цен», трудозатраты — строка
    «Затраты труда рабочих» в колонке «всего с учетом коэффициентов».
  - **Б, ресурсная 14 граф**: заголовки «Осн.З/п», «Эк.Маш.», «З/пМех», «Мат». Колонка сумм —
    «общая», трудозатраты — «Т/з осн. раб.» в строке итога.
- Числа в файлах бывают и числами, и строками с запятой или точкой («12622,61», «126779.78»):
  разбор принимает оба вида. Деньги внутри считаются в копейках целыми числами.
- Достаются: всего прямые затраты, материалы, ФОТ, накладные, сметная прибыль, всего без НДС,
  ставка и сумма НДС, ВСЕГО по смете, разделы с суммами, трудозатраты рабочих в чел.-ч.
  У каждого значения номер строки файла (правило 2 CLAUDE.md: у значения есть источник).
- Проверки. Смета получает статус **«Требует проверки сметчиком»**, а проблемная строка
  показывается с номером, если:
  1. не найдена строка итога (без НДС или ВСЕГО);
  2. сумма разделов отличается от итога без НДС больше чем на 1 ₽;
  3. без НДС плюс НДС не равно ВСЕГО с точностью до 1 ₽;
  4. ниже строки «ВСЕГО по смете» есть строки с суммами (так в одной смете заказчика
     дописаны «Технадзор», «Врезка» и второе «Итого»: какой итог настоящий, решает сметчик).
     Молчаливого числа нет: при статусе «Требует проверки» кандидат стоимости показывается,
     но подтвердить его нельзя, пока человек не отметит строку как проверенную.

### 2. Правило состава стоимости работ

- Правило — список строк итогов со знаком: `+ без НДС − материалы` по умолчанию.
  Формула показывается словами: «Всего без НДС минус материалы».
- Статус правила: «Требует согласования», пока его не подтвердил сметчик или менеджер.
  Подтверждается один раз на компанию; для объекта можно переопределить, переопределение
  тоже подтверждается и пишется в журнал.
- Почему по умолчанию «без НДС минус материалы»: это кандидат, который владелец привёл
  в задаче, и по смыслу ТЗ стоимость работ — «без материалов». Это не решение заказчика:
  открытый вопрос остаётся в отчёте.

### 3. Версии сметы и пересчёт

- Каждая загрузка — версия: файл, дата, итоги, кто подтвердил и когда. Стоимость объекта
  берётся из последней подтверждённой версии по действующему правилу, целыми рублями
  (округление до рубля в конце, как в файле заказчика).
- Подтверждение новой версии пересчитывает суммы **неподтверждённых** записей объекта.
  Подтверждённые записи и выданные отчёты не меняются: отчёт, в который вошли записи
  объекта, помечается «Требует обновления».
- Распределение стоимости объекта по записям — по минутам (ADR-043), методом наибольшего
  остатка до целого рубля: сумма частей равна стоимости ровно.
- Объект без сметы (котлы): ручной ввод суммы с обязательным комментарием, источник
  «вручную». Это существующий путь `setEstimate`.
- Метки привязки: при загрузке система предлагает объект из справочника по совпадению слов
  названия файла и наименования объекта со словами подписи объекта. Подтверждает человек,
  ручной выбор всегда доступен. Адреса из файла в журнал и в состояние не пишутся:
  хранится только имя файла, которое выбрал сам пользователь в своём браузере.
- Норма против факта: трудозатраты сметы в чел.-ч рядом с фактическими часами бригад
  по объекту на карточке объекта и в отчёте («норма 57,6 чел.-ч, факт 41,5 ч»).

### 4. Недельный график и бригады

- Импорт Excel графика: сопоставление колонок (объект, код, бригада, день) с запоминанием
  в браузере; предпросмотр «добавится / изменится / уйдёт»; применение одной кнопкой
  с отменой 6 секунд. Сравнение — чистая функция `diffSchedule` в домене.
- Бригады: отметка на неделю «работает / в отпуске». Бот бригадира и график показывают
  только работающие бригады.
- Файла недельного графика заказчика в загрузках нет: формат колонок взят обобщённый,
  сопоставление настраивается на экране. Это отмечено в отчёте.

### 5. Режимы проверки

- Три режима: «Проверять все», «Проверять только с замечаниями», «Без проверки, итоговая
  проверка перед отчётом». Режим 3 доступен, только когда точность (доля записей, принятых
  без правки, за последние подтверждённые записи) не ниже порога; порог настраивается,
  по умолчанию 95 %. Пока порог не набран, режим недоступен с объяснением и числами.
- Перед выгрузкой и сдачей отчёта — шаг «Итоговая проверка»: список записей без ручного
  подтверждения и подтверждение одним действием с записью в журнал, кто и когда.
  Сдача отчёта — финансовая операция: шаг обязателен во всех режимах.

  через exceljs, с итогами смет заказчика (А: без НДС 189 158,24, материалы 23 703,01,
  НДС 22 % 41 614,81, всего 230 773,05, кандидат 165 455,23; Б: без НДС 142 174,91,
  материалы 68 706,25, НДС 5 % 7 108,75, всего 149 283,66, трудозатраты 57,644,

- Регрессия: итоги отчёта на демо-данных до и после совпадают до рубля.

  и печатает только итоги. Не входит в CI: файлов заказчика в репозитории нет.

## Открытые вопросы к заказчику

1. Правило состава стоимости работ: какие строки итогов входят.
2. Единый формат сметы: какой из двух форматов будет стандартом и где итоги.
3. Порог автоподтверждения для режима «без проверки».

## Поправки по ходу реализации (26.10.2026)

- Запись без суммы получает долю стоимости при подтверждении, а не при смене версии:
  иначе сумма появлялась бы до решения менеджера. Пересчёт меняет только неподтверждённые
  записи, у которых сумма уже есть.
- Прежнее правило давало каждой подтверждённой записи всю стоимость объекта: объект на два
  дня считался дважды. Ожидание в `gas-ops-undo.test.ts` изменено с 12 000 на 3 273 ₽
  (доля 180 из 660 минут) и добавлен тест «доли в сумме дают стоимость ровно».
- Признаки записи для маршрута режима проверки считаются с долей стоимости: без неё любая
  новая запись была бы «без суммы» и режим «только с замечаниями» не подтверждал бы ничего.
- Разбор сметы, чтение файла и разбор графика — отдельные куски по требованию
  (`estimate-parse`, `estimate-file`, `schedule-import`) со своими порогами в `onDemand`;
  подписи и типы вынесены в `estimate-labels.ts`, который экраны грузят сразу.
- Деталь версии сметы на компьютере — панель справа 420, на телефоне — шторка.
- «Обзор» стартовый у руководителя; менеджер остаётся на очереди проверки: с неё начинается
  показ, и смена стартового экрана сломала бы сценарий показа.
