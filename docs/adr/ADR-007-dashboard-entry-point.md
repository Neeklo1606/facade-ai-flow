# ADR-007. Дашборд как точка входа

- **Статус:** принято
- **Дата:** 2026-09-18
- **Контекст коммита:** `910333c` (EMBER на всех экранах)
- **Задача:** TASK-A1 (блок A аудита функциональной полноты)
- **Отменяет:** [ADR-003](ADR-003-remove-legacy-screens.md), п. 3 — «корень `/` ведёт в реестр объектов»
- **Связано:** [ADR-001](ADR-001-data-layer.md) (слой данных), [ADR-002](ADR-002-state-and-persistence.md)
  (состояния экрана), [docs/domain/glossary.md](../domain/glossary.md), §3 (формулы величин)

## Контекст

ADR-003 удалил старый сводный дашборд: он собирал цифры из двух моделей данных и противоречил
карточке объекта. Пункт 5 того же решения оставил сводку по всем объектам на будущее — «отдельным
решением, когда до неё дойдёт очередь». Это решение и есть.

Аудит функциональной полноты (2026-09-18) показал, зачем она нужна: реестр объектов как точка входа
отвечает на вопрос «что требует внимания» наполовину. Число «Требуют внимания 3 из 5» видно, но
ячейки полосы метрик на реестре не кликабельны, оранжевая метка у строк нигде не объяснена,
привязки ко «сегодня» нет, а просроченные ответы и ожидающие решения приходится искать по объектам.

## Решение

1. **Маршрут `/` — дашборд**, первый пункт сайдбара в группе «Обзор». Редирект `/` → `/projects`
   убран, реестр остаётся вторым пунктом и не меняется.
2. **Новых сущностей нет.** Дашборд читает существующие запросы слоя данных: реестр объектов,
   действующие ревизии документов, карточки объектов (договор и захватки), запросы поставщикам,
   «ждёт решения» и журнал событий. Ни портов, ни таблиц, ни фикстур не добавлено.
3. **Формулы — в слое данных.** `src/domain/dashboard.ts` считает величины, `src/api/dashboard.ts`
   собирает их из запросов; экран получает готовые числа (ADR-001, п. 5). Каждая величина описана
   в глоссарии, §3.
4. **Дельты только там, где есть отметка времени.** «За период» означает «попало в период по
   отметке времени в данных»: ревизия загружена, запрос отправлен, срок ответа прошёл, объект
   начат, договор подписан. Там, где в модели нет события (принятые объёмы отчётов не попадают
   в факт захваток до задачи учёта объёмов, R15), дельта показывает «без изменений», а не
   придуманное число.
5. **Незакрытый объём считается по договорам и захваткам:** остаток объёма
   `Σ (plan_qty − fact_qty)` по захваткам объектов в работе, рубли — оценка этого остатка по
   договорной цене единицы (`contracts.amount / Σ plan_qty`). Оговорка про оценку стоит в самом
   блоке, рядом с числом.
6. **Каждая метрика — ссылка в реестр с фильтром.** Для разделов, которые ведутся по объекту
   (закупки, документация), реестр получает параметр `sectionStatus`: выбор объекта открывает его
   раздел сразу с нужным фильтром.
7. **Правила EMBER на экране:** единственное оранжевое пятно — главное действие «Перейти
   к проверке»; единственный градиент — главная метрика; инсайт-блок на этом экране в песочном
   варианте (`tone="sand"`), чтобы оранжевое пятно осталось одно.

## Рассмотренные варианты

- **Оставить реестр точкой входа и дополнить его.** Отклонено: реестр — это список объектов
  с фильтрами, а вопрос «что делать сегодня» требует другой композиции (очередь решений, поток
  событий, деньги). Смешение двух задач на одном экране и было причиной претензий к старому дашборду.
- **Считать дельты сравнением снимков состояния.** Отклонено: снимков в модели нет, а хранить их
  ради дашборда — новая сущность. Отметки времени дают тот же ответ и не врут.
- **Показывать спарклайны у метрик.** Отклонено: плотного временного ряда ни у одной метрики нет
  (десятки событий на объект за месяц), линия из трёх точек — украшение, а не данные.
- **Свести незакрытый объём к закупке.** Отклонено: цены есть только у позиций с предложениями
  поставщиков, сумма получилась бы неполной и несопоставимой между объектами.

## Последствия

**Плюсы**
- Точка входа отвечает на вопрос «что требует моего внимания сегодня»: шесть метрик с полярностью,
  очередь решений по всем объектам, поток событий с источниками и готовность объектов.
- Все цифры дашборда совпадают с экранами объектов: они считаются из тех же запросов теми же
  определениями (глоссарий, §2–3).
- Переход из метрики ведёт в отфильтрованный список, а не в общий реестр.

**Минусы**
- Точка входа читает данные по всем объектам: реестр и документы грузит loader, остальное —
  запросы по объектам со скелетонами. Рост числа объектов увеличит число запросов; когда объектов
  станет много, сводку нужно будет считать одним запросом (представление в БД).
- Отклонение от графика и рубли незакрытого объёма — оценки по договору, а не бухгалтерские
  величины. Пока в модели нет записей объёмов и КС-2, это единственный честный способ; оговорка
  стоит на экране.
