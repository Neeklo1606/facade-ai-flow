# ADR-085 (server). Рабочий контур на сервере: файлы смет, копии, приглашения, П8

Дата: 23.11.2026. Ветка `night/server`. Связано: ADR-012, ADR-021, ADR-068, ADR-069, ADR-077.

## Контекст

Промпт C, пункты 1–2 и критерий П8 плана критического тестирования: сервис поднимается
на чистом сервере по runbook, люди заказчика входят по своим ссылкам, сметы, время,
проверка, неделя и Excel переживают обновление страницы и перезапуск сервера.

Ночной прогон рабочего контура нашёл:

1. Мастер «Загрузить смету» разбирал файл во вкладке и писал только разобранную версию:
   исходник не хранился. Хранились лишь файлы папки смет (ADR-077).
2. В `docker-compose.yml` не было тома для `ESTIMATE_FILES_DIR`: файлы папки смет жили
   в слое контейнера и пропадали при `up -d --build app`.
3. `.dockerignore` не исключал `.local/`: реальные сметы заказчика попали бы в слой
   образа `build` и `migrate` (`COPY . .`).
4. Схема сервера `review` резала поле `accrual` (решение по разделу, ADR-078): принять
   запись с выбором доли на рабочем контуре было нельзя, ответ 400.
5. На рабочем контуре у живых записей стояли метки «Демо-подрядчик» и «Бот · Демо»:
   порт помечает новые строки источником `mock`, а метки выключались только в кабинете.
6. Экрана приглашений не было: людей заводили только командой `db:gas-user`.
7. Резервной копии файлов не было, копия базы описана одной строкой `pg_dump` без
   проверки восстановления.

## Решение

1. **Исходник мастера в хранилище.** После добавления версии мастер на рабочем контуре
   отправляет файл в `POST /api/gas/estimate-files?keep=<версия>`. Сервер проверяет роль
   (`addEstimateVersion`), формат Excel и размер, кладёт байты в хранилище по хешу и
   связывает опись `gas_estimate_files` с версией (`keepSourceFile`, чистая функция
   домена). Тот же файл, уже лежащий в папке смет, не описывается второй раз. Отказ
   сохранения виден тостом, версия остаётся. В демо байты по-прежнему не хранятся.
   Схема базы не меняется: таблица `gas_estimate_files` и `gas_estimate_versions.file_id`
   уже есть (миграция 20261119100000). Прежние версии без файла остаются без файла,
   данные не теряются; файл можно загрузить в папку смет заново.
2. **Том `estimate-files`** в compose, `ESTIMATE_FILES_DIR=/data/estimate-files` в образе,
   каталог создаётся с владельцем `node`. `PUBLIC_URL=https://$DOMAIN` для ссылок входа.
3. **`.dockerignore`**: `.local`, `data`, `backups`. **`.gitignore`**: `/data/`, `/backups/`.
4. **Схема `review`** принимает `accrual` (доля или ручная сумма с причиной), чужие поля
   по-прежнему 400.
5. **Метки демо** выключены и в сборке `--mode server` (`workingContour`), название
   подрядчика берётся из сборки, а не «Демо-подрядчик».
6. **«Люди и вход»** на экране «Настройка» (`/gas/admin`), только рабочий контур и только
   роль `admin`: добавить человека с ролью (бригадиру нужна бригада из справочника),
   выдать ссылку на 72 часа (новая гасит прежнюю), отозвать доступ (сессии и живые
   ссылки гаснут, вход по коду закрыт, свой доступ отозвать нельзя). Права проверяет
   `/api/gas/access`, а не меню.
7. **Копия и восстановление**: `scripts/gas-backup.sh` (pg_dump custom, архив файлов,
   число строк таблиц, SHA256SUMS, хранение 14 дней) и `scripts/gas-restore-check.sh`
   (восстановление только в отдельную пустую базу, сверка строк и SHA-256 каждого файла
   сметы). В compose сервисы `backup` и `restore-check` профиля `tools`.
8. **Проверка П8**: `scripts/check-server-p8.ts` поднимает чистую базу, миграции,
   `db:gas-init`, `db:gas-user`, сервер сборки `server`, проходит живой путь пилота
   (`e2e/pilot/server-pilot.spec.ts`), перезапускает процесс сервера, проверяет
   `e2e/pilot/server-restart.spec.ts`, что всё на месте, затем копию и восстановление.

## Границы

- Деплой на VPS не выполнен: нет доступа к серверу и домена (владелец).
- Docker-сборка образа не прогнана: демон Docker на машине разработки не запущен.
  Контур проверен без Docker теми же командами, что выполняет образ.
- Ежедневная копия запускается cron хоста; копия вне сервера (второй диск, облако)
  требует решения владельца, куда.
