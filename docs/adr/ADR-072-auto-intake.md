# ADR-072. Автоматический приём: бот Telegram, папка смет, PDF, подключения

Дата: 15.11.2026. Статус: принято.
Основание: запрос владельца. Бригадир в мессенджере выбирает объект и дату, пишет время,
и запись сама попадает в табель. Сметы один раз кладутся в папку Яндекс Диска, из них
вытягивается значение, и его видно в админке. Отчёт руководителю в PDF и Excel в любой момент.
На главной показатели. Помощник знает всё, что записано. Связанные: ADR-061 (табель, 13–14),
ADR-053 (разбор смет), ADR-066 (помощник), ADR-070 (автопилот).

## Что уже было до этого шага

Бот бригадира (машина диалога, MAX-каркас), табель как Google Таблицы (ADR-071), разбор смет
с номерами строк и правилом «без НДС минус материалы», Excel утверждённый и черновик, обзор
с показателями, помощник с данными недели. Не хватало канала Telegram, хранения диалога бота
на сервере, папки смет, PDF и честного списка подключений.

## Решения

1. **Telegram — второй канал того же порта** (`src/adapters/gas-ops/telegram/channel.ts`,
   вебхук `/api/telegram/webhook`). Обработчик событий общий с MAX (`handleInbound`):
   запись создаётся тем же серверным вызовом, что и с экрана, с теми же правами.
   Аккаунты Telegram хранятся с префиксом `tg:`, чтобы не пересечься с MAX в общих таблицах.
   Секрет вебхука проверяется заголовком `X-Telegram-Bot-Api-Secret-Token`.
   Если значение кнопки длиннее 64 байт, в Telegram уходит отпечаток. Обработчик находит
   кнопку по нему среди кнопок текущего шага.
2. **Диалог бота хранится в базе (B6)** (`src/adapters/gas-ops/messenger-db.ts`).
   Используются таблицы миграции T7, новой миграции нет. Повтор доставки отсекает
   `insert … on conflict do nothing`. Диалог живёт 48 часов. Без `DATABASE_URL`, токена
   или секрета вебхук отвечает 501, как раньше.
3. **Папка смет** (`src/ports/estimate-folder.ts`, `src/adapters/gas-ops/yandex-disk.ts`).
   Сервер читает папку `YANDEX_DISK_FOLDER` токеном `YANDEX_DISK_TOKEN`, токен в браузер
   не уходит. Список и файлы отдаются только менеджеру и администратору, проверка на сервере.
   Файл скачивается только из настроенной папки. На экране «Стоимость работ» видно,
   что лежит в папке: «новая», «изменилась», «загружена, версия N».
   Кнопка «Забрать» прогоняет новые файлы через тот же разбор, что и загрузку руками.
   Каждый файл становится версией сметы «ждёт подтверждения» с номерами строк.
   Деньги подтверждает человек, автоматически стоимость не применяется (правило 1).
   В демо работает папка-образец из двух синтетических смет с подписью
   «Демо: Яндекс Диск не подключён».
4. **Отчёт в PDF** (`/gas/print`, `src/domain/gas-ops/print-report.ts`). Лист A4 альбомом
   сохраняется в PDF печатью браузера. На лист попадают только принятые записи, как
   в утверждённом Excel. Сколько записей ещё ждёт проверки, сказано в шапке. Строки берутся
   из табеля, поэтому итоги совпадают с экраном. Отчёт открывается из меню «Выгрузить»
   и с «Обзора». Бригадиру отчёт с суммами недоступен. Отдельную библиотеку PDF не брали:
   кириллица потребовала бы встраивать шрифт, бандл вырос бы на сотни килобайт.
5. **Подключения в «Настройках»** (`/api/gas/connections`, `src/domain/gas-ops/connections.ts`).
   Сервер отдаёт только признаки «задано»: база, Telegram, MAX, Яндекс Диск, модель,
   Google Таблица. Значения ключей не отдаются. Бот без базы показан как «ждёт базу»,
   а не как «подключён».
6. **Помощник видит разбор смет.** Для ролей с деньгами в контекст добавлены файл, версия,
   итоги со строками файла и затраты труда. Ответ может сослаться на «строку 519».

## Не сделано и почему

- Настоящие бот Telegram и Яндекс Диск не проверены: нет токенов. Проверено по описаниям
  API на поддельных ответах. Перед пилотом нужно вызвать `setWebhook` с `secret_token`
  и положить файл в папку.
- Папка не забирается сама по таймеру. Нужен планировщик на сервере (B6), а сейчас
  у сервера нет постоянного процесса. Забор одним нажатием уже убирает ручной поиск файла.
- У сотрудника одна привязка на все каналы: привязка в Telegram снимает привязку в MAX.

- `scripts/check-db-gas.ts`, шаг «канал бота (B6)»: одновременные `claim`, диалог,
  переезд привязки на локальной PostgreSQL.

  Отчёт PDF открывается с «Обзора». Подключения приходят с сервера.
