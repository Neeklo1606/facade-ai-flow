# ADR-056. Учёт времени бригад v1: состав, человеко-часы, закрытие недели

Дата: 30.10.2026. Статус: принято (S4).
Основание: docs/design/GAIKA_SERVICE_V1_PROMPTS.md, разделы 1.2–1.4 и S4; ADR-043, ADR-053
(сметы), ADR-055.

## Task Brief

Цель: модуль 1 «Учёт времени бригад» получает состав и человеко-часы, ключ отправки и канал,
ставки с периодами, ожидание по графику, закрытие недели с версиями v1/v2 и отдельный
интерфейс бригадира, который не получает финансов. Расчёт стоимости по сметам (ADR-053)
и регрессия отчёта до рубля не меняются. Класс T2: демо-данные и порт, без рабочей базы.

Расхождения с документом владельца:

- Интерфейс бригадира лежит по адресу `/gas/brigade`, а `/field/brigade` ведёт туда же.
  Контур данных заказчика (ADR-047) загружается маршрутом `/gas`: вне него пришлось бы
  дублировать загрузчик и оболочку. Интерфейс отдельный: без меню, плавающей панели и сумм.
- «Получено отчётов 46 из 50» считается только по ожиданию. Есть график заказчика — по нему.
  Нет — по демо-назначениям «на сегодня», и экран подписывает источник. Нет ни того ни другого —
  строки нет вовсе, процент не придумывается.
- Прошлой недели в данных нет: на графике «Неделя» сравнение выключено с подписью, переключатель
  недель показывает только недели, которые есть.

## Решение

### 1. Состав и человеко-часы

- `CrewMember`: человек в бригаде с периодом `from`/`to`; `null` — с начала учёта или по сей день.
- Запись получает `headcount` (сколько людей) или `people` (строки людей при «у сотрудников
  разное время»). Человеко-минуты: сумма строк людей или минуты записи × число людей.
- В отчёте заказчика состава нет, только бригадир. У строк выгрузки `headcount: null`,
  человеко-часы по ним не считаются и не приравниваются к часам: экран пишет «Состав не указан»,
  неделя — «по N записям состав не указан».
- Для показа состав дополнен демо-монтажниками (`source: "mock"`, подпись «Демо»): в Бригаде 1
  трое, в остальных по двое. Одна демо-запись Бригады 4 указывает людей больше состава, чтобы
  был виден признак «Состав больше бригады».
- Строки людей задают рамку записи: начало самого раннего, окончание самого позднего, минуты
  записи — самая длинная смена. Распределение стоимости объекта по минутам (ADR-053, 3)
  остаётся по минутам записи, а не по человеко-минутам: регрессия отчёта не меняется.

### 2. Отправка и канал

- `clientKey`: ключ отправки с телефона. Повтор с тем же ключом возвращает ту же запись
  (инвариант 4). Экран бригадира создаёт ключ один раз на черновик формы.
- `channel`: «Форма бригадира», «Бот», «Внёс менеджер», «Выгрузка заказчика». По умолчанию
  по роли: бригадир — форма, остальные — менеджер.
- «Сохранено на телефоне» и «Принято сервером» — разные состояния (инвариант 7). Без сети
  форма кладёт запись в очередь вкладки с ключом, при сети отправляет; повтор не даёт дубля.

### 3. Ставки и стоимость труда

- `Rate` с периодом: на человека или на бригаду; ставка человека важнее. Новая ставка закрывает
  прежнюю накануне своей даты.
- Стоимость труда = человеко-часы × ставка. Нет ставки хоть одному человеку или неизвестен
  состав — `null`, частичная сумма не показывается. Ставок в данных заказчика нет:
  «Ставки не заданы».
- Слов «маржа», «прибыль», «доходность объекта» нет. «Выработка на час» и «на человеко-час»
  с формулой словами в подсказке.

### 4. Бригадир не получает финансов

- `fieldFor(snapshot, brigadeId)` в domain: перечисляет поля явно, без сумм, смет, ставок
  и чужих бригад. Бригадир получает свою бригаду, что бы ни пришло параметром.
- Порт `fieldSnapshot()` отдаёт только её; экран бригадира читает ту же функцию.
  Тест проверяет, что в выборке нет `amountRub`, `rubPerHour`, `estimate`, `revenue` и знака ₽.

### 5. Неделя и её версии

- Причины до закрытия (`closeReasons`):
  - не проверено;
  - на уточнении;
  - подтверждено системой без итоговой проверки;
  - нет записи по ожиданию;
  - пересечение;
  - объект без сметы;
  - состав больше бригады.
- Первые три принять как есть нельзя: неподтверждённое не попадает в итог (инвариант 1).
  Остальные руководитель принимает как есть с обязательной причиной.
- Закрытие фиксирует версию v1: копию подтверждённых записей и итог. Пока версия действует,
  на дни недели нельзя:
  - править запись;
  - принимать решение проверки;
  - отменять решение;
  - вносить новую запись.

  Ошибка `period-closed` (инвариант 3).

- Переоткрытие с причиной помечает версию переоткрытой, но не удаляет её. Файл v1 строится
  из её копии записей. Следующее закрытие даёт v2.
- Закрывают и переоткрывают руководитель и администратор; менеджер видит неделю, но не закрывает.

### 6. Экраны

- Бригадир, «Сегодня» (`/gas/brigade`):
  - сдано за сегодня, «Нужно уточнить: N», кнопка «Добавить время»;
  - форма объект → дата → кто работал → время → перерыв → комментарий;
  - проверка перед отправкой;
  - «Мои записи» с ответом на уточнение.

  Бот остаётся вторым каналом в деморежиме.

- Менеджер, «Проверка»:
  - вкладки «Новые / На уточнении / Принятые / Все»;
  - показатели над очередью;
  - состав и человеко-часы в записи;
  - правка состава с причиной.
- Руководитель, «Неделя» (`/gas/week`):
  - показатели и «До закрытия осталось»;
  - график по дням и доли объектов;
  - таблица по объектам;
  - «Закрыть неделю» и версии.
- Администратор, «Справочники» (`/gas/directory`):
  - состав с периодами и ставки с периодами;
  - профиль выгрузки Excel: столбцы и сверка итога.

  Сметы, график и режим проверки остаются на своих экранах, ссылками отсюда.

- Меню: «Стоимость работ» называется «Сметы»; у руководителя первым идёт «Неделя».

## Последствия

- Версия снимка вкладки 4 → 5: старый снимок без состава и версий не поднимается.
- Порт получает `fieldSnapshot`, `answerClarify`, `closeWeek`, `reopenWeek`, `setRate`,
  `addCrewMember`, `endCrewMember`. Серверная реализация повторит их как HTTP-методы
  с проверкой роли на сервере (ADR-012).
- Признак `over-crew` в домене.
