# ADR-038. Канон демо 18.10

Дата: 18.10.2026. Статус: принято владельцем. Уточняет ADR-037, заменяет раздел 4
`GAIKA_PRODUCT_UX.md` (решение от 17.10.2026). Этап D очереди сборки.

## Контекст

ADR-037 сделал три сценария, но каждый жил отдельно: пример показа, проверка и заявка не были
связаны одним фактом, а сценарий «замечание → задача» оставался в примерах показа без сущности
задачи. Цель этапа D: демо, которое не стыдно дать клиенту. Человек открывает ссылку
с телефона и за 3 минуты проходит три сценария.

По приоритету оснований (`GAIKA_CLAUDE.md`) прямое решение владельца выше документов набора.
Расхождение с решением от 17.10.2026 (снабжение вне демо) названо в ADR-037 и здесь закрепляется.

## Решение

Канон демо: три сценария ADR-037, связанные **одной цепочкой на одном объекте**
(«Северная Корона», корпус 3).

1. **Смена → учёт.** Прораб говорит про смену → расшифровка → разбор → «Верно» → отчёт уходит
   на проверку.
2. **ПТО → документ.** ПТО видит этот же отчёт в «Проверке» → при необходимости правит объём →
   «Принять» → «Скачать сводку смены» и «Скачать черновик ведомости» (xlsx с пометкой «Черновик,
   не исполнительная документация»).
3. **Объект → снабжение.** Прораб говорит о нехватке → заявка на материал → снабжение «Принять»
   или «Отклонить с причиной» → прораб видит статус. Ничего не заказывается автоматически.

Если факт из сценария 1 уже создан в этой вкладке, сценарий 2 берёт именно его. Иначе
подготовленный факт из данных демонстрации.

## Что отложено и почему

Код не удаляется: убирается из демо и навигации флагом `legacy_modules` или из примеров показа.

| Что                                                  | Почему                                                                             | Когда вернётся                                       |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------- |
| «Замечание → задача» (G6)                            | Сущности задачи нет; показывать черновик без жизни после «Верно» нечестно          | После первого платного пилота                        |
| Риски, кроме нехватки материала (G7 полный)          | Нехватка закрывает сценарий 3; остальные виды требуют владельцев и очереди решений | По решению после пилота                              |
| Версии записей и жизненный цикл сводки (G5)          | Нужны пилоту (исправление подтверждённого, снимок выгрузки), не показу             | До первого пилота с реальными данными                |
| Живая модель, живая речь, Telegram, вход по телефону | Ключей и согласованного контура данных нет (правило 7)                             | Порты и места под подключение есть; включение ключом |
| Лендинг (G9)                                         | Сначала демо, на которое лендинг ведёт                                             | После публикации демо                                |

## Чем канон отличается от фундамента

`GAIKA_AI_PROJECT_FOUNDATION.md` (раздел 6) называет снабжение и документы будущими кандидатами,
которые не появляются в backlog без отдельного решения. ADR-037 и этот ADR и есть такое решение,
в минимальном виде: заявка со статусом, а не закупка; черновик ведомости, а не исполнительная
документация.

Инварианты раздела 16 фундамента сверены с ADR-037 (п. 2):

| Инвариант фундамента                                       | В коде                                                    |
| ---------------------------------------------------------- | --------------------------------------------------------- |
| В отчёт не попадает неподтверждённая запись                | Да: сводка берёт только принятые (`shiftSummary`, тест)   |
| Подтверждение без данных и полномочий отклоняется сервером | Да: права в обёртке портов (ADR-012), схема входа приёмки |
| Повтор доставки и подтверждения не увеличивает объём       | Да: ключ отправки (ADR-036), приёмка идемпотентна (тест)  |
| В каждой строке отчёта источник **и версия** записи        | Источник да; **версии нет** — отложено с G5               |
| Исправление создаёт историю и не меняет выданный файл      | **Нет**: снимков выгрузки нет — отложено с G5             |
| Нет доступа к чужим объектам и файлам                      | Да в пределах одной компании демо; изоляции компаний нет  |
| Ошибка AI не теряет сообщение                              | Да: источник сохраняется до разбора (ADR-036)             |
| Разные единицы и виды работ не складываются без правила    | Да: группировка по единице (тест)                         |

Две строки с «нет» — известный долг пилота, а не показа. Демо их не обещает: в интерфейсе нет
слов «версия» и «выпущенная сводка».

## Последствия

- Пример «Замечание» уходит из «Примеров показа»; код примера и разбора остаётся.
- Полоса шагов показа строится на `src/lib/guide` и переключает роли там, где сценарий требует.
- Сценарий 2 сначала ищет отчёт, созданный в этой вкладке сценарием 1.
- Финал показа перечисляет созданное и даёт скачать оба файла.
- Публикация и слияние в main остаются за владельцем (класс T3).
