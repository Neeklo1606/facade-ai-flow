# ADR-051. Заявки, аналитика и превью ссылок

Дата: 23.10.2026. Статус: принято. Основание: docs/launch/01_SPEC.md, разделы 10 и 11; шаг L6.

## Task Brief

Цель: заявка с сайта доходит до владельца или честно ведёт в Telegram; партнёр пересылает
ссылки со своим кодом; ссылка в мессенджере выглядит прилично; аналитика только с согласия.
Меняются: порт заявок и маршрут `/api/leads`, форма, страницы `/case/gas`, `/razbor`, `/kit`,
`/privacy`, порт аналитики, строка согласия, превью. Не меняются приложение, данные, расчёт,
внутренняя телеметрия показа (ADR-010). Класс T2.

## Решение

1. **Порт `LeadSink`** (`src/ports/leads.ts`): `send(lead) → {ok:true} | {ok:false, reason}`.
   Адаптеры в `src/adapters/leads`: `telegram` (Bot API `sendMessage`, `LEADS_TELEGRAM_BOT_TOKEN`,
   `LEADS_TELEGRAM_CHAT_ID`), `webhook` (POST JSON на `LEADS_WEBHOOK_URL`), `none`. Выбор
   на сервере по окружению при запросе: есть токен и чат → telegram, иначе есть адрес → webhook,
   иначе none. Ключи только в окружении хостинга, в репозитории их нет. Тайм-аут 8 секунд.
2. **`POST /api/leads`.** Схема zod с ограничением длин, скрытое поле-ловушка `website`
   (заполнено → 204 без отправки: бот не узнаёт, что пойман). Лимит 5 заявок с IP за час
   в памяти воркера. **Ограничение:** у Cloudflare память у каждого изолята своя и теряется
   при перезапуске, лимит приблизительный. Для старта этого достаточно; при спаме переносим
   счётчик в KV или Durable Object. Адрес берётся из `cf-connecting-ip` (его ставит Cloudflare,
   подделать нельзя), без него из `x-forwarded-for` (node-сервер за прокси). Ответы: 204 принято, 400 неверно, 429 лимит, 501 с телом
   `{"sink":"none"}` приём не подключён, 502 адаптер не доставил.
3. **Журнал хостинга.** Пишется одна строка `{"channel":"lead", at, source, src, sink, ok}`.
   Имя, телефон и компания в журнал не пишутся никогда, в том числе при ошибке адаптера.
4. **Форма** (`LeadForm`, источники `landing`, `razbor`, `demo-final`, `case`): «Отправляю»,
   «Заявка отправлена» только на 204, «Не отправилось» с кнопкой повтора на 400, 429, 502
   и сбое сети, честный переход в Telegram с готовым текстом на 501. В заявку уходят
   источник, код партнёра `src` (из адреса, хранится в sessionStorage на время сессии),
   страница и время. На финалах показа (`/gas` и `/finish`) формы нет, там кнопка «Разобрать
   мои данные» ведёт на `/razbor?from=demo-final`, где та же форма с источником `demo-final`:
   финал на телефоне остаётся одним экраном с одним действием (указание владельца 23.10
   «проще на мобильной»).
5. **Порт `Analytics`** (`src/ports/analytics.ts`): `track(event, params)`. Адаптеры `none`
   и `metrika` (`VITE_METRIKA_ID`). Строка согласия внизу экрана сайта «Используем аналитику,
   чтобы улучшать сайт. Согласиться / Отказаться», решение в localStorage (try/catch).
   До согласия скрипт Метрики не загружается вовсе, события молча отбрасываются. Строка
   не показывается, если `VITE_METRIKA_ID` не задан: спрашивать согласие не на что.
   События 01_SPEC 11.2 вызываются через порт в местах действий.
6. **Превью.** `scripts/og-images.ts` открывает в Playwright страницу `/og/<имя>` (маршрут
   существует только при сборке для разработки, в production отдаёт 404) размером 1200 x 630
   и снимает картинку в `public/og/<имя>.jpg` для `/`, `/demo`, `/case/gas`, `/razbor`.
   Картинки собраны из живых фрагментов лендинга, не нарисованы руками. Теги og и twitter
   на четырёх страницах, `og:url` от `VITE_PUBLIC_URL`. Сайт не за шлюзом, краулеры
   TelegramBot, vkShare и WhatsApp получают 200 и теги.
7. **QR без внешних сервисов**: библиотека `qrcode-generator` (MIT, без зависимостей, около
   20 КБ, грузится только на `/kit`), рисуем в canvas сами. Своя реализация кодировщика заняла бы
   сотни строк без выигрыша. Тест декодирует картинку обратно `jsqr` (только для тестов).
8. **Набор партнёра** `/kit`: код партнёра в поле вверху (localStorage, try/catch), к каждой
   ссылке добавляется `?src=`. Скопировать, Поделиться (Web Share, без него кнопка скрыта),
   QR и «Скачать PNG». Сценарий показа на 90 секунд и ответы из DEMO_SCRIPT и 01_SPEC 9.10.
   noindex всегда, ссылка на `/kit` нигде на сайте не выводится.

## Проверка

`bun run ci`; тесты адаптеров на подменённом fetch (формат Telegram, тайм-аут, ошибка);
тесты маршрута (ловушка, лимит, 501 при none, журнал без персональных данных); e2e формы
при none и при webhook на тестовом сервере; QR декодируется в ту же ссылку; снимки страниц
на 390 и 1440.
