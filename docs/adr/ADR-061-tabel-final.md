# ADR-061. Табель: финальная версия для СЛАВЯНСКГАЗСТРОЙ

Дата: 02.11.2026. Статус: принято (T0).
Основание: docs/design/GAIKA_TABEL_FINAL.md (версия 1.0 от 02.11.2026), разделы 1-6.
Ветка `feature/tabel-final` от `origin/main` 629bd21 («Сервис v1» слит). Новых коммитов Lovable
после 629bd21 нет.

## Task Brief

Цель: зафиксировать решения по учёту времени бригад до реализации T1-T8 и заморозить
соседние модули. Класс T2: документ решения и флаг навигации, данные и порты не меняются.

Порядок приоритета при расхождениях (документ, раздел 0): договор и ТЗ v1.0 → решения Оксаны
и заказчика → GAIKA_TABEL_FINAL.md → прежние ADR и промпты.

Расхождения, которые решает этот ADR:

- Документ называет шрифт «Монохрома» Manrope. По итогу S1 (ADR-055, 30.10.2026) в продукте
  остался Golos Text: в Manrope коды записей вида «Il-12» неразличимы. Сохраняется Golos Text,
  вопрос шрифта владелец может открыть отдельно. Остальной «Монохром» сохраняется без изменений.
- CLAUDE.md требует EMBER, Inter и оранжевый акцент. Как и в ADR-055, действует «Монохром».
- Скриншотов ПТО Онлайн в репозитории и в ~/Downloads нет (docs/design/tabel/refs/ пуст).
  Оболочка T1 строится по словесному описанию раздела 2.2.
- Веб-кабинет менеджера, табель-таблица, помощник и тур не входят в ТЗ v1.0 («отдельная
  веб-админка не включена», D09). В интерфейсе и переписке их называют бонусом развития или
  предметом допсоглашения, обязательством по договору не называют.

## Решение 1. Рамки

Один продукт для одного заказчика: учёт времени бригад. Результат — закрытая неделя
и табель в формате заказчика, совпадающий с их Excel до рубля и минуты.

В рамках ТЗ v1.0: MAX-бот, справочники объектов, бригад и сотрудников, сбор времени, проверка
пересечений и дублей, стоимость работ по смете, минуты и доходность часа, модерация,
синхронизация с облачной таблицей и Excel, сервер.

Снабжение (ADR-057), ПТО (ADR-058) и общий лендинг (ADR-059) заморожены до сдачи заказчику:
код и проверки остаются, из навигации газового контура они уходят (решение 7).

## Решение 4. Экраны (раздел 4)

- Бригадир: «Сегодня», форма «Добавить время» одним экраном, разбор времени фразой
  с переспросом. Занятость — подсказка, пересечение — признак для менеджера, блок только при
  полном совпадении объекта, даты и интервала. Повторный выезд принимается с признаком.
  Канал и ключ отправки у каждой записи.
- «Проверка»: очередь слева, решение справа, после решения следующая запись, «Принять N без
  замечаний» с отменой 6 с.
- Четыре типа сведений о записи не складываются: состояние, ошибка данных, подозрение,
  полнота финансов. Неизвестное — «не рассчитано» с причиной, не ноль.
- «Журнал»: плотная таблица с составом и чел.-ч, настройка колонок.
- «Табель» вместо «Отчёта»: сетка на весь экран под одной панелью инструментов, виды «Формат
  заказчика» и «По людям», статус ячеек цветом вместо переключателей, выделение и копирование
  в TSV, правка ячейки только менеджером через исправление с причиной.
- «Неделя»: «Закрыть неделю» в шапке, «Что мешает закрыть» по типам, версии v1/v2.
- Справочники: объекты, бригады, сотрудники, сметы; мастера импорта графика и сметы.
- Тур «Шаг N из M» вместо показа; «Показать за 3 минуты» на /gas.

## Решение 9. Бригадир T2: ввод времени без «занято»

Task Brief. Цель: бригадир вносит типичную запись за 5 касаний, ничего не «занято»,
«с 13 до 17» читается как 13:00–17:00. Основание: разделы 4.1, 4.2, строки 1-4 и 12
таблицы 2.1. Затронуто:

- domain: `time-input.ts`, `entry-check.ts`, `time-slots.ts`, `bot-dialog.ts`, `calc.ts`, `crew.ts`;
- порт: проверка в `adapters/gas-ops/demo.ts`;
- экраны: `BrigadeToday.tsx`, `BotChat.tsx`;
- e2e бота и бригадира.

Риск: меняется правило записи. Раньше пересечение и второй выезд не принимались, теперь
принимаются с признаком. Откат: коммит T2 отдельный.

Правила:

- **Разбор.** Одна функция `parseTimeInput`:
  - формы «8», «8.20», «820», «8 20», «16.4» → 16:40;
  - «8,5» → 08:30, но с переспросом;
  - диапазоны «8-17», «с 8:30 до 16», «830-1700»;
  - словами — через `parseTimeMessage`.

  Маска поля бота `maskClockDraft` удалена. Окончание раньше начала даёт ответ «Работа через
  полночь?». Такие смены не принимаются, пока Оксана не утвердит правило (ТЗ 7).

- **Занятость.** Одна функция `checkEntry` для формы, бота и порта:
  - полное совпадение (бригада, объект, дата, интервал) — блок с «Открыть существующую запись»;
  - пересечение — признак «Пересечение времени»;
  - тот же объект и день с другим интервалом — признак «Повторный выезд» (новый `repeat-visit`).
    `findDuplicates` теперь группирует только по полному совпадению; записи без рамки смены,
    как и раньше, совпадают по объекту и дню;
  - касание встык не пересечение.
- **Сетки.**
  - Начало — 06:00–20:00 с шагом в час (15 кнопок). Шаг 30 минут дал бы 29 кнопок, а
    половинное время быстрее написать сообщением.
  - Окончание — от начала + 30 мин до 23:00 с шагом 30 минут.
  - Есть «Своё время». Занятое время — подпись на кнопке, кнопка доступна.
- **Диалог бота** — машина состояний `bot-dialog.ts` без React; `BotChat` только рисует её.
  - Шаг времени: «08:00–17:00», «08:00–16:00», сетка начала, «Своё время».
  - Состав (раздел 4.2, шаг 5) не отдельный шаг, а строка сводки с кнопкой «Меньше людей».
    Так путь кнопками остаётся в 6 касаний (J1, J2).
  - Свободный текст на любом шаге разбирается целиком. Набранное время бот переспрашивает:
    «Понял: 13:00–17:00, 4 ч. Верно?».
- **Канал.** Бот пишет `channel: "bot"` и ключ отправки. Значения перечисления в базе
  (`gas_entry_channel`) не меняются до T7: `bot` — это канал MAX, переименование в `max`
  будет вместе с миграцией у Сергея.
- **Форма** `/gas/brigade` — по 4.1:
  - одно поле «Время работы» с расшифровкой и быстрыми кнопками;
  - дата «Сегодня», «Вчера» или до 7 дней назад; всё старше сегодня подписано «внесено позже»;
  - «Отметить людей» передаёт строки людей с одинаковым временем. Сводка тогда пишет «по N ч
    на человека», а не «разное время»;
  - «У людей разное время» — за флагом `VITE_GAS_SPLIT_TIME` до решения D07.
- **Офлайн.** Очередь отправки вынесена в `drainQueue` с тестом:
  - отказ правила убирает запись из очереди с причиной;
  - сбой сети оставляет её до следующей попытки.
- **Отложено.**
  - Признак «внесено позже» для менеджера — в T3 вместе с проверкой; в T2 это метка в форме и сводке.
  - Отдельная вкладка «Уточнения» не сделана: вопросы менеджера стоят первым блоком
    «Сегодня» и в «Моих записях» с полем ответа.

## Решение 10. Проверка и журнал T3

Task Brief. Цель: менеджер начинает «Проверку» со списка, видит у записи четыре отдельных
типа сведений и принимает решение справа, не теряя места в очереди. «Журнал» — плотная
таблица по 4.4. Основание: разделы 4.3, 4.4, 2.3 и строки 7, 8, 11 таблицы 2.1. Затронуто:

- domain: новый `entry-info.ts`, поля `duplicates`, `repeats`, `author`, `objectMinutes` у `EntryView`;
- порт: запрет принять запись с нулём минут (`adapters/gas-ops/demo.ts`);
- экраны: `routes/gas/moderation.tsx`, `routes/gas/entries.tsx`, `review/*`, `EntryDetails.tsx`,
  человеко-часы на «Неделе»;
- e2e проверки и журнала.

Риск: меняются подписи и порядок экрана, на которые опираются e2e. Откат: коммит T3 отдельный.

Правила:

- **Четыре типа.** `entryInfo(view)` возвращает отдельно состояние, ошибки данных, подозрения
  и полноту финансов. `infoCounts` считает записи каждого типа отдельно, сумма счётчиков не
  выводится.
  - Ошибки данных: «Нет состава» (кроме строк отчёта заказчика: там состава нет по формату),
    «Неверный интервал», «Ноль минут».
  - Подозрения: «Возможный дубль», «Пересечение времени», «Повторный выезд», «Внесено позже»,
    «Состав больше бригады», «Высокая доходность».
  - Финансы: «Нет подтверждённой стоимости», «Нет суммы», «Ручная сумма», «Требует согласования»,
    «Объект на несколько дней».
- **Без замечаний** — нет ошибок данных и подозрений. Полнота финансов в это не входит: принять
  запись и подтвердить стоимость объекта — разные действия (2.3, п. 6). Раньше «без замечаний»
  исключало и финансовые метки.
- **Что блокирует.** Принять нельзя только запись с нулём минут: это правило теперь держит порт.
  Остальные замечания исключают запись из «Принять N без замечаний», решение за менеджером.
  Прежний уровень «Блокирует» у пересечения и дубля был неправдой: порт их принимал.
- **Неизвестное не ноль.** `manHours` и `manHoursText`: если состава нет ни у одной записи,
  выводится «не рассчитано» с причиной и ссылкой «Показать записи» в журнал с фильтром.
- **Сумма с расшифровкой.** `costBreakdown` и `costLine`: сумма, источник (смета и версия,
  отчёт заказчика и строка, ручная стоимость), формула словами (доля стоимости объекта по
  минутам), длительность и сумма на час длительности с пометкой, что это не стоимость
  человеко-часа.
- **Подписи.** Главная кнопка — «Принять N без замечаний», в карточке «Принять», «Исправить»,
  «Вернуть на уточнение»; «Отклонить» в «⋮». Группы «Требуют внимания» и «Без замечаний»
  убраны: очередь одним списком, записи с замечаниями выше. Карточки показателей убраны.
- **Шапка.** «Принять N» и фильтры — в месте действий шапки оболочки (T1). Строка счётчиков —
  таблетки статусов и счётчики типов. Так первая строка очереди на 1440 не ниже 200 px.
- **Отложено.**
  - «Исходное сообщение» бригадира в блоке «Данные бригадира»: в записи его нет, нужно поле
    `input_text` и миграция. Делается в T7 с Сергеем. Пока блок показывает автора, канал,
    время отправки, комментарий и ответы на уточнения.
  - Вопрос «Вернуть на уточнение» уходит в «Уточнения» бригадира; в MAX — после подключения (T7).

## Решение 11. Табель и неделя T4

Task Brief. Цель: руководитель и менеджер работают с неделей в одной сетке, как в Google
Таблицах. Над сеткой только панель инструментов. Неделя закрывается кнопкой из шапки.
Основание: разделы 4.5, 4.6, строки 9 и 10 таблицы 2.1. Затронуто:
- domain: новый `tabel.ts` (статус ячейки, выделение, TSV, итоги выделенного, вид «По людям»,
  контрольная сумма версии);
- сервер выгрузки `api/gas-export.ts`: файл из данных недели и версии, а не из строк клиента;
- порт синхронизации с облачной таблицей — заглушка;
- экраны: новый `/gas/tabel`, `/gas/reports` перенаправляет туда; «Неделя» перестроена;
- e2e отчёта и недели.

Риск: старый экран «Отчёт» уходит целиком вместе с его e2e. Откат: коммит T4 отдельный.

Правила:
- **Одна сетка вместо переключателя.** В сетке принятые и ждущие проверки записи. Ячейка
  с непроверенной записью — янтарная, число курсивом. Пустая ячейка там, где по графику
  ждали запись, — красная рамка; день без графика — серая. ✎ — ручная сумма, ⚠ — нет сметы.
  Утверждённая выгрузка берёт только принятые записи.
- **Иерархия** — та же, что в `customerFormatRows`: подразделение → бригада → бригадир →
  объект. Итоги родителей считаются снизу вверх без двойного счёта (инварианты report.ts).
- **Выделение как в таблицах:** ячейка, диапазон (мышь и Shift+стрелки), строка, столбец.
  Ctrl/Cmd+C копирует TSV. Внизу «Сумма / Среднее / Количество» по числам выделенного.
- **Правка.** Одна ячейка может складываться из нескольких записей, поэтому правка идёт
  через окно ячейки (Enter или двойной клик): там исходные записи, «Открыть запись» и для
  менеджера «Исправить» — начало, окончание, перерыв, состав и обязательная причина. Это то
  же исправление порта, что в «Проверке», история пишется. В закрытой неделе правки нет,
  вместо неё «Переоткрыть неделю».
- **«По людям»:** сотрудники × дни, часы из поимённых строк записей. В демо-наборе поимённого
  состава нет, вид включается, когда он появляется (форма бригадира «Отметить людей»).
- **Без внешних библиотек сетки.** Виртуализация строк своя, от 200 строк.
- **Выгрузка.** Клиент отправляет данные недели, сервер сам считает строки доменными
  функциями: «утверждённый» — принятые записи или записи закрытой версии, «черновик» —
  все, кроме отклонённых, с меткой «Черновик» и подсветкой непроверенных строк. В T7 данные
  придут из базы (`createGasDbStore`), а не из тела запроса.
- **Синхронизация с Google / Яндекс** — порт с заглушкой; пункт меню подписан «не подключено»
  и ничего не отправляет. Настоящая реализация в T7.
- **Блоки старого «Отчёта».** Итог недели крупно уходит (он есть в строке «Итого» и в
  «Неделе»). Итоговая проверка (ADR-053) переезжает на «Неделю» в «Что мешает закрыть».
  Сверка с файлом заказчика и «Норма и факт» — под легендой сетки.
- **Бюджет бандла.** После T3 и T4 сумма выросла на 2,7 КБ над порогом (рабочий контур
  869,7 КБ, демонстрация 926,7 КБ), хотя старый «Отчёт» и график «Недели» удалены. Пороги
  подняты по правилу файла: замер плюс 2 % (887 и 945). Самый большой кусок в пороге.
- **«Неделя»:** «Закрыть неделю (N причин)» в шапке, строка счётчиков вместо карточек,
  «Что мешает закрыть» по группам, таблица объектов, версии с файлом и контрольной суммой,
  «Переоткрыть» с причиной. График и доли объектов убраны.

## Решение 12. Справочники и мастера импорта T5

Task Brief. Цель: справочники как в ПТО Онлайн — таблицы с пустыми состояниями
и действиями, один мастер импорта Excel для графика и сметы. Основание: раздел 4.7.
Затронуто:
- domain: новый `import-wizard.ts` (листы, колонки с примером значения, файл как есть, шаблон),
  `estimate-parse.ts` (колонка сумм и строка начала задаются вручную, сверка разделов с НДС
  и без);
- порт: `discardEstimateVersion` (отмена импорта неподтверждённой версии) и `setUserRole`;
- экраны: мастер `components/gas-ops/import`, «Объекты», «Сотрудники», «Настройка»
  (выгрузка, подключения, доступы, журнал действий);
- e2e импорта графика и сметы на синтетических файлах.

Риск: меняется поток загрузки сметы и графика, на него опираются e2e. Откат: коммит T5 отдельный.

Правила:
- **Мастер импорта** — шаги «Файл → Колонки → Проверка → Применить»:
  - выбор листа (по умолчанию первый непустой, для сметы — лучший по разбору);
  - строка начала (угадана, меняется числом);
  - «что в каких колонках» с примером значения из первой строки данных;
  - проверка: зелёная или жёлтая плашка сходимости;
  - «Показать файл как есть» — первые строки листа сеткой;
  - «Скачать шаблон (.xlsx)» — файл собирается в браузере тем же модулем чтения Excel,
    который грузится по требованию;
  - предпросмотр изменений и «Всё верно — применить», отмена 6 секунд.
- **Смета:** форма определяется по содержимому (ADR-053). Колонку сумм и строку начала
  можно поправить. «Цены с НДС / без» выбирает, с каким итогом сверяется сумма разделов:
  «ВСЕГО по смете» или «Итого без НДС». Применение создаёт версию «требует подтверждения»,
  отмена удаляет её, пока её не подтвердили.
- **График:** колонки «Объект, Номер, Бригада, Дата», предпросмотр «добавится / изменится /
  уйдёт» (ADR-053, 4), отмена возвращает прежний график.
- **«Сотрудники»** — таблица по составу бригад:
  - ФИО, должность, бригада, роль в системе, MAX, последняя активность;
  - «Пригласить сотрудника» и «Отправить приглашение»: в демо показывают ссылку и код
    с пометкой, что канал MAX не подключён и ничего не отправлено;
  - «Изменить роль» — для сотрудников со входом;
  - «Деактивировать» закрывает период в составе бригады сегодняшним днём.
  - Телефона в данных нет: колонка показывает «–» с подсказкой. Поле появится с базой в T7.
- **«Настройка»:**
  - «Выгрузка»: профиль Excel заказчика с проверкой обязательных столбцов и предпросмотром
    шапки, выбор Google или Яндекс таблицы — настройка с меткой «не подключено»;
  - «Подключения»: MAX, время напоминаний, облачная таблица — все честно «не подключено»;
  - «Доступы»: матрица ролей и прав;
  - «Журнал действий»: кто, что, когда, было → стало.
- **Пустые состояния** объектов, смет и сотрудников — 2-3 действия: Excel, вручную, шаблон.

  - элемент ищется кадрами анимации не дольше 2 секунд после перехода, затем положение

- **Напоминания** (`src/domain/gas-ops/reminders.ts`): «кому что напомнить на момент T» —
  бригадиру, у которого по графику (или демо-назначениям) нет записи за день после времени
  напоминания, и бригадиру с записью на уточнении; менеджеру сводка дня. Повтор не уходит:

- Время напоминания из «Подключений» (по умолчанию 18:00). В демо отправку запускает
  кнопка «Проверить напоминания сейчас» на момент этого времени: по расписанию её будет
  делать сервер (T7), а прогон проверок не зависит от времени суток.
- Тур при первом входе в сквозных тестах отмечен просмотренным в оснастке: иначе подсказка
  закрывает экраны остальных проверок. Сам первый вход проверяет `gas-tour.spec.ts`.
- На телефоне, когда элемент шага занимает экран (бот), подсказка сжимается в строку внизу:
  полная закрыла бы кнопки ответа. Смена роли туром идёт без тоста, роль подписана у номера шага.

## Решение 14. Готовность к бэкенду и MAX T7

Task Brief: раздел 6 и BACKEND HANDOFF v1.1 (Drive, папка 06). Экраны не меняются: под ними
появляется серверная реализация порта учёта времени, контракты API, порты канала MAX
и черновик миграции. Живой интеграции с MAX нет и не обещается: ключей нет, методы API
не сверены с dev.max.ru.

Расхождения с документами:
- В BACKEND HANDOFF таблицы без префикса (`time_entries`, `max_links`), у нас с префиксом
  `gas_`: модули сервиса v1 живут в одной базе с основным приложением (ADR-060).
- Канал записи в HANDOFF `max/web/manager`, у нас `web/bot/manager/import`: `bot` — бот
  бригадира, в демо симулятор, на сервере MAX. Значение перечисления не меняем.
- `estimates`, `estimate_lines`, `accruals`, `weeks`, `exports`, `organizations`,
  `object_assignments` в базе пока не отдельные таблицы: сметы, назначения и недели лежат
  в `gas_state` и `gas_period_versions` (ADR-060). В OpenAPI они описаны схемами ответа,
  нормализация таблиц — задача B2.

Решения:
- **Порт над хранилищем.** `createGasOpsDemo(store)` читает `store.read()` и пишет
  `store.update(change, base)`, как снабжение и документы. Вкладка — `demoStore`, сервер —
  `createGasDbStore`. Это пункт 1 задач раздела 9.5 BACKEND_HANDOFF.
  - Вкладка тоже отвергает решение по устаревшему снимку, а порты вкладки обёрнуты
    `retrying`. Иначе двойная отправка формы давала две записи с одним номером: дефект нашли
    сквозные тесты.
- **Серверные функции** (`src/api/gas-ops-server.ts`): таблица доступа «метод порта → роли»
  на каждый метод, вызов порта над хранилищем от имени пользователя сессии, ответ через
  выборку по роли. Бригадиру не уходят суммы, сметы, ставки, правила стоимости, закрытые
  версии и чужие записи. Без `DATABASE_URL` вызов отвечает «рабочая база не подключена».
  `useGasOps` выбирает реализацию по `VITE_DATA_SOURCE`.
- **Контракты и OpenAPI.** Строки таблиц уже описаны zod в `src/contracts/gas.ts`. Входы
  действий и ответы API — в `src/contracts/gas-api.ts`; `docs/api/openapi.yaml` собирается
  из них скриптом, тест держит файл равным выводу.
- **MAX.** Порт `GasInboundChannel` (нормализованное событие: пользователь, чат, вид,
  данные, внешний id) и `OutboundMessenger` (отправка и правка). Демо-реализация и каркас
  MAX за `MAX_BOT_TOKEN`; методы MAX помечены «сверить с dev.max.ru». Обработчик событий
  ведёт ту же машину диалога T2 (`bot-dialog.ts`). Привязка сотрудника по одноразовому
  коду и идемпотентность по внешнему id — правила domain с тестами. `/api/max/webhook`
  отвечает 501, пока канал не настроен.
- **Выгрузка на сервере из хранилища:** по неделе и версии, только для ролей с деньгами.
- **Миграция T7 отдельным файлом:** новые таблицы `gas_max_links`, `gas_messenger_sessions`,
  `gas_inbound_events`, `gas_notifications`, `gas_schedule_items` и поля записи `flags`,
  `repeat_visit`. Миграция v1 не переписывается.
