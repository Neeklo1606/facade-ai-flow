# ADR-080: путь «смета → карточки → бригады → табель»

Статус: принято. 21.11.2026. Запрос владельца: «загрузить смету, вытащить нужные данные, создать
из них карточки, занести данные в таблицу учёта времени» одним сценарием. Опирается на ADR-077
(разбор смет), ADR-078 (разделы, назначения, начисление), ADR-071 (табель на телефоне).

## Что было

Каждый шаг уже работал, но жил на своём экране: смета в «Папке смет», объект и назначения на
странице объекта, часы в табеле. Человек сам искал, куда идти дальше. Разбор показывал «Читаю
файлы и ищу объекты…» и строку статуса. Табель показывал адрес, но не раздел сметы, хотя записи
с ADR-078 знают раздел.

## Решение

1. **Один вход «Загрузить смету»** на «Обзоре» и в «Объектах». Кнопку видят менеджер,
   администратор и руководитель (`canManageEstimates`). Права на загрузку по-прежнему проверяет
   сервер (ADR-077, 8). Мастер берёт один файл: путь ведёт к одному объекту. Пакетная загрузка
   осталась в «Папке смет».
2. **Итоги разбора по шагам** (`intakeChecks`, `src/domain/gas-ops/estimate-flow.ts`). Это отчёт
   о найденном, а не анимация ожидания (правило 3): шапка (сколько полей из шести), разделы
   и сходимость с итогом без НДС, отделены ли материалы, есть ли нормативные чел.-ч, найден ли
   объект и по какому признаку. Неполное помечено жёлтым и объясняет следствие («остальные
   начисляются вручную»).
3. **Карточки сметы** те же, что в «Папке смет»: шапка со строками файла, объект, разделы
   с суммами и опрессовкой, «Сверить с файлом». После «Создать объект» или «Прикрепить» мастер
   ведёт на страницу объекта. Деньги объекта по-прежнему решает человек (ADR-077, 6).
4. **Полоса пути на странице объекта** (`objectPath`): Смета → Стоимость → Бригады → Часы →
   Начисление. Шаг пройден по данным: разделы есть; смета подтверждена; на каждый раздел
   назначена бригада; есть принятые записи; есть начисление. У текущего шага одно действие:
   загрузить смету, подтвердить стоимость, назначить бригады, проверить записи. «Табель объекта»
   открывает табель с поиском по объекту (`/gas/tabel?q=`).
5. **Разделы в табеле.** Под адресом идут строки разделов по `sectionKey` записей в порядке
   сметы, записи без раздела строкой «Без раздела». Строка раздела справочная, как опрессовка:
   сумма разделов равна адресу, итоги групп не меняются, итог выделенного не считает раздел
   вместе с его адресом, пустой день раздела не пропуск. Выгрузка заказчику (`customerFormatRows`
   без `sections`) прежняя: формат его файла не меняется. Фильтры и поиск сохраняют разделы под
   найденным адресом, поиск находит и название раздела.
