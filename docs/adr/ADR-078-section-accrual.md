# ADR-078: назначения разделов, доля выполнения и начисление

Статус: принято. 20.11.2026. Промпт B брифа «ГАЙКА · СЛАВЯНСКГАЗСТРОЙ: три промпта до рабочего сервиса».
Опирается на ADR-077 (разделы объекта из сметы).

## Контекст

До B стоимость работ объекта делилась между всеми записями объекта по минутам (ADR-053, 3). Это
съедает всю смету первой же неделей и не знает, что разные разделы делают разные бригады. Распределение
по разделам было только демо-макетом в браузере (`demo-allocation`, ADR-075) и в отчёт не шло.

## Решение

1. **Назначение** раздел × бригада × период (`gas_section_assignments`). Ставит менеджер в карточке
   объекта. Повтор того же раздела той же бригаде на пересекающийся период — отказ. В назначении лежит
   подпись раздела: бригадир видит её без сумм раздела.
2. **Запись знает раздел** (`gas_time_entries.section_key`). У бригадира раздел из назначений: один
   подставляется сам, из нескольких выбирают, чужой — отказ порта. Менеджер может указать любой раздел
   сметы объекта. Объект с назначенным разделом доступен бригадиру в форме.
3. **Вопрос бригадиру** после отправки: «Работы по разделу на объекте закончены?» Да / Нет, можно
   пропустить (`section_done`, null — пропущен). Ответ «Да» поднимает предложение до 100 %, но
   завершает раздел только Оксана.
4. **Предложение доли** = подтверждённые чел.-ч по разделу / нормативные т/з раздела. Чел.-ч: строки
   людей, иначе состав × минуты, иначе минуты записи. Не выше 90 %, пока раздел не завершён; не ниже
   текущей доли. Нет норматива — предложения нет.
5. **Подтверждение.** Оксана видит «предложено 45 % (по нормативу) · было 20 %», сумму и остаток.
   Принимает как есть, вводит своё число или ставит «Раздел завершён» (100 %). Сумма пересчитывается
   на экране сразу тем же доменным расчётом, что у порта. Без норматива — ручное начисление с
   обязательной причиной, не больше остатка. Пакетное принятие берёт предложенные доли.
6. **Начисление шага** = цель при новой доле минус уже начисленное по разделу; цель при 100 % — ровно
   стоимость работ раздела, иначе `floor(стоимость × доля)`. Шаг не отрицательный и не больше
   остатка, поэтому сумма по разделу никогда не больше стоимости, а при 100 % равна ей до рубля.
   Снижение доли ничего не забирает. Пакет записей делит шаг по минутам наибольшим остатком.
7. **История доли** (`gas_section_progress`): было, стало, вид шага, записи, начислено, причина, кто,
   когда. Отмена решения тостом убирает шаг, только если он последний по разделу.
8. **Опрессовка.** Начисление записи делится на СМР и опрессовку: раздел испытаний целиком —
   опрессовка, иначе по доле опрессовки в стоимости работ раздела (`pressure_kopecks` из ADR-077).
   В отчёте строка «в т. ч. опрессовка» под адресом справочная, в итоги не складывается.
   В листе «Записи» Excel — раздел, СМР, опрессовка, доля.
9. **Закрытая неделя не меняется**: подтверждать в ней нельзя (как раньше), а доля и остаток всегда
   считаются от уже начисленного, поэтому разница уходит в следующую неделю.
10. **Режим «по времени»** (`reviewSettings.accrualMode = "time"`) оставляет прежний расчёт по
   минутам всей сметы. По умолчанию для заказчика — по доле. Записи без раздела (выгрузка заказчика,
   ручной ввод) считаются по-прежнему.
11. **Деньги решает человек**: автопилот проверки запись с разделом не подтверждает, она ждёт Оксану.
12. **Права на сервере.** Назначения и режим — менеджер и администратор; ответ «закончены» — роли
   учёта времени. Бригадир не получает `accrual`, сумм, разделов объекта и истории доли ни на
   экране, ни из API; назначения — только своей бригады.
13. **Демо-макет удалён.** `demo-allocation`, `AllocationPreview` и проект начислений в браузере
   убраны; на странице показа те же разделы, что в рабочем контуре. Проверки макета (40 % + 35 %
   оставляют 25 %, рубли не теряются, 100,001 % — отказ) перенесены в тесты модели доли.

## Проверка

- `tests/domain/gas-ops-section-accrual.test.ts`: правила и 1000 случайных последовательностей записей
  и долей — начислено ≥ 0, ≤ стоимости, при 100 % ровно стоимость.
- `tests/negative/gas-section-accrual-flow.test.ts`: через порт и серверную проверку прав.
- `bun scripts/check-section-accrual-db.ts` на PostgreSQL: смета → объект → назначение → время →
  доля → Excel только с подтверждённым → неделя закрыта → новое хранилище читает то же.
- `e2e/gas-demo-workspace.spec.ts`: назначение раздела, сохранение после перезагрузки, раздел в форме.

## Открытые вопросы к Оксане

- Согласна ли с правилом доли и порогом 90 %.
- Опрессовка внутри раздела: доля по стоимости работ раздела (сейчас) или отдельной долей выполнения.
- Кто назначает бригады на разделы и откуда график: из ГАЙКИ или их Excel.
- Нужен ли состав бригады в каждой записи: без него чел.-ч = часы записи, предложение занижено.
- Бот: выбор раздела в диалоге не сделан; при нескольких разделах бот получает отказ с текстом,
  бригадир отправляет через форму.
