# ADR-075. Демонстрационный рабочий процесс на данных пользователя

Дата: 17.11.2026. Статус: принято в рамках фронтенд-макета.

Используем существующие страницы и единый снимок demo. Новый старт показа не сбрасывает
данные. Назначение вручную использует прежний порт applySchedule, сохраняя прежние строки.
До первой записи назначенные бригады и объекты видны в карточках.

Редактирование объекта доступно только в demo менеджеру/администратору, меняет общий снимок
и пишет журнал, обновляет подписи графика. Это не новый серверный endpoint. Рабочий контур
не показывает неподключённое редактирование и не сообщает фиктивного успеха.

Распределение по разделам/долям — отдельный подписанный проект, привязанный к версии сметы,
изолированный по контуру и сохранённый в браузере. Материалы раздела задаёт человек, поскольку
парсер не даёт достоверной разбивки материалов по разделам. Проект проверяет доли и остаток,
но не меняет прежние начисления по минутам, подтверждения и утверждённую выгрузку.

Внешние каналы и новая схема начислений — handoff backend после утверждения примеров.

Экран проекта начислений загружается только по явной кнопке. Для отдельного ленивого куска
AllocationPreview установлен бюджет 8 КБ gzip, по существующему механизму onDemand.
Общий бюджет и предел крупнейшего стартового куска не повышаются. Экспорт проекта
повторно использует уже имеющуюся XLSX-библиотеку; ExcelJS дополнительно в браузер не включается.
