# ADR-003. Удаление старого дашборда, AI-агента и глобальных экранов

- **Статус:** принято
- **Дата:** 2026-09-16
- **Контекст коммита:** `ef7a93f`
- **Решает дефекты:** D1 (две модели данных) для удаляемой части; блокеры демонстрации 3, 7, 8, 10
- **Связано:** [ADR-001](ADR-001-data-layer.md), [ARCHITECTURE.md](../../ARCHITECTURE.md), [TASKS.md](../../TASKS.md)
- **Уточнено:** [ADR-006](ADR-006-agent-on-unified-model.md) — ассистент возвращён на единой модели (п. 5);
  [ADR-007](ADR-007-dashboard-entry-point.md) — сводка по всем объектам возвращена дашбордом, п. 3 отменён

## Контекст

После перестройки продукта вокруг объекта в коде остались экраны предыдущей итерации. Аудит `ef7a93f` показал:

- **Старый дашборд `/`** дублирует карточку объекта и собирает цифры из двух моделей сразу: незакрытый
  объём — из `repository`, объекты, риски и задачи — из старых моков. По «Северной Короне» он показывает
  договор СИ-2026/041, 47,2 млн и 62 %, а карточка объекта — ДСК-2026/008, 95,4 млн и 43,4 %.
- **AI-агент** (`components/agent/AgentDock`, `lib/agent-engine.ts`, `mock/agents`) отвечает по старой
  модели данных и противоречит экранам, рядом с которыми открывается.
- **Глобальные экраны** `/documents`, `/requests`, `/quotes`, `/suppliers`, `/deliveries`, `/inbox`,
  `/verification` читают моки напрямую, не видят действий пользователя (созданный запрос отсутствует
  в `/requests`), не имеют ни одного из восьми состояний, а на четырёх из них главные кнопки без обработчика.
  Их функции уже покрыты экранами объекта: документация, извлечение, материалы, закупки, сравнение,
  отчёты с площадки, история.

Держать эти экраны в продукте до переноса на единую модель значит показывать клиенту противоречивые цифры.

## Решение

1. **Удаляем из продукта** вместе с маршрутами, пунктами меню и ссылками:
   старый дашборд `/`, AI-агента, экраны `/documents`, `/requests`, `/quotes`, `/suppliers`,
   `/deliveries`, `/inbox`, `/verification`.
2. **Удаляем код, который служил только им:** `AgentDock`, `agent-engine`, `mock/agents`,
   `VerificationPanel`, `OriginalSourceDrawer`, `ProvenanceCanvas`, индикатор «в работе» в шапке
   (читал старые события).
3. ~~**Корень `/` ведёт в реестр объектов** `/projects`.~~ Отменено [ADR-007](ADR-007-dashboard-entry-point.md):
   корень — дашборд по всем объектам на единой модели.
4. **Разделы, которые ведутся по объекту** (документация, материалы, закупки, поставщики, отчёты,
   история), без выбранного объекта открывают реестр объектов с просьбой выбрать объект.
   Отдельные страницы-выборщики (`/materials`, `/field-reports`, `/audit`) удаляются: реестр
   и так решает эту задачу.
5. **Функциональность возвращается позже и только на единой модели** (ADR-001): сводка по всем
   объектам, агент, входящий поток. Для каждой — отдельное решение, когда до неё дойдёт очередь.
   Код удалённых экранов не переносится, он остаётся в истории git до коммита `ef7a93f`.

## Рассмотренные варианты

- **Скрыть экраны из меню, оставив маршруты.** Отклонено: противоречивые цифры остаются доступны
  по прямой ссылке и из поиска, а код продолжает держать старую модель данных в сборке.
- **Перевести экраны на новую модель сейчас.** Отклонено: их функции уже есть на экранах объекта,
  а перевод съел бы неделю до показа клиенту.

## Последствия

**Плюсы**

- В продукте не остаётся ни одного экрана, который показывает цифры иначе, чем карточка объекта.
- Исчезают все кнопки без обработчика, найденные аудитом на старых экранах.
- Задача P1-6 сжимается: из девяти файлов на старой модели остаются только `app-context` и выбор
  текущего пользователя.

**Минусы**

- Пропадает сводка по всем объектам сразу. Частично её заменяет реестр объектов с метками внимания.
- Пропадает агент. Поиск по системе (⌘K) остаётся.
- Пропадает единая лента входящих из Telegram и почты: отчёты видны в разделе «Отчёты с площадки»
  объекта, письма поставщиков — в сравнении предложений.
