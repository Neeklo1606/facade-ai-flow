# ADR-055. Сервис v1: три модуля и интерфейс «Монохром»

Дата: 29.10.2026. Статус: принято (S0).
Основание: docs/design/GAIKA_SERVICE_V1_PROMPTS.md (версия 1.0 от 25.10.2026), разделы 1 и 2;
аудит docs/design/service-v1/audit.md.

## Task Brief

Цель: зафиксировать продуктовые решения и интерфейс Сервиса v1 до реализации S1-S8.
Класс T2: документ решения, кода не меняет. Ветка `feature/service-v1` от `feature/graphite`
с влитым `main`.

Расхождения, которые решает этот ADR:
- CLAUDE.md требует EMBER, Inter и один оранжевый акцент; ADR-052 перевёл продукт на «Графит»
  и Golos Text. Документ владельца вводит «Монохром»: цвет только в данных, оранжевый только
  в знаке лендинга и в записи голоса. Действует этот ADR, CLAUDE.md в части дизайн-системы
  устарел.
- Номер ADR-053 занят дважды: `ADR-053-estimates-and-work-cost.md` (сметы, graphite)
  и `ADR-053-premium-landing.md` (лендинг, Lovable в main). Файлы не переименовываются,
  чтобы не ломать синхронизацию Lovable. В этом и следующих ADR «ADR-053» означает сметы,
  лендинг называется «ADR-053 (лендинг)».
- Документ ссылается на ADR-054, его в репозитории нет. Раскладку и цвет до этого ADR
  задавали ADR-045 и ADR-052, изменения записаны к ним.
- GAIKA_DESIGN_SYSTEM_V4.md и GAIKA_PREMIUM_PASS.md во входных файлах нет. Документ
  владельца заменяет PREMIUM_PASS и сам задаёт токены; пастели V4 берутся из токенов
  данных ADR-052, который опирался на V4.
- Скриншотов референсов нет. Раскладка строится по словесному описанию раздела 2.1.

## Решение 1. Продукт

ГАЙКА: помощник подрядчика. Данные с объекта превращаются в проверенные записи, отчёты
и документы. Три модуля одной системы:

| Модуль | Пользователи | Результат |
|---|---|---|
| 1. Учёт времени бригад (главный) | бригадир, менеджер, руководитель, администратор | закрытая неделя и Excel в формате заказчика |
| 2. Снабжение | прораб, снабженец, руководитель | заявка → предложения → заказ → приёмка |
| 3. Исполнительная документация (ПТО) | ПТО, прораб, руководитель | черновики АОСР, реестр ИД, записи журнала из подтверждённых данных |

Связи: принятая приёмка с сертификатом попадает в материалы актов; подтверждённые объёмы
дают основание актов; материалы разобранной сметы дают лимит заявок.

### Показатели модуля 1

Время и выработка разделены:

| Показатель | Как считается | Кто видит |
|---|---|---|
| Часы записи | окончание − начало − перерыв, от минут | все, кроме бригадира в чужих записях |
| Состав | число людей в записи, по умолчанию из состава бригады на дату | бригадир вводит, менеджер проверяет |
| Человеко-часы | сумма часов каждого человека; при «разное время» по строкам людей | все |
| Начислено по смете | ADR-053: подтверждённая стоимость объекта по минутам | менеджер, руководитель, администратор |
| Выработка на час бригады | начислено / часы записи (формула Excel заказчика) | менеджер, руководитель |
| Выработка на человеко-час | начислено / человеко-часы | менеджер, руководитель |
| Стоимость труда | человеко-часы × ставка с периодом; без ставок скрыто | руководитель, администратор |

Слова «маржа», «прибыль», «доходность объекта» не используются. Название модуля в интерфейсе
«Учёт времени бригад», отчёт заказчика сохраняет его название «Выработка». Признак
`high-rate` с подписью «Аномальная доходность» переименовывается на S4.

### Роли и стартовые экраны

| Роль | Старт | Поверхность |
|---|---|---|
| Бригадир | «Сегодня» бригадира | телефон, отдельный интерфейс; бот MAX только в деморежиме |
| Менеджер проверки | «Проверка» | компьютер и телефон |
| Руководитель | «Неделя» | компьютер и телефон |
| Администратор, сметчик | «Справочники» | компьютер |
| Прораб | «Сегодня» прораба | телефон |
| Снабженец | «Заявки» | компьютер и телефон |
| ПТО | «Документы» | компьютер |

Сейчас роли газа (4) и FieldOps (7) живут в двух моделях (аудит, раздел 0). На S2 меню
и поиск строятся по одной таблице ролей Сервиса v1; доменные роли не сливаются до S8.

### Инварианты (проверяются тестами)

1. Неподтверждённое не попадает в итог и финальную выгрузку. Черновая выгрузка помечена
   «Черновик», непроверенные строки выделены.
2. Исправление подтверждённого требует причины и создаёт новую версию. История не редактируется.
3. Закрытый период (неделя, реестр ИД) не меняется: переоткрытие с причиной создаёт v2.
4. Повтор отправки с тем же ключом не создаёт дубль.
5. Права проверяются в серверных функциях. Финансы и чужие объекты роль не получает из API.
6. AI только предлагает поля черновика. Подтверждает человек, считает код.
7. Офлайн: «Сохранено на телефоне» и «Принято сервером» не путаются.
8. Никаких чисел вне данных. Нет данных: честная метка.
9. Документы ИД, заказ поставщику и подписи система не выполняет. Только черновики и статусы,
   которые ставит человек.

## Решение 2. Интерфейс «Монохром»

### Каркас компьютера (от 1024)

- Верхняя строка 72 без фона: знак 44 (чёрная плитка, белая «г») и название компании;
  по центру меню-таблетка по роли (56, пункты 40, активный чёрный, индикатор переезжает
  за 220 мс); справа колокольчик и аватар кругами 48.
- Плавающая панель слева: капсула 64, радиус 32, по центру высоты. Поиск, модули со счётчиком,
  настройки, справка, ассистент, тема. Подсказка названия при наведении и фокусе.
- Заголовок экрана 44/48 и статус-плашка справа («● 6 ждут проверки»).
- Строка управления: сегменты периода и фильтра слева, «Сравнить с прошлым периодом»
  и «Выгрузить Excel» справа.
- Контент до 1440, отступ 120 слева от панели, сетка 12 колонок, промежуток 20.
- На 1024-1279 последние пункты меню уходят в «Ещё».

Меню по ролям:

| Роль | Пункты |
|---|---|
| Менеджер | Проверка N · Журнал · Неделя · Объекты · Бригады · Сметы |
| Руководитель | Неделя · Проверка N · Отчёты · Снабжение · Документы · Объекты |
| Администратор | Справочники · Сметы · График · Ставки · Выгрузка · Доступы |
| Снабженец | Заявки N · Поставщики · Поставки · Объекты |
| ПТО | Документы N · Реестр · Журнал работ · Материалы · Участники |
| Прораб, бригадир | компьютерного меню нет |

### Телефон (до 767)

Шапка 56, нижняя панель 64 + safe-area с 4 пунктами роли и «Ещё», активный пункт чёрной
таблеткой. У прораба по центру голос 56, при записи оранжевый. Плавающей панели нет.
Карточки на всю ширину, поле 16, радиус 20. Показатели прокручиваются вбок с прилипанием.
Таблицы становятся строками от 64, деталь шторкой 92 %. Касание от 44, полевые 52.

### Карточки и графики

Карточка белая, радиус 24, отступ 28, двойная мягкая тень, без рамки (в тёмной теме рамка
`line`). Карточка показателя: подпись, значение 36/40, изменение меткой со стрелкой,
спарклайн 1,5 px. Одна инверсная карточка на экран для главного показателя. График «по
времени»: текущий период линией ink 2 px, прошлый пунктиром ink-3, отсутствующая точка
не рисуется нулём. Блок «доли»: два процента, полоса 10, список с суммами.

### Цвет

Светлая тема основная: canvas #efefed, card #ffffff, panel-2 #f5f5f3, panel-3 #e9e9e6,
ink #111113, ink-2 #55555c, ink-3 #66666d; up, down, warn, info мягкими парами.
Тёмная тема по той же логике: canvas #0e0e10, card #18181b, ink #ededf0. Цвет данных только
в графиках с несколькими сериями и метках статуса, пастели ADR-052, фон метки 16 %.
Оранжевый только в знаке на лендинге и в записи голоса. Все пары проходят `check-contrast`
(текст 4,5:1, значки и границы 3:1); значение, которое не проходит, правится по светлоте.

Правки по светлоте на S1 (оттенок тот же):

| Токен | Документ | В styles.css | Почему |
|---|---|---|---|
| ink-3, тёмная | #8b8b94 | #95959e | 4,11:1 на panel-3, стало 4,68:1 |
| up, светлая | #1f8f4e | #187640 | 3,6-4,1:1 на холсте, карточке и своей плашке, стало от 5,0:1 |
| down, светлая | #c43d3d | #b83636 | 4,42:1 на своей плашке и 4,47:1 на холсте, стало от 5,0:1 |

Значений тёмной темы для up, down, warn, info в документе нет: подобраны светлые тона
тех же оттенков, все от 4,5:1. warn и info документа введены как `--caution` и `--note`,
прежние `--warn` и `--info` стали их псевдонимами. Действие (`--accent`) стало инверсной
заливкой (`--inverse`), оранжевый вынесен в `--record`; `check:typography` падает, если
`--record` или классы `*-record` появились вне записи голоса и знака лендинга.

### Шрифт и плотность

Две плотности вместо одной шкалы:

| Стиль | Компьютер | Телефон |
|---|---|---|
| Заголовок экрана | 44/48 | 30/36 |
| Показатель | 36/40 | 28/32 |
| Заголовок карточки | 18/24, 600 | 17/22 |
| Текст | 15/22 | 16/24 |
| Подписи | 14/20 | 14/20 |
| Мелкие | 13/18 | 13/18 |

Шрифт по документу владельца Manrope своей копией woff2. На S1 он проходит те же три
проверки, что в ADR-052: цифры одной ширины (tnum), веса 400-700 с кириллицей, различимость
строчной l и прописной I в кодах записей. Если tnum нет, документ называет Onest, но Onest
не прошёл проверку l/I в ADR-052. Тогда остаётся Golos Text.

**Итог S1 (30.10.2026): остаётся Golos Text.** Manrope 5.3.0 (`@fontsource/manrope`, OFL)
проверен отрисовкой в Chromium, кегль 200 px:

| Проверка | Manrope | Golos Text |
|---|---|---|
| Табличные цифры (`tnum`) | есть, «1111» и «0000» по 49,6 px | есть, по 49,6 px |
| Строчная l и прописная I | одинаковые палочки: ширина 15 и 15 px, высота 148 и 145, ширина штриха постоянна у обеих | у l хвост (ширина 40, штрих меняется), I прямая 19 |

Коды записей вида «Il-12» в Manrope неразличимы, поэтому он не принят; Onest отклонён
в ADR-052 по той же причине. Файлы шрифта не менялись. Две плотности введены токенами
`--t-*` и утилитами `type-screen`, `type-kpi`, `type-card`, `type-text`, `type-label`,
`type-small`.

### Движение

Появление карточек один раз (240 мс, сдвиг 8, шаг 40 мс), счёт чисел при первом показе
(600 мс), линии рисуются за 700 мс, индикатор меню 220 мс, наведение 160 мс, шторки 260 мс.
Только CSS и Web Animations. При prefers-reduced-motion только прозрачность. Анимации
не ухудшают CLS и первый экран.

### Поиск

Командная палитра на cmdk по ⌘K / Ctrl K, иконке панели и шапки. Ищет по данным роли через
порты с учётом прав: записи, объекты, бригады, сметы, заявки, поставщики, документы, люди;
плюс действия. Без учёта регистра и «ё/е», по началу слов и номерам, ответ до 100 мс.

### Решения S2 (оболочка, поиск, темы)

- **Планшет 768-1023** в документе не описан. Принята раскладка телефона: шапка 56 и нижняя
  панель 64. Меню-таблетка из шести пунктов на 768 не помещается, а левая панель
  «Графита» отменена. Верхняя строка и капсула — с 1024.
- **Меню роли** строится только из существующих экранов. Пункты 2.4, которых ещё нет
  («Ставки», «График», «Выгрузка», «Доступы», «Реестр», «Журнал работ», «Участники»,
  «Поставщики»), появятся вместе с экранами в S4-S6. Названия пунктов совпадают
  с заголовками экранов («Отчёт», «Стоимость работ»); переименование в «Неделя» и «Сметы»
  — вместе с экранами S4, чтобы меню, шапка и вкладка браузера не расходились.
- **Остальные разделы роли** (раньше были в левой панели) лежат в «Ещё» меню-таблетки
  группами; граница договора газового заказчика подписана у группы «Развитие».
- **Аватар роли на телефоне** остаётся в шапке рядом с поиском и колокольчиком: смена роли
  — основа показа, а бригадир переключает роль из шапки бота.
- **Капсула ГАЙКИ:** поиск, модули, настройки (сброс демо или выход), справка по экрану,
  тема. Ассистента в капсуле нет: экран ассистента за флагом прежних модулей (ADR-038),
  пункт появится, когда ассистент вернётся.
- **Поиск:** индекс строит контур из своих портов, права режет `lib/search` (бригадир
  не находит сумм, чужих записей, смет, людей и бригад). Действия палитры — только
  работающие («Внести время», «Выгрузить Excel», «Сменить тему»); «Закрыть неделю»,
  «Новая заявка», «Сформировать АОСР» придут со своими экранами. Палитра контура газа
  новая; палитра ГАЙКИ пока прежняя (объекты, документы, запросы, поставщики) и переходит
  на `lib/search` вместе с экранами S5-S6.
- **Тема:** светлая по умолчанию вместо «как в системе» (ADR-044).
- **Онбординг:** строки «Как работать с экраном» заменены подсказкой первого визита
  с кнопкой «Понятно»; шаги экрана и клавиши — в «?» плавающей панели.
- **Показ:** панель «Что происходит в системе» на экране бота видна только во время показа.
  Рамка телефона и подпись «Так будет выглядеть бот в MAX. Канал не подключён» остаются:
  без них менеджер не может ввести время в демо, а подпись — требование честности (правило 3).

## Последствия

- S1-S3 меняют токены, шрифт, оболочку и компоненты для всех контуров. Прежние имена токенов
  остаются псевдонимами, чтобы экраны не ломались до перевода.
- S4 расширяет модель газа: состав с периодами, люди в записи, ключ отправки, канал, ставки,
  версии недели. Нужны серверные функции с проверкой прав: сейчас демо-адаптер газа отдаёт
  браузеру весь снимок, включая суммы (аудит, инвариант 5).
- S5 соединяет заявку с площадки (`material_requests`) и запрос цены (`supply_requests`)
  в одну цепочку; заявка получает несколько позиций.
- S6 вводит новые сущности (участники, документы ИД, основания, реестр ИД, журнал работ).
  Поля форм сверяются с приказами Минстроя № 344/пр и № 1026/пр по открытому источнику или
  фиксируются в ADR-056 как черновые с меткой «сверить с приказом».
- e2e, которые сверяют сайдбар, шкалу и оранжевые действия, обновляются по смыслу на тех
  этапах, где меняется проверяемое поведение. Проверки не ослабляются.
