# ADR-063. Учёт времени бригад: отчёт заполняется сам (волна 1)

Дата: 04.11.2026. Статус: принято, реализация по пунктам 1.1–1.8.
Основание: «ГАЙКА · Финальный промт: отчёт заполняется сам», волна 1, и указание владельца
04.11 на ночной прогон волн 1 и 2. Ветка `feature/gas-wave-f` после волны 0 (`ff738e2`).

## Task Brief

Цель: убрать ручную работу между записью бригадира и готовым отчётом. Класс T2: домен,
экраны и порты; миграции на рабочей базе и развёртывание не меняются. Без слияния в main и
без Publish до «ок» владельца. Лендинг и публичную страницу не трогаем (указание 04.11).

Расхождения:

- Промт называет режим «Проверять только с замечаниями». В коде он уже был как `flagged`
  (ADR-053, 5), но автоприём держала любая пометка, даже «Объект на несколько дней», которую
  разбор подписывает «Принятию не мешает». Теперь правило одно: см. решение 1.2.
- Промт просит доставку напоминаний через порт MAX. Порт `OutboundMessenger` есть, отправку
  по расписанию делает сервер (этап 4, ADR-060). Здесь только расчёт «что и кому» и колокольчик.

## Решение 1.1. Конвейер записи

Один путь в домене, вызывает его порт (`createEntry`, `submitEntry`), он одинаков во вкладке
и на сервере (`createGasOpsDemo` в обоих):

1. **Запись.** Ключ отправки `clientKey`: повтор с тем же ключом возвращает ту же запись
   (`demo.ts`, `createEntry`), очередь телефона его не меняет (`field-queue.ts`).
2. **Проверки.** `flagsOf` (`calc.ts`): пересечение, дубль, повторный выезд, нет суммы, нет
   сметы, высокая доходность, состав больше бригады, объект на несколько дней. Размер состава
   на дату теперь передаётся и при маршруте, раньше «состав больше бригады» ставился только
   в разборе.
3. **Решение.** `routeEntry` (`review-policy.ts`): «в очередь» или «принять самой» по режиму.
4. **Начисление.** Доля подтверждённой стоимости объекта по минутам (`shareOf`, ADR-053, 3),
   стоимость объекта по правилу (`workCostRub`, ADR-062, F2).
5. **Табель, лист, файл недели.** Производные от записей: ячейка табеля, лист облачной
   таблицы и черновик xlsx считаются из тех же записей при каждом чтении, поэтому
   повтор шага не создаёт дублей, а у числа есть источник (номер записи и строка сметы).

## Решение 1.2. Режим приёма

- По умолчанию «Проверять все» (`DEFAULT_REVIEW_SETTINGS`).
- `flaggedModeSuggestion`: через 14 дней от первого решения человека и при точности не ниже
  95% за полное окно последних 50 решений «Проверка» показывает одну плашку «Включить» /
  «Не сейчас». Включает человек; «Не сейчас» прячет плашку до перезагрузки вкладки.
- Автоприём держат все признаки, кроме «Объект на несколько дней» (`remarkFlags`). Нет суммы
  или сметы — запись ждёт менеджера: финансовый итог подтверждает человек.
- Принятая системой запись подписана «Принята автоматически» в журнале, проверке и очереди.
  Бригадир видит «Замечаний нет: запись принята и учтена в отчёте недели».
- `undoAutoAccept`: менеджер возвращает такую запись в очередь кнопкой «Вернуть в проверку»
  до закрытия недели (`mustBeOpen`), в журнал действий пишется `entry.auto.undo`.
- Пустая очередь: «Всё проверено, отчёт обновлён в ЧЧ:ММ» по последнему действию журнала.
- Бейдж отправки в демо «Записано», а не «Принято сервером»: сервера в демо нет (правило 3).

Проверка: `tests/domain/gas-ops-schedule-review.test.ts`, `gas-ops-estimates-port.test.ts`,
`gas-ops-time-entry.test.ts`; `e2e/gas-auto-accept.spec.ts` на 390 и 1440.

## Решение 1.3. Табель живой

Ячейки пересчитываются из записей при каждом изменении снимка (подписка `state.ts`),
перезагрузка не нужна. Легенда названа словами промта: «принято», «ждёт проверки
(черновик)», «нет записи по графику», «нет сметы»; плюс «выходной или день без графика»
и «✎ ручная сумма». Проверка: `e2e/tabel.spec.ts`.

## Решение 1.4. Облачная таблица заказчика

- Домен `cloud-sheet.ts`: лист «ФАКТИЧЕСКИЙ ОТЧЁТ» из строк табеля (подразделение →
  бригада → бригадир → объект), столбцы «дни × сумма, эффективное время, доходность часа»,
  итог недели и отметка «черновик» у строк с непроверенными записями; `changedRanges` —
  только изменившиеся подряд идущие строки, при другом составе строк весь лист;
  `nextPushAt` — не чаще раза в минуту.
- Порт `SheetSyncPort.push({ sheet, prev })`. Реализации: заглушка во вкладке («не
  подключена»), Google через сервисный аккаунт (`GAS_SHEETS_SA_JSON`, `GAS_SHEET_ID`,
  только сервер, JWT RS256 на Web Crypto, `values:batchUpdate` и подсветка черновиков),
  Яндекс — адаптер без реализации. D12 не принято, поэтому по промту Google.
- Меню «Выгрузить»: строка статуса «Облачная таблица: не подключена» или «Таблица
  обновлена ЧЧ:ММ». Пункты «Синхронизировать с Google / Яндекс Таблицами» без подключения
  убраны: они обещали действие, которого нет.
- BLOCKED: боевая таблица. Нужен ключ сервисного аккаунта и таблица с доступом «Редактор».
  Отправку по расписанию после изменений ставит сервер (этап 4): `googleSheetSyncFromEnv`
  вместо `sheetSyncDemo`.

Проверка: `tests/domain/gas-ops-cloud-sheet.test.ts`, `gas-ops-sheet-google.test.ts`
(подпись JWT проверяется открытым ключом, запросы на подменённом `fetch`).

## Решение 1.5. Черновик недели готов всегда

- Файл недели собирается из записей в момент выгрузки, поэтому «Выгрузить ▾ → Excel
  черновик» отдаёт текущее состояние в любой момент; отдельной копии черновика нет.
- `weekReadyNotice` (`week.ts`): с пятницы 18:00 по времени заказчика открытая неделя
  показывает руководителю «Неделя готова к закрытию: N записей, M замечаний. Черновик файла
  готов.» с кнопкой «Скачать черновик». Закрытая неделя плашки не показывает.

## Решение 1.6. Закрытие недели в 3 действия

Уже было (ADR-056, 6): «Закрыть неделю (N причин)» → список причин, у каждой «Принять как
есть» с причиной → «Закрыть». Версия v1 фиксируется с контрольной суммой записей
(`versionChecksum`). Лист облачной таблицы фиксируется вместе с подключением (этап 4).

## Решение 1.7. Напоминания без участия менеджера

`remindersAt`: вопрос по записи бригадиру сразу, «нет записи по графику» после времени
напоминания (18:00), сводка дня менеджеру через час после него (19:00) или в своё время
`summaryTime`. Повтор ключа «день · вид · получатель» не отправляется. Доставка: порт
`OutboundMessenger`, в демо колокольчик; по расписанию отправляет сервер (этап 4).
Тест «повторная проверка» теперь начинает с 19:00: в 18:00 сводки по новому правилу нет.
