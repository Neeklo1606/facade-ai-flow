# План критического тестирования ГАЙКИ (газовый подрядчик)

23.11.2026. Цель: к показу и продаже по подписке сервис работает на реальных сметах заказчика
от загрузки сметы до Excel недели, на компьютере и телефоне, за каждую роль, в демо и в
контуре PostgreSQL. Основания: ТЗ `~/Downloads/GAIKA_GAS_SERVICE_PROMPTS.md` (промпты A, B
сделаны, C нет), отчёт по 14 звонкам `docs/gaika/sources/Stroitelnaya_vertikal_otchet.md`,
`docs/gaika/GAIKA_PRODUCT_UX.md`, ADR-077…084.

Деньги решает человек. Реальные сметы и отчёт заказчика лежат только в `.local/`, в Git,
логи, снимки и тесты не попадают (тесты на обезличенных копиях).

## 1. Приёмка заказчика (чек-лист из ТЗ, 390 и 1440)

| № | Проверка | Как | Критично |
| --- | --- | --- | --- |
| П1 | Смета загружается и разбирается; неизвестное требует проверки | 5 реальных смет из `.local/estimates` (.xls и .xlsx, несколько листов): шапка, разделы, материалы, опрессовка, трудозатраты, сходимость с итогом | да |
| П2 | Объект создаётся без дубликатов, связан со сметой | повторная загрузка той же сметы, похожий адрес, тот же номер КП | да |
| П3 | Разные разделы одной сметы разным бригадам | мастер «Бригады», страница объекта | да |
| П4 | Время отправляется верно, перерыв вычитается, повтор не дублирует | форма, бот голосом и текстом, двойная отправка, офлайн | да |
| П5 | Без подтверждения сумма не попадает в отчёт | неделя, Excel утверждённый и черновик | да |
| П6 | Частичное выполнение без двойного начисления, остаток не теряется | доля раздела, сумма начислений не больше стоимости работ | да |
| П7 | Excel: часы, суммы, итоги совпадают с контрольным расчётом | сверка с «ФАКТИЧЕСКИЙ ОТЧЁТ 28.09-03.10» | да |
| П8 | После обновления страницы и перезапуска сервера всё на месте | контур PostgreSQL, перезапуск процесса | да |

## 2. Роли и права

Бригадир, менеджер проверки (Оксана), руководитель, администратор, прораб, снабженец, ПТО.
- Каждая кнопка каждого раздела меню нажимается без экрана ошибки, ошибок консоли, 5xx и
  горизонтального переполнения (`scripts/qa-crawl.ts`).
- Бригадир не видит денег ни на экране, ни в ответах API. Права проверяет сервер, скрытый
  пункт меню защитой не считается (ADR-012).
- Изоляция объектов: роль видит только свои объекты.

## 3. Сценарии продукта

1. Смета → объект → разделы → бригады (мастер, ADR-080/082).
2. Бригадир: время кнопками и голосом, «как вчера», мои записи.
3. Проверка: принять, исправить с причиной, уточнение, пакет без замечаний, автопилот.
4. Табель как таблица (ADR-081), неделя, закрытие с версией, Excel.
5. Снабжение: заявка → предложения → заказ → приёмка с расхождением (демо).
6. ПТО: пакет АОСР, окна как в 1С (ADR-084), сертификат из поставки, подпись, реестр (демо).

## 4. Нефункциональное

- Сборка, размер бандла, Lighthouse, первый экран бригадира на 4G (CI).
- Доступность: axe на ключевых экранах, порядок табуляции, области нажатия от 44/48.
- Развёртывание: `docs/runbook/docker.md` на чистой машине, резервная копия базы и файлов
  смет, восстановление, первые пользователи, ссылки входа.
- MAX: честный статус в «Подключениях», без токена бригадир работает веб-формой.
