## Проверено (без нарушений)

Метод вне роли: 403 до хранилища, без сессии 401, чужой id 403, отказ ничего не пишет.
Выгрузка с суммами для бригадира, прораба, снабжения, ПТО: 403. Повторная отправка с тем же
ключом, в том числе три одновременные: одна запись. Сумма начислений раздела при случайных долях
не больше стоимости работ, «завершён» даёт ровно её. Запись на чужой объект: отказ. Вебхуки MAX
и Telegram сверяют секрет за постоянное время. Ключи читаются только из окружения, в репозитории
секретов нет. Личная ссылка заказчика уводит на адрес без ключа.

- Автотест `accessStateFn` с живой сессией: серверная функция берёт куку из запроса TanStack,
  без поднятого сервера с базой и входом её не вызвать. Исправление проверено чтением кода.
- Роли с деньгами (менеджер, руководитель, администратор) со списком объектов не «все» получают
  весь снимок: в наборе таких нет, правило для них не задано.
- Лимит помощника считается по `x-forwarded-for`, который подделывается; после обязательного
  входа это вторично.
- Строгий Content-Security-Policy для скриптов не введён: нужна проверка всех экранов и
  встраивания Lovable, иначе можно сломать показ.
