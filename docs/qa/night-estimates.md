# Ночь 23.11.2026: реальные сметы и сверка денег (П1, П6, П7)

Ветка `night/estimates`. Реальные файлы лежат только в `.local/`, здесь всё обезличено:
файлы называются номерами, сумм и адресов нет.

## Что сделано

1. **П6, двойное «Принять».** Повторное подтверждение уже принятой записи (двойное нажатие,
   второй менеджер, повтор запроса) пересчитывало долю раздела с нулевым шагом: начисление
   записи обнулялось, остаток раздела рос. Теперь отказ `already-reviewed`, начисление и
   остаток не меняются. Тест в `tests/negative/gas-section-accrual-flow.test.ts`.
2. **П1, независимая сверка смет** `scripts/estimate-crosscheck.ts`: .xlsx читается второй раз
   через exceljs, .xls через SheetJS, счёт по подписям без правил `src/domain`. Проверяет лист
   (пустой «12 граф» пропускается), итог без НДС, НДС и ставку, ВСЕГО, сходимость разделов,
   материалы, работы, т/з раздела и сметы, опрессовку разделом и строкой, перевозку, шапку
   (номер КП, дата, строка и текст объекта, дом, квартира, сметная стоимость шапки = ВСЕГО).
   Вывод без сумм и адресов, `--show` только для своего терминала.
3. **Перевозка в разделе.** В одной ГРАНД-Смете в итогах раздела земляных работ стоит
   «Перевозка» (самосвалы). Это не материалы и не работа бригады, а правило «итог минус
   материалы» оставляет её в стоимости работ. Разбор теперь показывает её суммой и строкой с
   пометкой «вычитать ли, решает руководитель». Правило не менялось. Регрессия на копии
   `grand-b.xlsx` в `tests/golden/estimate-fixtures.test.ts`.
4. **П7, сверка Excel недели** `scripts/check-week-vs-fact.ts`: файл строится кодом кнопки
   «Excel» и сравнивается с контрольным «ФАКТИЧЕСКИЙ ОТЧЁТ» по строкам: сумма, часы,
   доходность по дням и за неделю.
5. **Локальный golden** (`tests/golden/estimates.test.ts`) умеет проверять лист, формат, дату,
   адрес, т/з и опрессовку каждого раздела, перевозку; ожидания в `.local/golden` дополнены.
