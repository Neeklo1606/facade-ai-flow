# Ночной прогон: сервер, база, копии, люди (`night/server`)

Дата: 23.11.2026. Направление: промпт C, пункты 1–2, критерий П8. Решение: ADR-085 (server).

## Что сделано

1. Исходный файл сметы из мастера «Загрузить смету» хранится на томе сервера и связан
   с версией (`POST /api/gas/estimate-files?keep=`); раньше хранились только файлы папки смет.
2. Том `estimate-files` в compose, `ESTIMATE_FILES_DIR` в образе с владельцем `node`,
   `PUBLIC_URL` для ссылок входа.
3. `.dockerignore`: `.local` (реальные сметы) больше не попадает в слой образа.
4. Схема сервера `review` принимает решение по разделу (`accrual`, ADR-078): раньше 400.
5. На рабочем контуре нет меток «Демо-подрядчик» и «Бот · Демо» у живых записей.
6. «Настройка» → «Люди и вход» для администратора: добавить человека, ссылка на 72 часа,
   новая ссылка гасит прежнюю, отзыв доступа закрывает сессии. Права на сервере.
7. `scripts/gas-backup.sh` и `scripts/gas-restore-check.sh`, сервисы compose `backup` и
   `restore-check`, расписание cron в runbook.
8. `bun run check:server-p8`: чистая база, миграции, путь пилота до Excel, перезапуск
   процесса сервера, проверка после него, копия и восстановление в отдельную базу.
9. `docs/runbook/docker.md` переписан под чистый Ubuntu 24.04 (2 vCPU / 4 ГБ, подкачка,
   ufw, пользователь сервиса, копии, восстановление, обновление); `pilot.md` обновлён.

ветке `node_modules` собран из ссылок на пакеты, без общего `.nitro`.

## Что не сделано

- Образ Docker не собран и `compose up` не прогнан: демон Docker не запущен, сам не запускал.
  Контур проверен теми же командами без Docker. Первый подъём на сервере закрывает это.
- Деплой на VPS: нет доступа.
- Корневой загрузчик просит у бригадира справочник материалов и получает 403 в журнале
  сервера: отказ правильный, но лишний запрос. Не трогал, чтобы не задеть FieldOps-экраны.

## Что нужно от владельца

- Сервер Ubuntu 24.04 и доступ по SSH, домен с записью A на сервер.
- Куда уносить копии вне сервера (второй сервер или облачное хранилище).
- Канал кода входа: SMS или Telegram (сейчас `AUTH_CHANNEL=log`).
- Имена и телефоны: администратор, Оксана, руководитель, бригадиры.
