# ГАЙКА AI: очередь сборки до тестового демо

Документы этого набора лежат в docs/gaika/:

| Файл                   | Что внутри                                                       |
| ---------------------- | ---------------------------------------------------------------- |
| GAIKA_CLAUDE.md        | Правила и роль агента                                            |
| GAIKA_PRODUCT_UX.md    | Позиционирование, три сценария, состояния, навигация, экраны     |
| GAIKA_DESIGN_SYSTEM.md | Токены, темы, свечение, компоненты                               |
| GAIKA_AI_GATEWAY.md    | Шлюз моделей (DeepSeek, ChatGPT и другие), схемы, промпт, оценка |
| GAIKA_BUILD_QUEUE.md   | Этот файл: шаги G0-G10, демо, лендинг, журнал                    |

---

## Как запустить

Вставить в Claude Code:

```text
Прочитай docs/gaika/GAIKA_CLAUDE.md, затем остальные файлы docs/gaika/ в указанном там порядке.
Найди первый невыполненный шаг в разделе «Шаги» файла GAIKA_BUILD_QUEUE.md и выполни его
по MASTER-AGENT-SKILL: Task Brief, ADR при необходимости, реализация, проверка командами и в браузере,
Completion Report. Отметь шаг в разделе «Журнал». Переходи к следующему, пока не дойдёшь до шага
с пометкой «Остановка».
```

## Цель

Демо, которое проходит три сценария на синтетических данных на телефоне и компьютере, живой разбор через выбранную модель
при наличии ключа, вход по ссылке, и продающий лендинг. Это тестовый результат для показа и первых пилотов,
а не рабочая эксплуатация.

## Шаги

### G0. Синхронизация и сверка. Класс T0, затем остановка

```text
1. git fetch --all. Сравни main с origin/main, перечисли коммиты из Lovable, которых нет локально.
2. Перечисли ветки и их состояние: влита, впереди на N коммитов, конфликты.
3. Составь карту: что из docs/gaika уже есть в коде (implemented, verified, mock, planned, unknown).
   Отдельно: какие экраны FieldOps закрывают части трёх сценариев (отчёты с площадки, проверка, задачи, риски,
   демо-режим, роли, справка) и что можно переиспользовать без переписывания.
4. Какие модули уходят за флаг legacy_modules: снабжение, документы, извлечение спецификаций, поставки.
5. Запусти полный конвейер проверок на актуальном main.
6. Выведи план G1-G10 с оценкой часов под реальное состояние кода. Если шаг уже сделан, отметь.
Остановка: push, слияния и изменения плана только после ответа владельца.
```

### G4. Ввод: голос, текст, фото. Класс T2

```text
Экран «Запись» и шторка ввода из GAIKA_PRODUCT_UX.md.
- Запись голоса в браузере, пауза, таймер, волна громкости, лимит AI_MAX_AUDIO_SEC.

- Повтор отправки не создаёт дубль (ключ идемпотентности).
- Отказ в микрофоне не блокирует текст.
Проверка: телефон, медленная сеть в devtools, обрыв во время отправки, повторная отправка.
```

### G5. Сценарий 1: смена → отчёт. Класс T2

```text
Реализуй сценарий 1 из раздела 4 GAIKA_PRODUCT_UX.md целиком.
- Разбор → карточки Работы, Люди, Материалы, Проблемы, Завтра → янтарные отметки → «Верно».
- Очередь проверки: исходник рядом с полями, подтвердить, исправить, отклонить, свайп и кнопки.
- Версии: правка подтверждённой записи создаёт новую версию, старая superseded.
- Сводка дня из подтверждённых действующих версий; люди и часы отдельно от объёмов;
  разные единицы не складываются. Выпуск через «сдвиньте, чтобы подтвердить».
- Excel по шаблону: каждая строка с источником и версией, формулы в текстовых ячейках нейтрализованы.
Проверка: сквозной тест; тесты инвариантов из раздела 16 фундамента: неподтверждённое не попадает в сводку,
повтор подтверждения не удваивает объём, позднее подтверждение помечает сводку «требует обновления».
```

### G6. Сценарий 2: замечание → задача. Класс T2

```text
Реализуй сценарий 2.
- Голос или текст → черновик задачи: место, дефект, исполнитель, срок, обязательные фото.
- Неоднозначный исполнитель или срок: вопрос кнопками.
- Закрытие с фото «после»; закрывает контроль, а не автор устранения.
Проверка: сквозной тест, тест прав на закрытие.
```

### G7. Сценарий 3: проблема → риск или запрос → решение. Класс T2

```text
Реализуй сценарий 3 и очередь решений руководителя.
- Карточка: что, где, влияние, какое решение нужно, владелец, срок ответа, источник.
- Владелец по правилу объекта (нехватка материала → снабжение).
- «Одобрить», «Вернуть», «Источник». Решение с автором и причиной. Ничего не заказывается автоматически.
- Экран результата: одно голосовое может дать отчёт, задачу и запрос; каждый элемент можно исключить до подтверждения.
Проверка: сквозной тест на сообщение, которое даёт все три сущности.
```

### G8. Демо: вход, данные, сценарий показа. Класс T2, остановка

```text
1. Вход: экран из раздела 7 продукта. «Открыть демо» по ключу из ссылки и выбор роли:
   прораб, проверяющий, руководитель. Настоящий вход по телефону вне этого шага.
2. Данные, только синтетические: объект «Северный», инженерные сети, секции А-В;
   10 сотрудников, 3 бригады, 7 дневных сводок, 15-20 задач, 3 риска, 20-30 фото, 3 документа.
3. Три голосовых сообщения сценариев как готовые примеры с аудио и подготовленным разбором.
4. Сброс демо в «Ещё». Пометка «Демо» на каждом экране, включая телефон.
5. docs/gaika/DEMO_SCRIPT.md: показ на 5 минут и на 90 секунд, реплики, что показывать с телефона,
   чего не открывать, ответы на «а если ИИ ошибётся», «где данные», «прораб не будет пользоваться».
Остановка: владелец проходит демо сам и даёт добро на лендинг.
```

### G9. Лендинг. Класс T2

```text
Публичный маршрут в том же приложении (или отдельный проект, если так решит G0 с обоснованием в ADR).
Демо-приложение остаётся за ключом.

Структура и тексты, без выдуманных логотипов, процентов и отзывов:
1. Герой. Заголовок «Говорите с объекта. Гайка соберёт всё остальное.»
   Подзаголовок «Голос, фото и сообщения превращаются в проверенные отчёты, задачи и риски
   по нужному объекту, участку и ответственному.»
   Кнопки «Показать на нашем отчёте» и «Открыть демо».
   Справа живая последовательность, а не картинка телефона: запись → распознанные сущности → отчёт, задача, риск.
2. Боль: информация живёт в голосовых, фото, звонках и таблицах. Сотрудник тратит часы на перенос.
3. Как это работает в трёх шагах: говорите, проверьте, получите сводку.
4. Три результата: отчёт за смену, задача по замечанию, решение по проблеме.
5. Прорабу не нужно новое приложение: пишет и говорит, как привык.
6. Ошибки видны и правятся за секунды: источник рядом с каждым значением, без подтверждения ничего не уходит.
7. Данные и безопасность: где хранятся, что не передаётся во внешние модели без согласования.
8. Пилот: один объект, один процесс, 4-6 недель, измерение до и после. Цену показывать только после утверждения
   основателем (значение в конфиге, по умолчанию скрыто).
9. Вопросы: ошибки ИИ, плохая связь, данные, официальные документы, 1С и таблицы.
10. Форма «Пришлите голосовое, пять фото и шаблон отчёта, покажем на ваших данных».
    Сохранение заявки с согласием на обработку данных.

Тема тёмная, дизайн-система ГАЙКИ, точечная сетка и цветовое поле в герое.
noindex до проверки названия «Гайка», доменов и товарного знака.
Проверка: Lighthouse мобильный, первый экран до 2,5 с на 4G, форма доходит до хранилища.
```
