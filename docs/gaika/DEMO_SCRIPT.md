# Сценарий показа ГАЙКИ AI

Решение: [ADR-037](../adr/ADR-037-demo-scenarios.md). Три сценария проходят от ввода до
результата на моковых данных. Показ идёт с телефона: ширина 375 px, тёмная или светлая тема
по настройке системы.

## Доступ

Демо-контур открывается по адресу публикации без пароля: данные живут во вкладке браузера
и в базу не попадают. На входе экран выбора роли, в показе нужны три:

| Роль      | Кто в данных    | Что показывает                            |
| --------- | --------------- | ----------------------------------------- |
| Прораб    | Эльдар Гареев   | сценарии 1 и 3, вход фактов               |
| ПТО       | Елена Волкова   | сценарий 2, проверка и черновик документа |
| Снабжение | Дмитрий Дорохов | сценарий 3, решение по заявке             |

Меню открывается значком слева в шапке (на десктопе от 1024 px оно открыто всегда). Роль
меняется в нём: карточка с именем и ролью внизу меню. Чтобы показывать две роли сразу,
откройте второе окно браузера: данные во вкладках независимы.

**Сброс данных:** в том же меню — «Сбросить демо-данные». Спрашивает подтверждение, возвращает
фикстуры в исходное состояние. Пройти показ второй раз после сброса можно сразу.

## Сценарий 1. Объект → учёт

1. Роль «Прораб», экран «Запись» (центральная кнопка панели).
2. «Примеры показа» → **Смена**. Текст встаёт в поле, статус меняется на «Сохранено»,
   ниже появляется карточка «Что система услышала» с пометкой «разбор подготовлен заранее».
3. Показать источник у любого значения: под значением открывается фраза, из которой оно взято.
4. «Верно: завести отчёт». Отчёт уходит **на проверку**, а не в сводку: неподтверждённое
   в сводку не попадает.
5. Экран «Сегодня» → карточка «Сводка смены» → **«Скачать Excel»**. Файл
   `Сводка_<объект>_<дата>.xlsx` открывается в Excel: строки по видам работ и захваткам,
   люди и часы отдельными колонками, у каждой строки источник.

Пример говорит про стилобат, которого в данных смены ещё нет: новая строка видна как новая.

## Сценарий 2. ПТО → черновик документа

1. Роль «ПТО», экран «Проверка».
2. Карточка факта с объёмом → **«Исправить объём»**: принятый объём вводит человек,
   система его не подставляет.
3. «Принять». Факт становится принятым и попадает в сводку.
4. **«Скачать черновик ведомости»**. Файл `Ведомость-черновик_<объект>_<дата>.xlsx`
   содержит колонку «Статус документа» со значением «Черновик, не исполнительная
   документация». Юридически значимые документы демонстрация не выпускает.

## Сценарий 3. Объект → снабжение

1. Роль «Прораб», экран «Запись» → «Примеры показа» → **Нехватка материала**.
2. В разборе — риск с нехваткой. **«Создать заявку снабжению»**: название, количество
   и единица подставлены из фразы, срок ответа — из разбора. Чего в фразе нет, остаётся
   пустым: система не выдумывает количество.
3. «Отправить снабжению».
4. Роль «Снабжение» (или второе окно), экран «Входящие» → блок «Заявки на материал».
   Заявка видна со статусом «Новая».
5. **«Принять»** или «Отклонить» с причиной. Статус меняется, решение записывается с автором.
   На экране сказано: ничего не заказывается автоматически. Закупка не выполняется.

## Что в показе подготовлено заранее

- Речь не распознаётся: примеры показа — это тексты с готовым разбором (ключа модели нет).
  Пометка стоит рядом с результатом, а не в сноске.
- Файл записи и фото не хранятся: сохраняются текст и метки времени.
- Данные моковые: пометка «Демо» стоит в шапке каждого экрана.

## Что показывать не нужно

Разделы прежнего контура (закупки, поставки, спецификации) убраны из навигации флагом
`legacy_modules` (ADR-034). Публикация на рабочий адрес — за владельцем.
