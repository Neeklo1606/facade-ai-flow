# План: полный цикл «смета → объект → раздел → время → табель» и лендинг

20.11.2026. Основание: созвон 17.11, обратная связь со скриншотами 20.11, разбор ПТО Онлайн.
Документы: `docs/guide/full-cycle.md` (цикл по шагам), `docs/design/2026-11-20-design-changes.md`
(правки дизайна).

## Что уже сделано

- Промпт A: папка смет, разбор шапки и разделов, объект без дублей, версии. В main.
- Промпт B: назначения разделов, доля выполнения, начисление, опрессовка в отчёте. В main.
- Правки по скриншотам 20.11: флажки «Проверки», «Сметы» руководителю, часы «7 ч 50 мин»,
  табель без подсветки столбца, отпуск бригады. Ветка `feature/gas-feedback`.

## Этапы

Каждый этап заканчивается проверкой на 390 и 1440 px, тестами и коммитом. В main — после «ок».

### Этап 1. Один путь объекта (2–3 дня)

Цель: человек не ищет, где объект, смета и разделы — всё на одной странице.

1. Страница объекта `/gas/objects/$id` (D3): шапка с адресом, номером, сметой и файлом; вкладки
   «Разделы», «Записи», «История». Телефон: вкладки сверху, панель на всю ширину.
2. После «Создать объект» открывать страницу объекта с подсказкой «Назначьте разделы» (D5).
3. Хлебные крошки по линии Объект → Раздел → Запись (D4).
4. Демо-папка Яндекс Диска: строки файлов нажимаемые, «Забрать» на каждой (D8).

Проверка: e2e «смета → создать объект → назначить раздел → бригадир видит раздел» на 390 и 1440.

### Этап 2. Сверка сметы с файлом (2 дня)

1. «Сверить с файлом» (D1): лист файла рядом с разбором, клик подсвечивает строку. Файл уже
   хранится; лист рисуется из той же сетки, что разбирает SheetJS, без новых зависимостей.
2. Телефон: вкладки «Разбор» и «Файл».

Проверка: golden на обезличенных сметах — клик по разделу 3 подсвечивает его строку.

### Этап 3. Цифры с расшифровкой (1–2 дня)

1. Начислено, остаток и сумма записи раскрываются по нажатию (D2): шаги доли, записи, итог.
2. Режим «Таблица» в «Проверке» на компьютере (D7).

Проверка: сумма расшифровки равна цифре на карточке, тест на каждую.

### Этап 4. Лендинг в палитре pto-app.ru (2 дня)

1. Токены лендинга и шрифт Manrope (L1). Сервис не трогаем.
2. Форма в первом экране (L2), демо-объект и сброс (L3), «чем отличаемся» (L9).
3. Справочный центр по разделам и «Что нового» (L4).
4. Цифра, цены, видео, реквизиты (L5–L8) — когда владелец пришлёт данные.

Проверка: Lighthouse, axe, первый экран на 390 и 1440, сайт без горизонтальной прокрутки.

### Этап 5. Рабочий контур (промпт C, после покупки домена)

1. Развёртывание по `docs/runbook/docker.md` на сервере заказчика, HTTPS.
2. Приглашения по ссылке на 72 часа, отзыв доступа.
3. MAX: инструкция для организации, честный статус в «Подключениях».
4. Ежедневная копия базы и файлов смет, проверка восстановления.
5. Инструкции Оксане и бригадиру, сценарий показа на 5 минут.

## Риски

- Палитра лендинга отличается от сервиса: переход с сайта в демо будет заметен. Предложение —
  после этапа 4 решить, переводить ли сервис на синий акцент.
- Страница объекта меняет навигацию: старые ссылки на шторку объекта перенаправляются.
- Шесть старых сквозных тестов на main чинятся отдельной сессией; до их починки CI красный.
