# Ручная проверка выпуска: что смотреть и в каком контуре

Сборка от 26.09.2026, ветка `feature/deployable` → `main`. Автоматические проверки пройдены
(конвейер из 12 шагов, 720 модульных, 142 сквозных теста, обход пяти ролей в двух темах,
первая неделя на чистой базе). Здесь — то, что машина проверить не может: смысл, порядок
и ощущение от работы.

Два контура проверяются по-разному, и это главное, что нужно держать в голове:

| Контур         | Где                                                  | Что в нём есть                                                     |
| -------------- | ---------------------------------------------------- | ------------------------------------------------------------------ |
| Демонстрация   | facade-ai-flow.lovable.app по ссылке с ключом        | все экраны на вымышленных данных, вход не требуется, роль — в меню |
| Рабочий контур | локально: PostgreSQL + сборка `bun run build:server` | вход по телефону и коду, приглашения, пустая база, реальные записи |

Вход, приглашения и первая неделя проверяются **только в рабочем контуре**: в демонстрации входа
нет по замыслу.

## 1. Демонстрация после публикации (15 минут)

Проверки командами — [RUNBOOK.md, раздел 6](../RUNBOOK.md). Руками:

1. Открыть ссылку с ключом на телефоне в мобильной сети. Метка «Демо» в шапке на месте.
2. Пройти сценарий показа из [SALES_DEMO.md](../SALES_DEMO.md) целиком, не подглядывая в текст.
3. Переключить тему на светлую и пройти те же три экрана: оранжевое пятно одно на экран.
4. Открыть «Справочники» → «Журнал»: записи есть, у каждой видно, кто и когда.
5. Открыть документ → список позиций: у строк видно место на листе и уверенность.
6. Отправить ссылку себе в мессенджер: превью с названием продукта, без «Фасад-РП».

## 2. Рабочий контур на чистой базе (40 минут)

Порядок — [IMPLEMENTATION.md](../IMPLEMENTATION.md). Коротко:

```bash
createdb fieldops_test
export DATABASE_URL="postgres://localhost/fieldops_test?sslmode=disable"
export SESSION_SECRET="любая-строка"
bun run db:migrate
bun run db:owner --name "Ваше имя" --phone "+7…" --url "http://localhost:3000"
NITRO_PRESET=node-server bun run build:server
DATABASE_URL=$DATABASE_URL SESSION_SECRET=$SESSION_SECRET AUTH_CHANNEL=log PORT=3000 \
  node .output/server/index.mjs
```

Дальше по шагам, отмечая, где пришлось задуматься:

1. **Вход.** Открыть ссылку из `db:owner` → «Войти по приглашению». Затем выйти из меню профиля
   и войти заново по телефону: код показывается на экране (канал-заглушка) и пишется в журнал.
2. **Объект.** «Объекты» → «Добавить объект». Проверить, что после создания открывается карточка.
3. **Захватки.** Карточка → «Ход работ» → «Захватка». Завести две: корпус и захватку внутри него.
   Попробовать перенести корпус внутрь его же захватки — система должна отказать словами.
4. **Справочники.** Категория верхнего уровня, затем номенклатура из Excel: взять свою выгрузку
   или файл с ошибочными строками. Смотреть отчёт: номера непринятых строк и причины.
5. **Поставщик.** Объект → «Поставщики и запросы» → «Завести поставщика». Без региона или
   категорий сохранение не должно проходить.
6. **Сотрудники.** Завести трёх с разными ролями, каждому «Пригласить». Войти по одной ссылке
   в приватном окне — должен открыться рабочий экран этой роли, а не дашборд руководителя.
7. **Спецификация.** Документ → «Загрузить спецификацию из Excel». Проверить сопоставление
   колонок на своём файле. Затем «Позиция» — завести строку руками.
8. **Проверка и передача.** Подтвердить сопоставление у каждой строки, передать в закупку.
9. **Запрос.** «Материалы» → «Создать запрос поставщикам» → четыре шага мастера → отправить.
10. **Отчёт и приёмка.** «Отчёты с площадки» → «Завести отчёт» → принять объём. Открыть
    «Ход работ»: факт по захватке вырос на принятый объём.

## 3. На что смотреть особенно

- **Слова, а не молчание.** Любая кнопка, которая ничего не сделала и ничего не сказала, — находка.
  Отказ обязан называть причину и следующий шаг.
- **Обещания.** Если экран обещает разбор документа, распознавание голоса или отправку письма —
  это ошибка: ничего этого нет, и все такие места должны говорить прямо.
- **Телефон.** Пройти пункты 6 и 10 с телефона: нижняя панель, одно главное действие, ничего
  не уезжает за край.
- **Возврат.** После выхода из системы кнопка «назад» не должна возвращать внутрь.

## 4. Куда записывать находки

Одной строкой: экран, что сделали, что ожидали, что получилось. Снимок экрана помогает больше
описания. Найденное попадает в `TASKS.md` разделом очередной очереди.
